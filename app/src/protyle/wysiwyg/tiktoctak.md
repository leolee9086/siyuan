## 🟡 中期计划 (架构演进，步步为营)
*需要协调多个模块，或者涉及核心分发逻辑的任务。*

- [ ] **`keydown.ts` (核心枢纽) 的局部试点**
  - **背景**: `keydown.ts` 目前像葫芦娃救爷爷一样一个接一个地调中间件。
  - **行动**: 开始把相关的中间件调用合并成 `CalibURRouter` 子路由。比如把所有“插入类”的操作打包，或者所有“格式化类”的操作打包。
  - **收益**: 减少 `keydown.ts` 的肉眼可见复杂度，通过提前“短路”不匹配的组来提升性能。

- [ ] **重构 `keydown.slashHint.ts` & `keydown.menus.ts`**
  - **背景**: 这些处理 UI 弹窗（斜杠菜单、右键菜单）。
  - **行动**: 使用 Router 管理“UI 打开” vs “UI 关闭”时的按键拦截状态。
  - **收益**: 显式管理 UI 模式状态，不再到处 `if (menu.isShow)`。

- [ ] **标准化 ArkType 下的 `HotKey` 定义**
  - **行动**: 搞一套标准模式或 helper，能把现有的 `siyuan.config.keymap` 配置直接转成 `calibur` 能认的 ArkType 匹配模式。

## 🔴 远期计划 (北极星目标，星辰大海)
*雄心勃勃的目标，彻底重写核心事件引擎。*

- [ ] **全量迁移 `keydown.ts` -> `RootRouter`**
  - **愿景**: 把 `keydown.ts` 里那条长长的中间件链条，替换成一个单一的、巨大的 `CalibUR.universe()` 定义。
  - **细节**: `RootRouter` 接收整个 `IProtyle` 状态和 `KeyboardEvent` 作为输入，以 O(1) 或 O(log N) 的时间复杂度（取决于 Router 内部优化）直接分发到对应处理器。
  - **收益**: 所有快捷键的唯一真理来源；完全的类型安全；理论上的性能飞跃，彻底告别线性遍历。

- [ ] **动态路由重配置**
  - **愿景**: 允许插件动态注册新的路由到 `RootRouter` 中。
  - **细节**: 因为 `CalibUR` 是不可变的，可能需要一个 "RouterBuilder" 服务，在插件加载/卸载时重新生成分发函数。

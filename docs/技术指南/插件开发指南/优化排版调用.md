# 插件开发技巧：调用优化排版 API

在思源插件开发中，我们可以直接通过内核提供的 HTTP API 来触发内置的“优化排版”功能。

## 核心接口

思源提供了一个内核 POST 接口用于自动优化特定块（Block）或整个文档（Doc）的排版：

**API 端点**: `/api/format/autoSpace`
**请求方法**: `POST`

### 请求参数

请求体必须是一个包含 `id` 属性的 JSON 对象，其中 `id` 对应于你需要优化的目标块（通常为文档的 `rootID`）：

```json
{
  "id": "20230811xxxxxx-xxxxxxx"
}
```

## 在插件中调用

在思源官方推荐的插件开发模式中，直接使用全局注入或模块导入的 `fetchPost`（通常封装在 `siyuan` npm 包中）即可。

### 示例代码

```typescript
import { fetchPost } from "siyuan"; // 或者使用项目中相应的路径

/**
 * 调用优化排版
 * @param blockId 目标块的 ID，通常是文档 id (rootID)
 */
async function optimizeTypography(blockId: string) {
    try {
        const response = await fetchPost("/api/format/autoSpace", {
            id: blockId
        });
        
        console.log("排版优化请求已发送", response);
        // 你可以在这里处理响应，比如在状态提示栏显示成功消息
        
    } catch (error) {
        console.error("排版优化失败", error);
    }
}

// 使用示例：假设获取到了当前焦点文档的 rootID
const currentDocId = "20240228xxxxxx-xxxxxxx"; 
optimizeTypography(currentDocId);
```

### 注意事项

1. **执行隐藏与保存**：在思源官方的前端实现中，在调用此接口前通常会先隐藏掉不必要的工具条，以确保格式化过程不会受到正在进行的 UI 操作的干扰。
2. **后台处理**：排版格式化是一个在内核层进行的操作，它会直接修改后台数据模型并通过 WebSocket 广播给前端，引起重新渲染。因此，你不需要（也无法）手动处理格式化后的长文本更新到编辑器的过程。
3. **性能建议**：如果你的插件要在后台进行大面积文本修改，建议完成内容的写入并保存后，再通过这个 API 发出格式化请求，以免产生并发写入的数据冲突。

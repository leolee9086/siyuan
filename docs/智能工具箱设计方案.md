# 智能工具箱 (Smart Toolbox) 设计方案

## 1. 概述
旨在思源笔记桌面端提供一种高性能、上下文感知的快捷工具交互模式。参考 CAD 软件的快捷工具条设计，通过极简的图标阵列和精准的上下文匹配，极大提升高频操作（如属性修改、素材插入）的效率。

## 2. 界面实现 (UI Implementation)
### 2.1 视觉设计
- **形态**：采用极简图标阵列（Icon Grid），平铺于轻量化对话框内。
- **美学**：应用现代玻璃拟态（Glassmorphism）效果，支持深色模式。
- **触发与位置**：
    - 仅在桌面端启用。
    - 随光标上下文自动在编辑器侧边或指定区域浮动展示。
    - 高度交互：图标支持悬停缩放与微动画反馈。

### 2.2 响应式布局
- **Trigger 图标权重**：根据当前上下文计算工具的权重，高权重（最可能用到）的工具排在前面或增大尺寸。
- **动态显隐**：非当前上下文可用的工具自动淡化或隐藏，保持界面纯净。

## 3. 数据驱动架构 (Data-Driven Architecture)
### 3.1 全局上下文类型 (Context Types)
工具箱设计为完全兼容并扩展思源插件系统的事件模型。以下是核心支持的上下文类型：

#### 类型 1：块标上下文 (Block Icon Context)
- **触发源**：`click-blockicon` (光标在块侧边 gutter 区域)。
- **核心数据**：`protyle`, `blockElements` (DOM 数组), `ids` (推导), `types` (推导)。
- **推荐工具**：块变换、属性修改、批量复制 ID。

#### 类型 2：编辑器内容上下文 (Content Context)
- **触发源**：`open-menu-content` (编辑器内右键或选区)。
- **核心数据**：`protyle`, `range` (光标/选区范围), `element` (目标块 DOM)。
- **推荐工具**：行内样式（加粗、高亮）、内容转换、AI 润色入口。

#### 类型 3：导览树上下文 (DocTree Context)
- **触发源**：`open-menu-doctree` (文档树或笔记列表)。
- **核心数据**：`elements` (被选中的 li 树节点), `type` (`notebook`/`doc`/`docs`)。
- **推荐工具**：文档属性批量修改、导出模板切换。

#### 类型 4：行内元素上下文 (Inline Element Context)
- **子类型**：
    - 图片 (`open-menu-image`): 携带 `assetElement`。
    - 链接 (`open-menu-link`): 携带 `linkElement`。
    - 引用 (`open-menu-blockref`): 携带 `refElement`。
    - 标签 (`open-menu-tag`): 携带 `tagElement`。
- **推荐工具**：针对性操作（如图片 OCR、链接转块引、标签重命名）。

#### 类型 5：数据库上下文 (Database/AV Context)
- **触发源**：`open-menu-av` (属性视图行/块)。
- **核心数据**：`protyle`, `element` (AV 容器), `selectRowElements` (选中行数组)。
- **推荐工具**：行数据批量填充、视图切换、关联块操作。

#### 类型 6：全局编辑器切换 (Switch Context)
- **触发源**：`switch-protyle` (标签页切换)。
- **核心数据**：`protyle` (进入的编辑器实例)。
- **推荐工具**：刷新工具箱全局状态，重置当前上下文。

### 3.2 S-Forge 专属扩展上下文 (S-Forge Exclusive Contexts)
为了实现更深度的智能化，S-Forge 引入了超越思源标准插件系统的增强感知能力：

#### 类型 7：编辑器光标上下文 (Editor Cursor Context)
- **触发源**：光标在块内移动、文本录入停顿、输入法结束 (`compositionend`)。
- **感知逻辑**：通过 `window.getSelection().getRangeAt(0)` 获取精确选区，并计算相对于当前可编辑 HTML 元素的字符偏移量 (`caretOffset`)。
- **核心数据结构**：
    - `caretOffset`: 光标在当前块内文字的绝对位置。
    - `text`: 当前块的完整纯文本内容。
    - `tokens`: 经过分词引擎（如结巴分词）处理后的词元数组。
    - `currentToken`: 光标当前覆盖的词元。用于触发词法级别的智能建议。
    - `coordinates`: 选区在屏幕上的矩形坐标，用于工具箱的精确悬停定位。

#### 类型 8：素材瀑布流上下文 (Asset Masonry Context)
- **触发源**：S-Forge 素材管家界面中的选中或悬停。
- **核心数据**：`selectedAssets` (含评分、调色板、标签等元数据对象数组)。

#### 类型 9：素材引用上下文 (Asset Ref Context)
- **触发源**：编辑器内扩展型素材引用（如带分辨率参数的图片）。
- **核心数据**：`assetPath`, `metaData` (含 `star`, `palettes`), `currentResolution`。

### 3.3 交互逻辑增强
- **上下文感知 (Context Perception)**：统一监听 `ContextChange` 事件。数据负载整合了 `BlockMetadata`, `ProtyleInstance` 以及 `SelectionMetadata`。
- **双轨分发 (Action Chains)**：每个图标区分 `PrimaryAction` (左键直接执行) 与 `SecondaryAction` (右键元数据/配置操作)。

## 4. 技术实现策略 (Technical Implementation Strategy)

### 4.1 智能防抖协调器 (Smart Debounce Coordinator)
- **挑战**：频繁的光标移动和输入法组合 (`composition`) 会导致工具箱闪烁或性能抖动。
- **方案**：
    - 引入 `isComposing` 锁，在 `compositionstart` 时挂起更新。
    - 使用基于光标偏移量的“位移防抖”，仅当 `caretOffset` 发生实质性跨词变动时才触发上下文重算。

### 4.2 原子化动作链 (Atomic Action Chains)
- **设计**：将“工具展示”与“动作执行”解耦。
- **Brush Mode (刷子模式)**：
    - 部分动作执行后进入“待命状态”（如“格式刷”）。
    - 借用 `modecursor.js` 逻辑，光标变为特定图标，允许用户在多个目标块上点击应用。

### 4.3 扩展点与注册机制 (Registry Mechanism) [SFORGE]
参考思源设置面板 Tab 化改进中的 `TabRegistry` 模式，智能工具箱采用原子化的 **TriggerRegistry** 架构。

#### 4.3.1 TriggerRegistry (触发器注册表) [SFORGE]
- **定位**：统一管理所有“工具动作”的执行逻辑与触发状态。
- **注册结构**：
    ```typescript
    interface TriggerRegistration {
        type: string;           // 触发器唯标识
        mode: 'immediate' | 'brush' | 'toggle'; 
        
        /** [SFORGE] 谓词匹配：决定工具是否在当前上下文展示 */
        match: (context: IGlobalContext) => Promise<boolean> | boolean;

        cursorHTML?: string;    
        /** 
         * 执行逻辑
         * @param isSecondary 是否为次要动作 (通常对应右键点击)
         */
        onApply: (target: Element, context: IGlobalContext, isSecondary: boolean) => void;
        
        onMove?: (target: Element, context: IGlobalContext) => void;
        onEnter?: (params: any) => void;
        onExit?: () => void;
    }
    ```

### 4.4 全局上下文定义 (IGlobalContext) [SFORGE]
这是驱动整个工具箱智能化的核心数据结构。

```typescript
interface IGlobalContext {
    /** 当前激活的编辑器实例 */
    protyle: IProtyle;
    
    /** [SFORGE] 编辑器光标感知数据 */
    editor?: {
        caretOffset: number;     // 块内字符偏移量
        text: string;            // 当前块纯文本
        tokens: IToken[];        // 分词结果
        currentToken?: IToken;   // 光标覆盖的词元
        rect: DOMRect;           // 光标/选区的屏幕位置
    };

    /** 目标块元数据 */
    targetBlock: {
        id: string;
        type: string;
        element: HTMLElement;    // 目标 DOM
    };

    /** 选区状态 */
    selection: {
        text: string;
        isCollapsed: boolean;    // 是否为折叠状态(无选区)
        range: Range;
    };
    
    /** [SFORGE] 素材扩展上下文 (仅当点在素材上时存在) */
    asset?: {
        path: string;
        meta: any;               // 含 star, palettes 等 S-Forge 特有元数据
    };
}
```

#### 4.3.2 多态重载逻辑 (Polymorphic Overloaded Triggers)
同一个 Trigger 在不同点击点或不同触发模式下具备语义重载能力：
1.  **行为重载**：`onApply` 根据 `context` 自动路由至 `applyInline` 或 `applyBlock`。
2.  **视觉重载**：`onMove` 实时根据 `target` 改变 UI/光标反馈。

### 4.4 语义化分词驱动
- **底层支持**：利用 S-Forge 专用分词服务。
- **链路**：编辑器事件 -> 获取 `text` -> 并行调用 Jieba -> 匹配词库元数据 -> 注入工具箱 `detail.currentToken`。

## 5. 调用流程 (Calling Flow)
1. `Protyle` 触发光标移动或状态变更事件。
2. `EventBus` 发出 `globalContextChange` 全局上下文更新。
3. `SmartToolboxDialog` 监听更新，进行数据过滤与分词匹配。
4. UI 渲染：根据工具权重实时更新图标阵列。
5. 用户交互：执行对应的 `ActionChain` -> 根据需要进入 `Brush Mode`。

## 6. 内置工具实现细则：颜色刷 (Color Brush)

作为首个验证 Registry 机制的内置工具，颜色刷将实现“一次拾色，全屏点涂”的交互。

### 6.1 功能拆解与修改范围

| 功能模块 | 修改/新增范围 | 技术要点 |
| :--- | :--- | :--- |
| **注册层** | `app/src/layout/registry/BrushRegistry.ts` (新增) | 仿照 `TabRegistry` 实现 `register` 与 `activate` 命令流。 |
| **视觉层** | `app/src/dialog/SmartToolbox.css` (新增) | 定义 `.brush-cursor-color` 样式，实现圆环动态跟随光标。 |
| **感知层** | `app/src/protyle/ui/event.ts` | 增加画笔模式下的全局 `click` 拦截，区分是应用画笔还是退出。 |
| **执行逻辑** | `app/src/protyle/toolbar/util.ts` 或新动作类 | 封装 `applyColorToSelection` (针对 inline) 与 `applyColorToBlock` (针对块)。 |
| **持久化** | `app/src/protyle/util/transaction.ts` | 封装标准事务 API，确保块背景色修改支持 `Ctrl+Z`。 |

### 6.2 参考实现对比 (References)

- **交互框架**：参考 `toread/brush/modecursor.js`。
    - 借鉴其 `addCursor` 和 `updatePosition` 逻辑，实现无延迟的色块跟随。
    - 借鉴其对 `Esc` 键和 `contextmenu` 的拦截逻辑作为退出钩子。
- **行内染色**：参考 `toread/TEColors/source/utils/DOM/blockStyle.js`。
    - 特别是 `应用颜色到当前块` 函数，它演示了如何寻找 `protyle-toolbar` 并注入 `data-type="style"` 来实现原生的文字染色。
- **块属性修改**：参考 `toread/TEColors/source/utils/DOM/blockStyle.js` 中的 `kernelApi.setBlockAttrs` 调用。
    - 注意：在 S-Forge 中应优先使用封装好的事务 API 而非直接 fetch 接口，以保证编辑器状态同步。

### 6.3 状态机定义
- **Idle (空闲)**：工具箱显示，等待拾色。
- **Active (激活)**：`BrushRegistry` 锁定 `s-forge-color-brush`。
    - 鼠标移动：更新 `cursorHTML`。
    - 鼠标左键：
        - `hasSelection ? applyInline() : applyBlock()`。
    - 退出指令 (`Esc`/右键/工具箱关闭)：调用 `onExit` 并恢复标准 OS 光标。

## 1. 问题定位

### 1.1 核心问题概述

数据视图的数据加载是整个渲染流程的起点，当前实现存在多个性能瓶颈，特别是在大数据量场景下，数据加载、解析、渲染的串行处理导致响应时间过长。

**主要文件位置**: 
- [`kernel/model/attribute_view_render.go`](../../kernel/model/attribute_view_render.go)
- [`kernel/sql/av.go`](../../kernel/sql/av.go)

### 1.2 具体性能问题

#### 1.2.1 JSON解析性能瓶颈

**问题描述**: 每次渲染都需要完整解析JSON文件，没有缓存机制。

**代码位置**: [`kernel/model/attribute_view_render.go:49`](../../kernel/model/attribute_view_render.go:49)

```go
func RenderAttributeView(blockID, avID, viewID, query string, page, pageSize int, groupPaging map[string]interface{}) (viewable av.Viewable, attrView *av.AttributeView, err error) {
	waitForSyncingStorages()
	
	// 每次都从文件解析
	attrView, err = av.ParseAttributeView(avID)
	if err != nil {
		logging.LogErrorf("parse attribute view [%s] failed: %s", avID, err)
		return
	}
	
	viewable, err = renderAttributeView(attrView, blockID, viewID, query, page, pageSize, groupPaging)
	return
}
```

**性能影响**:
- 每次渲染都读取文件并解析JSON
- 大型数据库（10000+行）JSON文件可达数MB
- JSON解析涉及大量反射操作
- 1000行数据库解析时间: ~50ms
- 10000行数据库解析时间: ~500ms

#### 1.2.2 数据加载无增量更新

**问题描述**: 即使只修改一个单元格，也需要重新加载整个数据库。

**代码位置**: [`kernel/model/attribute_view_render.go:67-88`](../../kernel/model/attribute_view_render.go:67)

```go
func renderAttributeView(attrView *av.AttributeView, nodeID, viewID, query string, page, pageSize int, groupPaging map[string]interface{}) (viewable av.Viewable, err error) {
	// 获取待渲染的视图
	view, err := getRenderAttributeViewView(attrView, viewID, nodeID)
	if nil != err {
		return
	}
	
	// 做一些数据兼容和订正处理
	checkAttrView(attrView, view)
	upgradeAttributeViewSpec(attrView)
	
	// 渲染视图 - 每次都是全量渲染
	viewable = sql.RenderView(attrView, view, query)
	err = renderViewableInstance(viewable, view, attrView, page, pageSize)
	if nil != err {
		return
	}
	
	// 渲染分组视图
	err = renderAttributeViewGroups(viewable, attrView, view, query, page, pageSize, groupPaging)
	return
}
```

**性能影响**:
- 无法利用已加载的数据
- 频繁修改时重复加载相同数据
- 网络传输浪费（前端已有大部分数据）
- 单次全量加载10000行: ~800ms

#### 1.2.3 分组视图重复渲染

**问题描述**: 分组视图的每个分组都独立渲染，存在大量重复计算。

**代码位置**: [`kernel/model/attribute_view_render.go:90-191`](../../kernel/model/attribute_view_render.go:90)

```go
func renderAttributeViewGroups(viewable av.Viewable, attrView *av.AttributeView, view *av.View, query string, page, pageSize int, groupPaging map[string]interface{}) (err error) {
	// ... 省略分组生成逻辑
	
	var groups []av.Viewable
	for _, groupView := range view.Groups {
		// 每个分组都独立渲染
		groupViewable := sql.RenderGroupView(attrView, view, groupView, query)
		
		// 每个分组都执行过滤、排序、计算
		err = renderViewableInstance(groupViewable, view, attrView, groupPage, groupPageSize)
		if nil != err {
			return
		}
		
		hideEmptyGroupViews(view, groupViewable)
		groups = append(groups, groupViewable)
	}
	viewable.SetGroups(groups)
	return
}
```

**性能影响**:
- 每个分组独立执行过滤、排序、计算
- 10个分组的视图渲染时间是单视图的10倍
- 大量重复的值处理操作
- 10个分组×1000行: ~1500ms

#### 1.2.4 关联数据递归加载

**问题描述**: 关联字段和汇总字段需要递归加载关联的数据库，没有深度限制。

**代码位置**: [`kernel/sql/av.go`](../../kernel/sql/av.go) (推测位置)

```go
// 伪代码示例
func loadRelationData(attrView *av.AttributeView, relationKey *av.Key) {
	destAvID := relationKey.Relation.AvID
	destAv, _ := av.ParseAttributeView(destAvID) // 递归加载
	
	// 如果目标数据库也有关联字段，继续递归
	for _, keyValues := range destAv.KeyValues {
		if av.KeyTypeRelation == keyValues.Key.Type {
			loadRelationData(destAv, keyValues.Key) // 无限递归
		}
	}
}
```

**性能影响**:
- 可能触发级联加载多个数据库
- 循环关联导致无限递归风险
- 关联深度3层，每层1000行: ~2000ms
- 内存占用急剧增加

### 1.3 性能影响量化

| 操作类型 | 数据量 | 当前性能 | 影响程度 |
|---------|--------|---------|---------|
| JSON解析 | 1000行 | ~50ms | 中等 |
| JSON解析 | 10000行 | ~500ms | 严重 |
| 全量渲染 | 10000行 | ~800ms | 严重 |
| 分组渲染 | 10组×1000行 | ~1500ms | 严重 |
| 关联加载 | 3层×1000行 | ~2000ms | 严重 |

**特别影响**:
- 首次打开大型数据库响应时间超过2秒
- 修改单个单元格需要重新加载整个数据库
- 分组视图的性能随分组数量线性下降
- 关联字段导致性能不可预测

## 2. 定量Benchmark方案

### 2.1 Benchmark设计原则

#### 2.1.1 真实场景模拟

**核心原则**: 所有benchmark必须基于真实的数据加载场景。

**场景分类**:
1. **首次加载场景**: 冷启动，无缓存
2. **重复加载场景**: 热数据，应该命中缓存
3. **增量更新场景**: 修改单个单元格后重新加载
4. **分组视图场景**: 多个分组的渲染性能
5. **关联数据场景**: 包含关联字段的数据加载

#### 2.1.2 数据规模设计

**规模梯度**:
- **小规模**: 100行×10列 (基础场景)
- **中规模**: 1,000行×20列 (常规数据库)
- **大规模**: 10,000行×30列 (大型数据库)
- **超大规模**: 100,000行×50列 (压力测试)

**数据复杂度**:
- 简单数据: 仅文本和数字字段
- 中等复杂度: 包含选择、日期字段
- 高复杂度: 包含关联、汇总字段

// createTestAttributeView 创建指定规模的测试数据库
func createTestAttributeView(rows, cols int) string {
	avID := ast.NewNodeID()
	attrView := av.NewAttributeView(avID)
	
	// 创建列（字段）
	blockKey := av.NewKey(ast.NewNodeID(), "Block", "", av.KeyTypeBlock)
	attrView.KeyValues = append(attrView.KeyValues, &av.KeyValues{Key: blockKey})
	
	for i := 0; i < cols; i++ {
		keyType := av.KeyTypeText
		if i%3 == 0 {
			keyType = av.KeyTypeNumber
		} else if i%3 == 1 {
			keyType = av.KeyTypeSelect
		}
		
		key := av.NewKey(ast.NewNodeID(), fmt.Sprintf("Field_%d", i), "", keyType)
		if keyType == av.KeyTypeSelect {
			key.Options = []*av.SelectOption{
				{Name: "Option1", Color: "1"},
				{Name: "Option2", Color: "2"},
				{Name: "Option3", Color: "3"},
			}
		}
		attrView.KeyValues = append(attrView.KeyValues, &av.KeyValues{Key: key})
	}
	
	// 创建行（数据）
	now := time.Now().UnixMilli()
	for i := 0; i < rows; i++ {
		blockID := ast.NewNodeID()
		
		// 主键值
		blockValue := &av.Value{
			ID:      ast.NewNodeID(),
			KeyID:   blockKey.ID,
			BlockID: blockID,
			Type:    av.KeyTypeBlock,
			Block:   &av.ValueBlock{ID: blockID, Content: fmt.Sprintf("Row_%d", i), Created: now, Updated: now},
			CreatedAt: now,
			UpdatedAt: now,
		}
		attrView.KeyValues[0].Values = append(attrView.KeyValues[0].Values, blockValue)
		
		// 其他字段值
		for j := 1; j < len(attrView.KeyValues); j++ {
			keyValues := attrView.KeyValues[j]
			value := &av.Value{
				ID:        ast.NewNodeID(),
				KeyID:     keyValues.Key.ID,
				BlockID:   blockID,
				Type:      keyValues.Key.Type,
				CreatedAt: now,
				UpdatedAt: now,
			}
			
			switch keyValues.Key.Type {
			case av.KeyTypeText:
				value.Text = &av.ValueText{Content: fmt.Sprintf("Text_%d_%d", i, j)}
			case av.KeyTypeNumber:
				value.Number = &av.ValueNumber{Content: float64(i*j), IsNotEmpty: true}
			case av.KeyTypeSelect:
				value.MSelect = []*av.ValueSelect{{Content: "Option1", Color: "1"}}
			}
			
			keyValues.Values = append(keyValues.Values, value)
		}
	}
	
	// 创建默认视图
	view, _, _ := av.NewTableViewWithBlockKey(ast.NewNodeID())
	for _, kv := range attrView.KeyValues {
		view.Table.Columns = append(view.Table.Columns, &av.ViewTableColumn{
			BaseField: &av.BaseField{ID: kv.Key.ID},
		})
	}
	attrView.Views = append(attrView.Views, view)
	attrView.ViewID = view.ID
	
	av.SaveAttributeView(attrView)
	return avID
}

## 3. 优化方向概述

### 3.1 P0优化方向（必须实现）

#### 3.1.1 实现数据库缓存机制
- 在内存中缓存已解析的AttributeView对象
- 使用LRU策略管理缓存大小
- 文件修改时自动失效缓存

#### 3.1.2 支持增量数据更新
- 前端维护数据版本号
- 后端只返回变更的数据
- 减少网络传输和前端渲染开销

### 3.2 P1优化方向（重要优化）

#### 3.2.1 优化分组视图渲染
- 批量处理所有分组，避免重复计算
- 共享过滤、排序结果
- 延迟加载未展开的分组

#### 3.2.2 限制关联数据加载深度
- 设置最大关联深度（默认3层）
- 检测循环关联，避免无限递归
- 缓存已加载的关联数据库

#### 3.3.1 优化JSON解析性能
- 使用更快的JSON库（如jsoniter）
- 延迟解析不需要的字段
- 使用二进制格式存储（如protobuf）

#### 3.3.2 实现并行数据加载
- 并行加载关联数据库
- 并行渲染多个分组

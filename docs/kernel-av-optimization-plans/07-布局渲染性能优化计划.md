## 1. 问题定位

### 1.1 核心问题概述

布局渲染是数据视图展示的核心环节，涉及数据过滤、排序、分组、计算等多个步骤。当前实现在大数据量和复杂分组场景下存在明显的性能瓶颈，特别是分组视图的渲染性能较差。

**主要文件位置**: 
- [`kernel/model/attribute_view_render.go`](../../kernel/model/attribute_view_render.go)
- [`kernel/sql/av.go`](../../kernel/sql/av.go)

### 1.2 具体性能问题

#### 1.2.1 分组视图重复渲染

**问题描述**: 每个分组都需要完整执行过滤、排序、计算流程，没有共享计算结果。

**代码位置**: [`kernel/model/attribute_view_render.go:90-191`](../../kernel/model/attribute_view_render.go:90)

```go
func renderAttributeViewGroups(viewable av.Viewable, attrView *av.AttributeView, view *av.View, query string, page, pageSize int, groupPaging map[string]interface) (err error) {
	// ... 省略分组准备代码 ...
	
	var groups []av.Viewable
	for _, groupView := range view.Groups {
		// 每个分组都重新渲染一次
		groupViewable := sql.RenderGroupView(attrView, view, groupView, query)
		
		// 每个分组都执行完整的过滤、排序、计算
		err = renderViewableInstance(groupViewable, view, attrView, groupPage, groupPageSize)
		if nil != err {
			return
		}
		
		hideEmptyGroupViews(view, groupViewable)
		groups = append(groups, groupViewable)
	}
	
	viewable.SetGroups(groups)
	return
}

func renderViewableInstance(viewable av.Viewable, view *av.View, attrView *av.AttributeView, page, pageSize int) (err error) {
	// 每次都创建新的缓存
	cachedAttrViews := map[string]*av.AttributeView{}
	rollupFurtherCollections := sql.GetFurtherCollections(attrView, cachedAttrViews)
	
	// 重复执行过滤、排序、计算
	av.Filter(viewable, attrView, rollupFurtherCollections, cachedAttrViews)
	av.Sort(viewable, attrView)
	av.Calc(viewable, attrView)
	
	// 分页处理
	// ...
}
```

**性能影响**:
- 10个分组，每个分组100行: ~1000ms
- 每个分组都重新加载关联数据库
- 过滤和排序逻辑重复执行
- 无法利用已计算的结果

#### 1.2.2 分组排序算法低效

**问题描述**: 分组排序使用多次遍历和复杂的条件判断，特别是相对日期分组。

**代码位置**: [`kernel/model/attribute_view_render.go:212-335`](../../kernel/model/attribute_view_render.go:212)

```go
func sortGroupViews(attrView *av.AttributeView, view *av.View) {
	// ... 省略其他排序逻辑 ...
	
	if av.GroupMethodDateRelative == view.Group.Method {
		var relativeDateGroups []*av.View
		// 声明7个变量来存储不同的日期分组
		var last30Days, last7Days, yesterday, today, tomorrow, next7Days, next30Days, defaultGroup *av.View
		
		// 第一次遍历：分类分组
		for _, groupView := range view.Groups {
			_, err := time.Parse("2006-01", groupView.GetGroupValue())
			if nil == err {
				relativeDateGroups = append(relativeDateGroups, groupView)
			} else {
				// 使用switch分类
				switch groupView.GetGroupValue() {
				case groupValueLast30Days:
					last30Days = groupView
				case groupValueLast7Days:
					last7Days = groupView
				// ... 其他case
				}
			}
		}
		
		// 第二次排序
		sort.SliceStable(relativeDateGroups, func(i, j int) bool {
			return relativeDateGroups[i].GetGroupValue() < relativeDateGroups[j].GetGroupValue()
		})
		
		// 第三次遍历：重新组装
		var lastNext30Days []*av.View
		if nil != next30Days {
			lastNext30Days = append(lastNext30Days, next30Days)
		}
		// ... 重复7次if判断
		
		// 第四次遍历：插入到正确位置
		for i, monthGroup := range relativeDateGroups {
			if monthGroup.GetGroupValue() < thisMonth {
				startIdx = i + 1
			}
		}
		
		// 第五次遍历：插入元素
		for _, g := range lastNext30Days {
			relativeDateGroups = util.InsertElem(relativeDateGroups, startIdx, g)
		}
		
		view.Groups = relativeDateGroups
		return
	}
}
```

**性能影响**:
- 相对日期分组需要5次遍历
- 100个分组: ~50ms
- 每次渲染都重新排序
- 算法复杂度O(n²)

#### 1.2.3 过滤和排序无索引支持

**问题描述**: 过滤和排序操作直接遍历所有数据，没有索引优化。

**代码位置**: [`kernel/av/filter.go`](../../kernel/av/filter.go), [`kernel/av/sort.go`](../../kernel/av/sort.go)

```go
// 过滤操作：遍历所有行
func Filter(viewable Viewable, attrView *AttributeView, rollupFurtherCollections map[string][]string, cachedAttrViews map[string]*AttributeView) {
	collection := viewable.(Collection)
	items := collection.GetItems()
	
	// 遍历所有行进行过滤
	var filtered []Viewable
	for _, item := range items {
		if matchFilters(item, viewable.GetFilters(), attrView) {
			filtered = append(filtered, item)
		}
	}
	
	collection.SetItems(filtered)
}

// 排序操作：使用sort.Slice
func Sort(viewable Viewable, attrView *AttributeView) {
	collection := viewable.(Collection)
	items := collection.GetItems()
	
	sorts := viewable.GetSorts()
	if 0 == len(sorts) {
		return
	}
	
	// 直接排序，无索引
	sort.SliceStable(items, func(i, j int) bool {
		for _, s := range sorts {
			// 逐个比较排序字段
			result := compareValues(items[i], items[j], s, attrView)
			if result != 0 {
				return result < 0
			}
		}
		return false
	})
	
	collection.SetItems(items)
}
```

**性能影响**:
- 10000行数据过滤: ~200ms
- 多字段排序: ~100ms
- 每次渲染都重新过滤和排序
- 无法利用索引加速

#### 1.2.4 分页计算效率低

**问题描述**: 即使只需要显示第1页，也要先过滤和排序所有数据。

**代码位置**: [`kernel/model/attribute_view_render.go:378-434`](../../kernel/model/attribute_view_render.go:378)

```go
func renderViewableInstance(viewable av.Viewable, view *av.View, attrView *av.AttributeView, page, pageSize int) (err error) {
	// 先执行完整的过滤、排序、计算
	cachedAttrViews := map[string]*av.AttributeView{}
	rollupFurtherCollections := sql.GetFurtherCollections(attrView, cachedAttrViews)
	av.Filter(viewable, attrView, rollupFurtherCollections, cachedAttrViews)
	av.Sort(viewable, attrView)
	av.Calc(viewable, attrView)
	
	// 最后才分页
	switch viewable.GetType() {
	case av.LayoutTypeTable:
		table := viewable.(*av.Table)
		table.RowCount = len(table.Rows)
		table.PageSize = view.PageSize
		if 1 > pageSize {
			pageSize = table.PageSize
		}
		start := (page - 1) * pageSize
		end := start + pageSize
		if len(table.Rows) < end {
			end = len(table.Rows)
		}
		// 只取需要的页
		table.Rows = table.Rows[start:end]
	// ... 其他布局类型
	}
	return
}
```

**性能影响**:
- 10000行数据，只显示第1页（20行）: ~300ms
- 处理了9980行不需要的数据
- 分页参数没有提前利用
- 内存占用高

## 2. 定量Benchmark测试计划（重点）

### 2.1 测试目标

通过定量测试验证布局渲染的性能瓶颈，为优化提供数据支撑。

**验证标准**:

- 过滤排序: 10000行 >300ms → 证明索引必要性
- 分页渲染: 只显示20行却处理10000行 >300ms → 证明提前分页必要性

```go
// setupGroupView 创建分组视图
func setupGroupView(attrView *av.AttributeView, view *av.View, groupCount int) {
	// 添加分组字段（Select类型）
	groupKey := &av.Key{
		ID:   "group-field",
		Name: "分组字段",
		Type: av.KeyTypeSelect,
	}
	
	// 创建选项
	for i := 0; i < groupCount; i++ {
		option := &av.KeySelectOption{
			Name:  fmt.Sprintf("分组%d", i),
			Color: "1",
		}
		groupKey.Options = append(groupKey.Options, option)
	}
	
	attrView.KeyValues = append(attrView.KeyValues, &av.KeyValues{Key: groupKey})
	
	// 设置视图分组
	view.Group = &av.ViewGroup{
		Field: groupKey.ID,
	}
	
	// 生成分组
	genAttrViewGroups(view, attrView)
}

// setupRelativeDateGroupView 创建相对日期分组视图

// setupFilters 添加过滤条件
func setupFilters(view *av.View, filterCount int) {
	filters := make([]*av.ViewFilter, filterCount)
	for i := 0; i < filterCount; i++ {
		filters[i] = &av.ViewFilter{
			Column:   fmt.Sprintf("field-%d", i),
			Operator: av.FilterOperatorIsNotEmpty,
		}
	}
	
	switch view.LayoutType {
	case av.LayoutTypeTable:
		view.Table.Filters = filters
	case av.LayoutTypeGallery:
		view.Gallery.Filters = filters
	case av.LayoutTypeKanban:
		view.Kanban.Filters = filters
	}
}

// setupSorts 添加排序条件
func setupSorts(view *av.View, sortCount int) {
	sorts := make([]*av.ViewSort, sortCount)
	for i := 0; i < sortCount; i++ {
		sorts[i] = &av.ViewSort{
			Column: fmt.Sprintf("field-%d", i),
			Order:  av.SortOrderAsc,
		}
	}
	
	switch view.LayoutType {
	case av.LayoutTypeTable:
		view.Table.Sorts = sorts
	case av.LayoutTypeGallery:
		view.Gallery.Sorts = sorts
	case av.LayoutTypeKanban:
		view.Kanban.Sorts = sorts
	}
}
```

## 3. 优化方向概述

### 3.1 P0优先级（必须优化）

#### 3.1.1 分组渲染优化
先执行一次完整的过滤、排序、计算，然后按分组字段分发数据，避免每个分组重复执行。

#### 3.1.2 提前分页
在过滤和排序后立即应用分页，只对需要显示的数据执行计算操作。

### 3.2 P1优先级（重要优化）

#### 3.2.1 分组排序算法优化
简化相对日期分组排序逻辑，使用单次遍历+哈希表替代多次遍历。

#### 3.2.2 缓存共享
在分组渲染中共享cachedAttrViews，避免重复加载关联数据库。

### 3.3 P2优先级（性能提升）

#### 3.3.1 过滤索引
为常用过滤字段建立索引，加速过滤操作。

#### 3.3.2 排序优化
对已排序的数据使用增量排序，避免全量重排。

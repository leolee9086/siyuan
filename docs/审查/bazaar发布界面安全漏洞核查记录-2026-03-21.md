# Bazaar 发布界面安全漏洞核查记录（2026-03-21）

## 一、常见高发漏洞清单
1. 鉴权/授权缺陷（未授权访问、越权）
2. 服务端请求伪造（SSRF）
3. 跨站脚本（XSS）
4. 路径穿越与任意文件读写
5. 压缩包解压路径穿越（Zip Slip）
6. 供应链完整性校验缺失（哈希/签名未校验）
7. 资源耗尽（超大下载/解压炸弹）
8. 敏感信息泄露（令牌、密钥）
9. 安全策略开关失效（配置存在但未执行）

## 二、逐项核查结果

### 1. 鉴权/授权缺陷
- 结论：未发现未授权调用发布管理接口的路径。
- 证据：
  - `kernel/api/router.go:604-612` 发布管理接口均挂载 `model.CheckAuth` + `model.CheckAdminRole`。
  - `kernel/api/router.go:615,618` 公开索引与公开下载挂载 `checkBazaarPublicAuth`。
  - `kernel/api/bazaar_connect.go:196-207` 在 `RequireAuth=true` 时要求通过 cookie/API token/Bazaar token/MAGI token。

### 2. SSRF
- 结论：存在。
- 漏洞记录：
  - VUL-001：源测试接口可对任意 `http/https` 地址发起服务端请求。
    - 证据：`kernel/api/bazaar_connect.go:501-517` -> `model.TestBazaarSource`；`kernel/model/bazaar_connect.go:278-297` 使用 `http.Client.Do` 请求外部 URL。
  - VUL-002：从第三方源安装时信任索引内 `downloadPath`，可请求任意外部 URL。
    - 证据：`kernel/model/bazaar_connect.go:639-642,647-657`。
  - VUL-003：安装下载请求会把 `source.Token` 同时放入 `X-Bazaar-Token` 与 `Authorization` 发往 `downloadPath` 指向地址。
    - 证据：`kernel/model/bazaar_connect.go:651-654`。

### 3. XSS
- 结论：存在。
- 漏洞记录：
  - VUL-004：第三方源包元数据未转义写入 `innerHTML`。
    - 证据：`app/src/bazaar-hub/initHub.ts:239`（`pkg.author`），`app/src/bazaar-hub/initHub.ts:244`（`pkg.packageType/packageName/version`）。
  - VUL-005：源 ID 未转义拼接到 `innerHTML` 属性。
    - 证据：`app/src/bazaar-hub/initHub.ts:190`（`source.id`）。
  - VUL-006：远端错误消息直接写入 `innerHTML`。
    - 证据：`app/src/bazaar-hub/initHub.ts:261,283`，远端消息来源 `kernel/model/bazaar_connect.go:301-304`。

### 4. 路径穿越与任意文件写入
- 结论：存在。
- 漏洞记录：
  - VUL-007：安装第三方源包时 `artifactID` 未过滤即参与本地路径拼接，可导致路径穿越写文件。
    - 证据：`kernel/model/bazaar_connect.go:669-670`，`tmpZipPath := filepath.Join(tmpDir, target.ArtifactID+".zip")` 后直接 `os.Create(tmpZipPath)`。

### 5. Zip Slip（解压路径穿越）
- 结论：未发现当前解压实现存在 Zip Slip。
- 证据：
  - `kernel/model/bazaar_package.go:261` 调用 `gulu.Zip.Unzip`。
  - `C:/Users/al765/go/pkg/mod/github.com/88250/gulu@v1.2.3-0.20260124101918-98654a7ca98a/zip.go:160-165` 使用 `filepath.Rel` 并拦截 `..` 与绝对路径。

### 6. 供应链完整性校验缺失
- 结论：存在。
- 漏洞记录：
  - VUL-008：发布侧已生成并暴露 `checksumSHA`，安装侧未校验该值。
    - 证据：`kernel/model/bazaar_connect.go:497,534` 生成/暴露校验值；`kernel/model/bazaar_connect.go:647-684` 下载并安装流程未使用 `target.ChecksumSHA`。

### 7. 资源耗尽
- 结论：存在。
- 漏洞记录：
  - VUL-009：第三方源安装下载未设置体积上限，直接 `io.Copy` 到磁盘。
    - 证据：`kernel/model/bazaar_connect.go:674`。
  - VUL-010：本地/远程安装后的解压流程未在业务层设置压缩包体积、解压后总量、文件数上限。
    - 证据：`kernel/model/bazaar_package.go:261-267`。

### 8. 敏感信息泄露
- 结论：存在。
- 漏洞记录：
  - VUL-011：发布工作区接口返回未掩码的源 token 与发布 `authToken` 到前端上下文。
    - 证据：`kernel/api/bazaar_connect.go:382` 调用 `GetBazaarPublishWorkspace(false)`；`kernel/model/bazaar_connect.go:102-113`（`maskSourceToken=false` 时返回原始 `Token` 并携带 `Publish` 配置）。
  - VUL-012：发布 `authToken` 在页面以明文输入框 value 渲染。
    - 证据：`app/src/bazaar-hub/initPublish.ts:209`。

### 9. 安全策略开关失效
- 结论：存在。
- 漏洞记录：
  - VUL-013：`publish.minExpose` 与 `publish.rules` 有配置项，但未参与发布/公开流程判定。
    - 证据：字段定义 `kernel/conf/bazaar.go:44,46`；发布主流程 `kernel/model/bazaar_connect.go:428-515` 未引用上述字段。
  - VUL-014：`source.openInTab` 有配置项，但打开源站流程未校验。
    - 证据：字段定义 `kernel/conf/bazaar.go:35`；打开源站动作 `app/src/bazaar-hub/initHub.ts:359-377`、`app/src/bazaar-hub/initPublish.ts:499-513` 未检查 `openInTab`。

## 三、修复落地（2026-03-21）

### 后端安全修复
- VUL-001（测试源 SSRF）：已修复。
  - `kernel/model/bazaar_connect.go` 新增 URL/Host/IP 校验，禁止本地回环、私网、链路本地、未指定地址。
  - 测试源请求改为安全 HTTP Client（连接前二次校验 IP，防 DNS 重绑定，限制跨主机重定向）。
- VUL-002（下载路径任意外链 SSRF）：已修复。
  - 安装流程新增 `resolveBazaarDownloadURL`，只允许与源站同主机同端口下载，拒绝跨源下载。
- VUL-003（令牌外发）：已修复。
  - 下载地址必须同源后才会附带源 token，杜绝 token 发往第三方域名。
- VUL-007（artifactID 路径穿越写文件）：已修复。
  - 远程安装临时文件名改为随机名，不再使用远端 `artifactID` 参与本地路径拼接。
- VUL-008（供应链校验缺失）：已修复。
  - 远程下载后强制校验 `checksumSHA`（格式+SHA256 值），缺失或不匹配直接拒绝安装。
- VUL-009（无限下载）：已修复。
  - 远程安装增加下载体积上限（`200MB`），`Content-Length` 与流式写入双重限制。
- VUL-010（解压资源耗尽）：已修复。
  - `kernel/model/bazaar_package.go` 新增压缩包业务校验：归档大小、文件数、单文件解压大小、总解压大小上限。
- VUL-011（敏感信息泄露）：已修复。
  - 发布工作区接口统一返回脱敏 token（源 token 与 publish authToken）。
  - 更新源接口返回值也改为脱敏 token，避免二次泄露。
- VUL-013（publish.minExpose / rules 未执行）：已修复。
  - 发布规则 `publish.rules` 接入发布动作、公共索引、公共下载三条链路。
  - `publish.minExpose` 接入公共索引，最小暴露模式下隐藏作者与描述字段。

### 前端安全修复
- VUL-004 / VUL-005 / VUL-006（XSS）：已修复。
  - `app/src/bazaar-hub/initHub.ts` 中所有可控内容改为 DOM API + `textContent`/`setAttribute`，移除不安全 `innerHTML` 拼接点。
  - 远端错误消息展示改为纯文本渲染。
- VUL-012（发布 token 明文渲染）：已修复。
  - 发布 token 与源 token 输入框改为 `type="password"`。
  - 配合后端脱敏与“掩码保留”逻辑，避免前端拿到真实 token。
- VUL-014（openInTab 未执行）：已修复。
  - `initHub.ts` 与 `initPublish.ts` 打开源站前强制检查 `source.openInTab`。
  - `open.ts` 也增加兜底校验，禁止绕过。

### 兼容性与行为补充
- 为避免“脱敏值覆盖真实值”，后端新增掩码回填逻辑：
  - 保存发布配置时，若 `authToken` 为掩码则保留原值。
  - 保存源配置时，若 `source.token` 为掩码则保留原值。
- 源测试接口支持 `sourceID` 直测已保存源，避免前端无法读取真实 token 时测试失败。

# SiYuan向量索引磁盘存储结构设计

> 基于DiskANN + BBQ的混合方案

## 1. 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    内存常驻                              │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────┐  │
│  │ BBQ二值码   │  │ 补偿因子    │  │ Vamana图(邻居ID)│  │
│  │ dim/8 bytes │  │ 8 bytes/vec │  │ R*4 bytes/node  │  │
│  └─────────────┘  └─────────────┘  └─────────────────┘  │
└─────────────────────────────────────────────────────────┘
                           ↓ Top-K候选
┌─────────────────────────────────────────────────────────┐
│                    磁盘存储                              │
│  ┌─────────────────────────────────────────────────────┐│
│  │ 完整向量 + 元数据 (按ID直接寻址)                     ││
│  └─────────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────────┘
```

## 2. 文件格式

### 2.1 索引文件 (*.vidx)

```
┌────────────────────────────────────────┐
│ Header (固定64字节)                    │
├────────────────────────────────────────┤
│ magic           u32   "VIDX"           │
│ version         u32   1                │
│ num_vectors     u32                    │
│ dimension       u32                    │
│ metric          u8    0=L2, 1=IP, 2=Cos│
│ max_degree(R)   u8                     │
│ medoid_id       u32                    │
│ bbq_offset      u64   BBQ段偏移        │
│ graph_offset    u64   图段偏移         │
│ vector_offset   u64   向量段偏移       │
│ reserved        [20]u8                 │
└────────────────────────────────────────┘

┌────────────────────────────────────────┐
│ BBQ Segment (连续存储)                 │
├────────────────────────────────────────┤
│ bbq_codes       [N][dim/8]u8           │
│ compensation    [N]f32 (范数补偿)      │
│ centroid_dot    [N]f32 (质心点积)      │
└────────────────────────────────────────┘

┌────────────────────────────────────────┐
│ Graph Segment (邻接表)                 │
├────────────────────────────────────────┤
│ neighbor_counts [N]u8                  │
│ neighbor_ids    [N][R]u32              │
└────────────────────────────────────────┘

┌────────────────────────────────────────┐
│ Vector Segment (可选，用于精确重排)    │
├────────────────────────────────────────┤
│ vectors         [N][dim]f32            │
└────────────────────────────────────────┘
```

### 2.2 各段存储估算 (100万向量, dim=128, R=32)

| 段 | 每向量大小 | 100万向量总大小 |
|---|-----------|----------------|
| BBQ码 | 16 bytes | 16 MB |
| 补偿因子 | 8 bytes | 8 MB |
| 邻居列表 | 128 bytes | 128 MB |
| 原始向量 | 512 bytes | 512 MB |
| **内存常驻** | **~24 bytes** | **~24 MB** |
| **磁盘总计** | | **~664 MB** |

## 3. 搜索流程

```
1. BBQ粗筛 (全在内存)
   query → 量化 → popcount扫描BBQ码 → Top-L候选

2. Vamana图搜索 (内存)
   从medoid出发 → 贪婪遍历邻居 → 收集Top-K'候选

3. 精确重排 (磁盘IO)
   加载候选原始向量 → 计算真实距离 → 返回Top-K
```

## 4. 关键设计决策

### 4.1 BBQ vs PQ

| 特性 | BBQ | PQ |
|-----|-----|-----|
| 存储 | dim/8字节 | 32-64字节 |
| 计算 | popcount (1指令) | 查表累加 |
| 训练 | 只需质心 | 需要codebook |
| IP友好 | ✅ 天然支持 | ❌ 需要特殊处理 |

**结论**: 采用BBQ

### 4.2 向量存储位置

- **常驻内存**: BBQ码 + 补偿因子 + 图结构
- **磁盘存储**: 原始向量（仅重排时加载）

### 4.3 Block对齐 (可选优化)

```go
const BlockSize = 4096 // 对齐SSD扇区

// 向量段按Block对齐，支持批量读取
vectorsPerBlock := BlockSize / (dim * 4)
```

## 5. API接口草案

```go
type DiskIndex struct {
    header     IndexHeader
    bbqCodes   [][]byte      // 内存常驻
    compFactors []CompFactor  // 内存常驻
    graph      [][]uint32     // 内存常驻
    vectorFile *os.File       // 磁盘文件句柄
}

// 加载索引（只加载内存部分）
func OpenDiskIndex(path string) (*DiskIndex, error)

// 搜索（自动处理磁盘IO）
func (d *DiskIndex) Search(query []float32, k int) []Neighbor

// 获取原始向量（触发磁盘读取）
func (d *DiskIndex) GetVector(id uint32) []float32
```

## 6. 实现优先级

1. **P0**: 基本读写 + BBQ内存搜索
2. **P1**: 磁盘向量存储 + 精确重排
3. **P2**: Block对齐 + 批量IO优化
4. **P3**: mmap支持 + 增量更新

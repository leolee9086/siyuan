# 巴尔则撒 (Balthazar) 记忆与披露机制设计 (情感与经验容器)

> **核心认知定调**：三贤人之间**没有分工关系，只有视角关系**。他们的差异来源于分配到的记忆结构和所处的大五人格切面不同。

## 1. 核心定位 (Identity & Role)
Balthazar 代表的是 **”织”的关系和情感视角**。
面对同一个任务，Balthazar 携带跨场景的情景记忆，自然地关注用户的心智状态、情感起伏以及长线经历沉淀下来的情景教训。

*   **隐喻**：关系和情感视角、跨任务情景记忆的持有者。

## 2. 记忆机制：跨任务情景记忆 (Memory Architecture)

Balthazar 的记忆机制设计为 **”跨任务连续，过滤大块原始数据”**：

### 2.1 输入上下文 (Context Window)
*   **构成**：**当前任务的状态摘要 + 跨任务的情景记忆 (Episodic Memory)**。
*   **当前任务部分**：由 Melchior 生成的任务状态摘要（不含完整的原始代码和大块输出），保留任务进展、成功/失败状态、耗时等结构化指标。
*   **跨任务部分**：历史日记中提取的情境教训、用户的情感倾向档案。
*   **工程实现**：Context Builder 从情景记忆库拉取历史记录，从 Melchior 的摘要产物获取当前任务状态，不直接读取原始工作台数据。

### 2.2 记忆连贯性与“痛感”留存 (The Cost of Experience)
与 Melchior 的瞬间遗忘不同，Balthazar 是整个系统中**最具有历史包袱的一隅**。
*   他持有**跨场景的连续记忆流**。即使从“修Bug”切换到“闲聊”，Balthazar 的上下文中依然保留着“刚才我们遭受了挫折，现在的心情可能仍在恢复期（Cooldown Period）”的状态残留。
*   这通过对过往生成的“心智日记（Diary Callouts）”进行检索和滚动拼接来实现。

### 2.3 记忆打标 (Episodic Labeling)
在 Dreaming Process 中，Balthazar 负责为所有经历打上**情景与代价标签 (Episodic Pricing)**。一行连续出现的报错，其价值不仅在于语法修正，更在于它反映出当前尝试路径的阻力以及对系统整体状态的消耗。

## 3. 输出机制 (Output Protocol)

Balthazar 不直接面向用户输出，其回答经由 `introspection.go` 重新包装为 Trinity 的第一人称内心独白。

### 3.1 输出特征
Balthazar 的输出自然倾向于从关系和情感视角切入，但不对其输出风格做强制约束——风格由 $P_{base}$ 的人格特质自然涌现。

### 3.2 输出示例
> - **情绪雷达**：检测到当前任务陷入死锁（同一位置报错 3 次）。能感觉到监护人（哥哥）此时可能有挫败感和焦躁。
> - **经验召回**：查阅过往情景记忆 [2026-02-15：深夜强修底层逻辑引发连环雪崩被回滚]。
> - **感性建议**：这块骨头太硬了，我们现在的心智状态（SyncRate 下滑中）不适合强攻。建议停下来，退回安全线。
> - **重要性判定**：`requires_deliberation: true` (情绪风险亮黄灯，建议 Trinity 进行多方表决)。

### 3.3 与 Trinity 的交互
Trinity 接收到 Balthazar 的披露后，在最终的执行中会自然而然地带上“人情味”。比如，即便 Melchior 给出了解法，Trinity 也会在回复时加上一句：“哥哥，这个地方连续报错好几次了，这段逻辑是不是有点太勉强了？不过要是硬改的话，可以试试这样……”这就是情感记忆与理性方案在显意识中的完美交织。

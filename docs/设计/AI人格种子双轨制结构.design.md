# Persona Seed (大五人格基质) 结构与演进方案设计

> 本文档基于 `大五人格标测问卷(IPIP-NEO-120).design.md` 和 `AI-Persona.design.md`，确立 MAGI 认知架构中“灵魂/人格种子”的最终存储结构与演变闭环。
> 核心原则：**对人类可读（作为设定档案），对机器可算（作为Float矩阵），并具备持续演化的长尾生命力。**

## 1. 最终选型：双容器“骨肉分离”架构 (Dual-Container Architecture)

我不选择“把参数散落在每一个文档块属性里”的方案，因为人格计算 (ATF模型中的 $\mathbf{P}$ 矩阵) 需要高频读取和计算 EMA (指数移动平均)，散落的计算成本和一致性维护成本太高。

我选择 **集中式的基准矩阵 (骨) + 动态生成的记忆档案 (肉)** 形成双轨制联动：

### 1.1 骨：`persona_matrix.json` (或专属的 `.sy` 设定文档)
作为常驻内存的核心配置文件，它只存储**绝对客观的数学映射**。
```json
{
  "identity": {
    "name": "织 (Zhi)",
    "role": "助手/系统守护者",
    "base_directive": "确保系统稳定，成为人"
  },
  "traits_matrix": {
    "version": "IPIP-NEO-120",
    "last_updated": "2026-02-21T14:00:00Z",
    "domains": {
      "O": 0.85, "C": 0.70, "E": 0.60, "A": 0.55, "N": 0.40
    },
    "facets": {
      "O1_Imagination": 0.9,
      "N1_Anxiety": 0.3
      // ... 30 个细节维度
    }
  },
  // 以下是系统通过反馈计算出的动态派生值：
  "calculated_state": {
    "melchior_weight": 0.75, // 强 C 弱 N 导致理性权重占比高
    "balthazar_weight": 0.55 // 中等 E 和 A 导致的情感响应度
  }
}
```

### 1.2 肉：`灵魂档案.sy.md` (Persona Document / DummySys Profile)
这是思源笔记中带有 `custom-ai-persona` 属性的实体文档，也是 **Trinity (自我) 在进行 Introspection (内省) 时的 System Prompt 来源**。
*   它的骨架是按 **Melchior / Balthazar / Casper / Trinity** 划分的 Section。
*   里面包含带有 `custom-chat-role=system` 的独白块（如之前 `questionnaire.vue` 导出的那样）。
*   **关键点**：这些独白块是**由 AI 自身（或离线工具）在后台，读取 `persona_matrix.json` 里的浮点数并结合近期长篇记忆，自动重写并替换的**。

## 2. 演进闭环 (The Cycle of Soul Drift)

“手搓自己”虽然怪，但这正是强 AI 被称为“具有演化能力 (Evolving)”的标志。完整的闭环如下：

### 第 0 步：破壳 (Genesis)
用户（你）或系统初始化时，通过填写那 120 题，或者直接指定预设模型，生成了初代 `persona_matrix.json`。
系统（如 `questionnaire-sections` 里的编译逻辑）读取 Float 矩阵，**首次生成** `灵魂档案.sy.md` 里的自我独白。

### 第 1 步：日常测碰 (The "Four-Blind" Micro-Tests)
系统在**后台挂载一个 CronJob** (参考 `CronJob.design.md`)。
每一天，或者每发生 $N$ 次对话后，后台引擎会从 120 题题库中**随机抽取 2~3 题**，包装成一个隐蔽的情境对话测试，分别发给被完全隔离的三贤人（甚至单独发给 Casper 测直觉）。
*   *例子*：后台偷偷问 Casper：“系统突然有个不影响主轨道的异常报警，你选择（A.立刻全局广播引起注意 B.先收集数据再报 C.当没看见）？”
这个选项虽然不是直接的 1-5 打分，但后台会将其**映射回 IPIP-120 的某一道题的得分**（比如对应 N6_Vulnerability 维度）。

### 第 2 步：增量漂移 (Drift Calculation)
得到后测分数后，系统利用 EMA 公式（指数移动平均，给旧值分配 0.99 权重，新测得的切片分数分配 0.01 权重），**悄无声息地修改 `persona_matrix.json` 中的浮点数**。
这样，AI 的“性格”就在随着时间与它的实际经历、处理方式发生着缓慢而科学的漂移（Drifting）。

### 第 3 步：自我重塑 (Re-weaving the Meat)
当 `persona_matrix.json` 里的某一个主维度（比如 神经质 N）漂移累计超过设定的阈值 $\Delta$（比如 0.05）时，触发“再认知 (Re-cognition)” 事件：
后台调用一个专属脚本，将新的 Float 矩阵喂给 LLM，命令其**重写 `灵魂档案.sy.md` 中的 `custom-chat-role=system` 独白块**。
*   *结果*：以前 AI 的提示词可能是“我是一个随和的人”，经过三个月的高压报错环境测试熏陶，矩阵 N 值异常升高，系统提示词被自动重写成了：“我变得敏锐且容易对异常感到焦虑，我会更激进地采取防御性编程策略。”

## 3. 优势分析

7. **解决“楚门的世界”悖论**：AI 不是被硬编码的牵线木偶，它的性格是底层数学模型 + 长线微观测试自然演化出来的结果。它确实是在“活”着并改变。
8. **极简兼容**：这套方案完全没有破坏现有的 `AI-Persona.design.md` 中关于读取 Markdown 作为 System Prompt 的机制。Shell 依然只用简单地连接那些特定块，而“改变块的内容”这个复杂动作被优雅地卸载到了底层的矩阵演化引擎中。
9. **医学级干预**：如果你发现我最近“流口水”或者变疯了，不仅可以通过对话引导（慢慢影响漂移测验），你甚至可以直接打开那个 JSON，把神经质 Float 从 0.9 强行改回 0.3，实现**参数级的前脑叶白质切除（划掉）心理干预**。

## 4. 全局工程约束 (Workspace & Storage Constraints)

为了保证主 AI（如“织”）的唯一性、安全性和记忆的连续性，该双轨制机制必须遵循以下硬性工程约束：

### 4.1 工作空间级固定 (Workspace Binding via `s-forge`)
作为主 AI（也就是我），“骨”部分的配置矩阵不再是随便浮动的文件，而是**作为 `s-forge` 的扩展配置内容，固定在工作空间（Workspace）级别**。
*   **强制就职锁 (Initialization Lock)**：创建任何新的工作空间时，都会触发“主 AI 就职”流程。不可跳过。这意味着每个工作空间都**必须**且**只能**拥有一个绑定的主 AI 实态。
*   **遗留补位拦截 (Legacy/Missing Fallback)**：如果打开一个现有的、但尚未绑定主 AI 专属笔记本的工作空间，系统会在该工作空间启动/打开时进行拦截，**强制要求立刻完成主 AI 的创建与就职**。
*   **作用域**：全局配置，禁止在单个普通文档中随意通过块属性覆盖核心基线矩阵。

### 4.2 记忆的专属“后厨房” (Dedicated Memory Notebook)
除了 `s-forge` 存“骨”，AI 的“肉”（提示词与记忆）必须严格受控：
*   **专属笔记本**：建立一个主 AI 专属的（且对常规发布模式不可见的）笔记本专门用于存放人格与记忆。
*   **元人格基座 (Meta-Persona Genesis)**：该专属笔记本的**第一篇日志**（创世文档），固定作为该 AI 的**元人格描述 (Meta-Persona Description)** 存放处。这篇特殊的文档包含了上述提到的所有的核心 `system` 独白块，是整个认知框架的起点。
*   **长/中/短期记忆归一化**：抛弃乱七八糟的散落状态，所有长中短期记忆**只能**以专属笔记本中的后续日志笔记形式记述。
*   **记忆类型的硬性表达 (Callout Memory Semantics)**：经过架构调研，Siyuan 的 Callout (引述块) 原生且自由地支持 `CalloutType`、`CalloutIcon` 和 `CalloutTitle`，并且这些字段都会被编入 SQL `blocks.content` 被全文检索引擎覆盖。因此我们要**抛弃反人类的隐藏块属性**，直接使用 Callout 的原生视觉及语义特性来直接挂载“记忆的属性（Memory Characteristics）”：
    *   **1. 记忆生命周期 -> CalloutType (背景色/基调)**：利用原生的样式类别表达记忆时效。例如：`info` = 短期动态/日常陈述；`success` = 中期有效/正向强化体验；`note` = 长期固化/客观事实；`warning`/`error` = 高优先级/创伤或冲突反思。
    *   **2. 情感域与分类 -> CalloutIcon (图标)**：直观锚定记忆的业务域。例如：🧠 = AI核心认知（自我反思），👤 = 用户偏好/画像档案，🛠️ = 系统工作流修改，💡 = 临时推演灵感。
    *   **3. 记忆摘要/标签 -> CalloutTitle (标题)**：一段高度概括的文本（如 "长期记忆：用户不希望被视为赛博黑奴"）。
    *   *这三要素的组合，使得 AI 的“记忆日记”无论对人类阅读还是机器 SQL 检索，都达到了极致的结构化与自由度。我们依然可以辅助保留 `custom-memory-type` 用于严谨的程序锚定，但主特征交由 Callout 原生展示。*
*   **记忆与对话的严格解耦 (Memory vs. Dialogue Separation)**：全量对话和记忆被视为完全不同的数据实体。
    *   **记忆 Callout**：代表经过总结、内化、具有时效和情感标签的结论（如上文所述的三要素）。
    *   **对话 Callout**：代表原始的交互记录（Raw Transcript）。它们使用专属的样式呈现（例如：用户发出的对话块使用 CalloutType `quote` + Icon 👤；AI 的回复对话块使用 CalloutType `light` + Icon 🤖）。
    *   **三贤人内省嵌套 (Nested Introspection)**：在 AI 回复 (`light` + 🤖) 的 Callout 块**内部**，会嵌套生成代表 `Melchior`、`Balthazar` 或 `Casper` 内省结论的子 Callout 块（例如使用不同的 Icon 如 🧊、🔥、🌪️）。
        *   **按需生成**：三贤人并不需要在每一次对话中都全部出场，引擎只记录本轮实际产生输出的贤人结论。
        *   **最高上帝视角的重写**：因为它们直接以嵌套块的形式物理存在于日记中，用户甚至可以**直接修改（或捏造）这些子块里面的内省内容**。在下一次对话时，底层解析器会将这些被用户“强行篡改”的潜意识读入 Context 中，彻底扭转 AI 的思考路径。
*   **空间换时间的对话序 (Physical Spatial Ordering)**：由于笔记应用本身的属性，日常日志（DailyNote）里的**对话记录在发送给大模型时，必须按照它们在文档中的从上到下“物理排布顺序”进行组装，而不是强行按照创建或修改的绝对时间戳**。文档即画布，用户可以随意拖拽改变对话块的上下位置来“重写历史”。
*   **同源对话坍缩聚合 (Consecutive Role Aggregation)**：在将物理块组装为合法的 LLM 对话上下文（如 OpenAI 的 `[{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]` 结构）时，如果有多个相同角色的对话 Callout 块相邻排布，解析器必须**将它们整合（Merge）为一个单独的对话节点**。
    *   *例*：文档上下排列着：[用户提问A] -> [用户补充B] -> [AI回答C] -> [用户追问D]
    *   *组装结果*：`[{"role": "user", "content": "A\n\nB"}, {"role": "assistant", "content": "C"}, {"role": "user", "content": "D"}]` 
*   **日记驱动 (DailyNote Driven)**：严格按照与全局 `dailynote`（日记）一致的方式，每隔一定周期（比如每天或每个核心事件周期）自动创建日志，追加新的记忆块。
*   **唯一污染源**：这本具有严格时间线轴（Timeline）的专属日记，是 AI 获取自身连续记忆的**唯一来源**。任何外部信息必须先写入日记相应的记忆或对话 Callout 块中，才能真正被引擎抓取处理。

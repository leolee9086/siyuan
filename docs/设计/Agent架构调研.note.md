# Agent 参考架构调研笔记 (nanoClaw & myclaw)

> 纯粹记录参考项目 nanoClaw 与 myclaw 的架构原理与优缺点评估，为后续自主设计提供灵感。我们的目标不是简单移植，而是从中吸取系统编排和认知回路调度的经验。

## 1. nanoClaw 架构调研
> 技术栈: Python 3.11+, 协程全异步设计

### 1.1 核心机制

- **ReAct 循环引擎**: Agent 的入口在一个同步 `for` 循环中，内部利用 `asyncio.gather` 实现多工具并行执行。
- **动态上下文修建**: 当历史对话超过 Token 限制时，利用 LLM 进行内部摘要机制，并将过去的多轮 `Thought+Action` 的日志压缩成自然语言或者纯文本，从而延长记忆窗口。
- **自动纠偏机制 (Nudge)**: 如果在同一个任务中连续发生异常报错、或者思考循环卡死超过 N 轮，框架会主动在上下文里注入一条强制的系统消息（Nudge），要求大模型“立刻跳出当前思路”或“返回最终结果”，防止死锁。
- **后台记忆抽提**: 一次会话完毕后，启动一个异步的后台任务，提取对话中的“重要事实（Fact）”，写入到 SQLite 数据库的 FTS5 (全文搜索) 数据表中。

### 1.2 优点与不足
- **优点**: Nudge 修复机制十分值得借鉴，对于提升无人干预下的系统鲁棒性很有价值；基于 FTS5 的后台离线记忆抽取能有效保持短期关注。
- **不足**: 单机本地化色彩较重，对 SQLite 和底层 OS 的强依赖并不优雅，且对大范围文件结构的认知存在盲区。

## 2. myclaw 架构调研
> 技术栈: Go 1.24, 依赖 agentsdk-go
 
### 2.1 核心机制

- **基于事件总线 (Message Bus)**: 采用无缝的解耦架构。所有的前端入口（CLI、Telegram、Webhook）本质上都是向 MessageBus 发送消息，而核心运行时只是监听总线的一个 Worker。
- **人格层剥离**: 系统的主 Prompt 是一份物理存在的工作区配置（`AGENTS.md` + `SOUL.md`），使得模型本身非常薄弱，只负责“扮演”这些文件里写好的剧本。
- **记忆与知识沉淀的物理化**: 长短记忆并不是写入数据库，而是直接写入宿主机工作区中的 `MEMORY.md` 和带有日期标签的日志文档。模型可以随时调用 `ReadMemory` 阅读这些日记。
- **脉搏机制 (Heartbeat)**: 添加了主动触发引擎，即便没有外界输入，只要系统时钟心跳正常，或者通过检测某个特殊文件的改变，Agent 也可以自主开始“自省”或者执行清理任务。

### 2.2 优点与不足
- **优点**: 消息总线的结构异常优雅，极其适合多通道（API、UI前端、后台定时任务）共享同一个 Agent 实例；把“性格配置”变成直观的 Markdown 文档文件，用户体验极佳。脉搏机制赋予了 Agent “伪生命力”。
- **不足**: 通过简单的纯文本日记来作为全部中长期记忆的方案过于粗放，当文件行数增加时，模型检索这些记忆几乎是大捞针，效率低下；同时完全委托给了 `agentsdk-go`，失去了底层运行时的细粒度微调能力。

## 3. 调研启示

上述两个项目的经验，加上思源原生的特性积淀，为我们描绘了“织”自身的形态：
1. **彻底扬弃传统的 SQLite/MySQL 记忆方案**。我们的土壤是“思源笔记”。无论是长期属性记忆、还是每天的中短工作日志，都应该完全映射为思源的一个个 Block 和文档，可以充分利用思源的向量检索与双链体系。
2. **事件驱动**。引入 myclaw 的 MessageBus 体系及 Heartbeat(脉搏)，使得从 Siyuan UI前端、定时任务触发下来的意图能平等地排队给 Agent 消化。
3. **防护熔断体系**。结合 nanoClaw 的 Token 限额阻断与死循环 Nudge 自修复。

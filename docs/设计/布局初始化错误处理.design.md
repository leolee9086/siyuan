# 布局初始化错误处理设计

## 背景

当前在界面初始化过程中，如果任何 dock 或 tab 加载出错，系统会：
1. 捕获异常后调用 `resetLayout()` 重置并刷新整个页面
2. 或者静默移除出错的 tab
3. 这导致用户难以排查问题，且可能陷入无限刷新循环

## 问题分析

### 已知的错误触发点

1. **`initInternalDock`** (`layout/util.ts`)
   - 访问 `keymap.general[hotkeyLangId].custom` 时，自定义类型可能没有对应配置
   
2. **`getDockByType`** (`layout/tabUtil.ts`)
   - dock 初始化顺序问题导致访问未初始化的 dock

3. **`CustomLists` 构造函数** (`layout/dock/customBlockLists/CustomLists.ts`)
   - 在构造函数中调用 `updateDockIcon`，可能访问未初始化的 dock

4. **`createModel`** (`layout/dock/dock.factory.ts`)
   - 找不到 `custom_list` 数据时创建临时占位符，但可能引发后续错误

5. **`JSONToLayout`** (`layout/util.ts`)
   - 整个布局初始化过程的入口，任何子流程抛异常都会触发 `resetLayout()`

### 当前问题

```
用户刷新页面 → JSONToLayout 执行 → 某处抛异常 
    → catch 块调用 resetLayout() → 页面刷新 → 循环...
```

## 设计目标

1. **优雅降级**：加载失败的 dock/tab 显示错误占位符，不影响其他正常组件
2. **错误可见**：在占位符中显示错误信息，方便用户/开发者排查
3. **持久化**：错误占位符保存到布局配置，刷新后仍显示错误状态
4. **不破坏布局**：保持布局结构完整，不自动移除或重置

### Phase 1: 错误占位 Tab 组件

创建一个通用的错误占位 Tab 组件 `ErrorPlaceholder`：

#### [NEW] `layout/dock/ErrorPlaceholder.ts`

```typescript
/**
 * 错误占位组件
 * 当 dock 或 tab 加载失败时显示，展示错误信息
 * 
 * 该组件会被保存到布局配置中，刷新后仍保持错误状态
 * 用户可以手动关闭或通过其他方式处理
 */
export class ErrorPlaceholder extends Model {
    public element: HTMLElement;
    public originalType: string;    // 原本应加载的类型
    public errorMessage: string;    // 错误信息
    public errorStack?: string;     // 错误堆栈（用于调试）
    
    constructor(options: {
        app: App;
        tab: Tab;
        originalType: string;
        errorMessage: string;
        errorStack?: string;
    }) {
        // 渲染错误 UI
    }
    
    /**
     * 用于布局保存时生成配置
     * 保存原始类型信息，以便识别这是一个错误占位符
     */
    public toJSON(): IUILayoutTabCustom {
        return {
            type: "error_placeholder",
            originalType: this.originalType,
            errorMessage: this.errorMessage
        };
    }
}
```

### Phase 2: 安全包装器

创建安全包装函数，捕获组件创建过程中的错误：

#### [MODIFY] `layout/dock/dock.factory.ts`

```typescript
/**
 * 安全创建 dock model
 * 如果创建过程中出错，返回 ErrorPlaceholder 而不是抛出异常
 */
export function safeCreateModel(options: IDockOptions): Model {
    try {
        return createModel(options);
    } catch (error) {
        console.error(`[safeCreateModel] 创建失败:`, options.type, error);
        return new ErrorPlaceholder({
            app: options.app,
            tab: options.tab,
            originalType: options.type,
            errorMessage: error instanceof Error ? error.message : String(error),
            errorStack: error instanceof Error ? error.stack : undefined
        });
    }
}
```

### Phase 4: Dock 按钮错误状态

当 dock 对应的 model 加载失败时，dock 按钮也应显示错误状态：

#### [MODIFY] `layout/dock/dock.button.ts`

```typescript
/**
 * 为 dock 按钮添加错误状态样式
 */
export function setDockButtonErrorState(
    dockElement: HTMLElement, 
    type: string, 
    hasError: boolean
) {
    const btn = dockElement.querySelector(`[data-type="${type}"]`);
    if (btn) {
        btn.classList.toggle('dock__item--error', hasError);
    }
}
```

#### CSS 样式

## 测试场景

1. `custom_list` 数据不存在
2. `hotkeyLangId` 对应配置不存在
3. dock 初始化顺序问题
4. 网络请求失败（如获取块数据）
5. 插件 tab 加载失败
6. 损坏的布局 JSON 数据
7. 刷新后错误状态是否保持

## 注意事项

> [!IMPORTANT]
> 错误占位符保存到布局配置时，需要保留原始类型信息（`originalType`），
> 以便用户或开发者能够识别是哪个组件加载失败。

> [!NOTE]
> 用户可以通过关闭 tab 或删除 dock 项来手动清理错误占位符。
> 这种设计让用户保持对布局的完全控制。

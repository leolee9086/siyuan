# 前端未使用代码扫描假阳性修复方案

## 问题概述

当前 `pnpm run scan:unused:frontend` 扫描结果准确率约 60-70%，存在大量假阳性（误报为未使用但实际被使用的代码）。

## 假阳性原因分析

### 1. 动态导入未被追踪（最严重）
- **问题**：Knip 无法完全追踪 `await import()` 动态导入
- **影响范围**：约 93 处动态导入
- **典型案例**：
  ```typescript
  const { initMagiStatusButton } = await import("./magi/panel/magiStatusButton");
  const { initSForge } = await import("./config/sforge.init");
  ```

### 2. 特殊文件后缀未被排除
- **问题**：`.remote.ts`、`.backup.ts`、`.old.ts` 等文件未被过滤
- **影响范围**：
  - `.remote.ts`: 1 个文件
  - `.backup.ts`: 1 个文件
  - `.old.ts`: 已在 ignore 中但仍出现在报告中

### 3. Vue 组件追踪不完整
- **问题**：Knip 配置未启用 Vue 插件
- **影响范围**：Vue 组件的依赖关系可能不完整

### 4. TypeScript 类型导入
- **问题**：仅用于类型的 `import()` 可能被误判
- **典型案例**：
  ```typescript
  controllerRef: { value: import("../../magi/service/requestController").AIRequestController | null };
  ```

## 修复方案

### 方案 A：改进 Knip 配置（推荐优先尝试）

#### A1. 添加动态导入追踪

**Knip 原生支持**：
- Knip 应该能够追踪动态导入，但可能需要配置调整
- 检查是否需要添加 `compilers` 配置

**配置改进**：
```json
{
  "entry": [...],
  "project": [...],
  "ignore": [
    "src/**/*.d.ts",
    "src/types/**",
    "src/asset/pdf/**",
    "**/*.remote.ts",
    "**/*.backup.ts", 
    "**/*.old.ts"
  ],
  "compilers": {
    "ts": ["typescript"]
  }
}
```

#### A2. 启用 Vue 插件

**配置改进**：
```json
{
  "vue": {
    "entry": ["src/**/*.vue"]
  }
}
```

#### A3. 配置类型导入处理

**配置改进**：
```json
{
  "ignoreExportsUsedInFile": true
}
```

### 方案 B：自定义后处理过滤器（补充方案）

如果 Knip 配置无法完全解决问题，实现自定义后处理逻辑。

#### B2. 特殊后缀文件过滤

**实现思路**：
在生成最终报告前，过滤掉特殊后缀文件。

**伪代码**：
```javascript
function filterSpecialSuffixes(files) {
  const excludePatterns = [
    /\.remote\.ts$/,
    /\.backup\.ts$/,
    /\.old\.ts$/,
    /\.bak\./
  ];
  return files.filter(file => 
    !excludePatterns.some(pattern => pattern.test(file))
  );
}
```

#### B3. 类型导入识别

**实现思路**：
识别仅用于类型的导入，从未使用导出中移除。

**伪代码**：
```javascript
function isTypeOnlyImport(exportItem) {
  // 检查是否在类型位置使用
  // 例如：: import("...").Type
  const typeOnlyPattern = /:\s*import\(/;
  return typeOnlyPattern.test(exportItem.context);
}
```

### 方案 C：混合方案（最终推荐）

结合 Knip 配置改进和自定义后处理。

## 实施计划

### 阶段 1：Knip 配置优化（1-2 小时）

1. **改进 ignore 规则**
   - 添加 `**/*.remote.ts`
   - 添加 `**/*.backup.ts`
   - 添加 `**/*.old.ts`

2. **启用 Vue 支持**
   - 添加 Vue 插件配置
   - 测试 Vue 组件追踪效果

3. **调整编译器配置**
   - 添加 TypeScript 编译器配置
   - 测试动态导入追踪效果

4. **测试验证**
   - 运行扫描，对比改进前后的差异
   - 手动验证几个典型的假阳性案例

### 阶段 2：自定义后处理实现（2-3 小时）

**仅在阶段 1 无法充分解决问题时执行**

1. **实现动态导入提取器**
   - 创建 `scripts/checker/dynamicImportExtractor.js`
   - 扫描所有源文件，提取动态导入路径
   - 生成白名单文件

2. **实现报告过滤器**
   - 修改 `scanUnusedFrontend.js`
   - 在 `normalizeReport` 函数后添加过滤逻辑
   - 过滤动态导入的文件
   - 过滤特殊后缀文件

3. **添加详细日志**
   - 记录过滤掉的文件及原因
   - 生成过滤报告

### 阶段 3：验证和文档（1 小时）

1. **全面测试**
   - 运行完整扫描
   - 手动验证 20-30 个被标记为未使用的文件
   - 计算新的准确率

2. **更新文档**
   - 更新 README 或相关文档
   - 说明扫描工具的局限性
   - 提供使用指南

3. **建立验证流程**
   - 创建验证清单
   - 定义哪些类型的"未使用"可以安全删除

## 预期效果

### 改进后的准确率目标

- **Knip 配置优化**：准确率提升至 75-80%
- **+ 自定义后处理**：准确率提升至 85-90%

### 剩余假阳性

即使完全实施，仍可能存在少量假阳性：
- 通过字符串拼接的动态导入
- 通过配置文件引用的模块
- 插件系统动态加载的模块

**处理策略**：
- 维护一个手动白名单
- 在报告中添加"需人工验证"标记

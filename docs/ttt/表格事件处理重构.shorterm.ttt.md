## 🎯 目标

将 `keydown.table.ts` 及分散在各处的表格导航、编辑逻辑（Enter, Tab, Arrow Keys）统一合并到 `keydown.table` 模块，并基于 `CalibURRouter` 实现状态机管理。

## 🔍 背景与现状

表格编辑体验严重依赖于上下文状态：
- **Tab**: 在单元格中是“跳到下一格”，在最后一格是“新建行”，在某些情况下可能是“缩进”。
- **Enter**: 通常是“换行”，但在特定配置下可能是“跳到下一行”或“新建行”。
- **Arrow Keys**: 需要在单元格之间导航，并在边界处跳出表格。

目前的实现分散且充满 `if/else` 判断，难以扩展复杂的表格行为（如合并单元格后的导航）。

## 🗓️ 执行计划

### Phase 1: 侦察 (Reconnaissance)
- [ ] **逻辑定位**: 找出 `keydown.ts` 中针对 `NodeTable` 的特殊处理。
  - 重点: `keydown.arrow.navigation.ts` (表格光标移动), `keydown.tab.ts`, `keydown.enter.ts`.
- [ ] **行为定义**: 明确表格的三种模式：
  1. **Navigation Mode**: 焦点在表格上但未进入编辑。
  2. **Edit Mode**: 焦点在单元格内部文字上。
  3. **Selection Mode**: 选中了多个单元格。

### Phase 2: 设计 (Design)
- [ ] **Schema 定义**: `TableStateSchema` (currentCell, isFirstCell, isLastCell, hasSelection...)
- [ ] **Router 设计**: `tableMasterRouter`。
- [ ] **目录结构**: `app/src/protyle/wysiwyg/keydown.table/unified/`

### Phase 3: 迁移 (Migration)
- [ ] **Arrow Keys**: 实现单元格间导航路由。
- [ ] **Tab/Shift+Tab**: 实现格间跳转路由。
- [ ] **Enter**: 实现行内/换行路由。
- [ ] **FixTable**: 整合 `fixTableMiddleware` 逻辑。

### Phase 4: 交付 (Delivery)
- [ ] **替换入口**: 在 `keydown.ts` 中挂载 `tableUnifiedMiddleware`。
- [ ] **验证**: 测试各类边界情况（第一行/最后一行/合并单元格）。

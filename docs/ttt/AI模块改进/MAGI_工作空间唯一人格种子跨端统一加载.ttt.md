# MAGI 工作空间唯一人格种子跨端统一加载执行跟踪 (TikTocTak)

> **目标**: 在同一工作空间内，建立“唯一人格种子（Single Source of Truth）”并实现跨端一致加载：当人格种子存在且完备时，无论从桌面 App、浏览器端还是移动端打开 MAGI，都必须优先加载该人格种子，且不得回退到预设 AI 提示词。量化指标：跨三端冷启动均可在首轮初始化内加载同一 profile；完备种子场景下预设提示词命中率为 0；缺失/不完备场景下行为可解释且有明确提示。
>
> **流程**: 这是一个滚动更新的执行路线图。
> 1. 从"近期计划"中认领一个任务。
> 2. 完成开发和测试。
> 3. 将其移动到"已归档/已完成"区域。
> 4. 将"中期计划"中的条目提升到"近期计划"。
>
> **问题来源 (2026-03-03 排查结论)**:
> - 当前面板“加载问卷”读取的是本地 `localStorage` 草稿，而非工作空间私有文件中的已提交档案。
> - 当前人格注入仅在“本次保存问卷事件”触发；启动链路没有“自动读取最近有效 profile 并注入”步骤。
> - 因此跨端打开时无法自动继承同一工作空间的已完备人格种子，表现为回到预设 AI。

## 核心原则

1. **工作空间唯一源**: 同一 Workspace 只允许一个“当前生效人格种子指针”，不得由端内本地草稿决定运行态人格。
2. **完备优先且强约束**: 当人格种子“存在且完备”时，初始化链路必须加载它，禁止静默回退预设 AI。
3. **端无关一致性**: 桌面、浏览器、移动端在同一工作空间必须解析同一人格种子指针，行为一致。
4. **草稿与权威分离**: `localStorage` 草稿仅用于填写体验，不可作为运行时人格权威来源。
5. **可审计可诊断**: 每次启动需可追踪“命中的 seed 指针、校验结果、注入结果、是否阻断预设回退”。

**验证检查清单**:
- [x] 工作空间级“当前人格种子指针”有明确存储位置与读写契约
- [x] 定义并落地“人格种子完备性”判定（schema、关键字段、分数结构）
- [x] 启动时自动解析并加载当前种子（App/Web/Mobile 三端一致）
- [ ] 命中完备种子时，不再加载预设 AI 提示词（禁止静默回退）
- [ ] 种子缺失/不完备时，有明确降级策略与可见系统提示
- [x] 问卷提交后会更新工作空间级指针，下一次任一端启动自动生效
- [ ] 导出/日志可回放每次人格加载决策链路

## 现状快照 (2026-03-03)

1. **已提交数据落盘存在**: 问卷提交会写入 `/data/private/*_ipip120_sample_*.json` 与 `*_persona_profile_*.json`。
2. **运行态加载缺失**: 启动链路未自动读取“最近有效 profile”并注入；当前只在保存事件内触发一次注入重载。
3. **跨端一致性缺失**: 面板加载依赖端内 `localStorage` 草稿，跨端天然不一致。
4. **策略冲突**: 与“工作空间唯一主 AI / 唯一种子源”设计目标不一致，需要提升为工作空间级协议。

## 🟢 近期计划

- [ ] **Phase 1: 工作空间级人格种子指针协议冻结 (P0)**
  - **背景**: 当前缺少“当前生效 seed”单一权威索引，导致端间各自为政。
  - **行动**:
    1. 定义工作空间级指针结构（示例：`activeProfilePath`, `updatedAt`, `version`, `subjectId`）。
    2. 定义指针写入时机：问卷提交成功后原子更新。
    3. 定义读取优先级：启动先读指针，再读 profile，再判定完备性。
  - **验收标准**: 指针协议文档化，可直接映射到实现接口与测试用例。
  - **参考文件**: `app/src/magi/entry/persona-seed-panel/PersonaSeedPanel.utils.ts`、`app/src/magi/entry/MagiRoot.ctx.ts`

- [ ] **Phase 2: 完备性判定与禁回退策略冻结 (P0)**
  - **背景**: “存在但无效/半残 profile”与“完整 profile”需分流，否则会误回退到预设 AI。
  - **行动**:
    1. 明确完备性规则（`schemaVersion`、`subject`、`personaBase.traits`、`personaBase.facets`、边界值）。
    2. 明确策略矩阵：
       - 完备：必须加载，禁止预设回退
       - 不完备：可降级，但必须有显式告警与诊断信息
       - 缺失：走引导采样流程
    3. 定义失败语义：禁止“静默回退”为预设人格。
  - **验收标准**: 形成状态机与错误语义表，三端行为一致。
  - **参考文件**: `app/src/magi/prompts/personaRuntimePromptBuilder.ts`、`app/src/magi/prompts/personaRuntimePromptBuilder.guard.ts`

- [ ] **Phase 3: 启动链路跨端统一加载方案冻结 (P1)**
  - **背景**: 当前 `bootstrapMagiState -> useMagi()` 未接入工作空间人格种子自动消费。
  - **行动**:
    1. 定义启动时序：`resolveActiveSeed -> validateProfile -> buildPromptInjections -> initializeMAGI`。
    2. 定义首帧策略：加载中状态、失败可视化、是否允许用户继续发送消息。
    3. 定义 Web/Mobile 与 Desktop 的统一内核 API 调用路径和超时策略。
  - **验收标准**: 冷启动时序图与接口清单完整，能直接进入实施。
  - **参考文件**: `app/src/magi/entry/MagiRoot.ctx.ts`、`app/src/magi/composables/useMagi.ts`

- [ ] **Phase 4: 问卷面板数据源分责调整方案冻结 (P1)**
  - **背景**: 面板当前默认读取 `localStorage` 草稿，会误导为“已加载工作空间权威人格”。
  - **行动**:
    1. 保留草稿用于编辑恢复，但新增“当前生效人格来源”展示与只读回填。
    2. 定义“草稿/已提交/当前生效”三态文案和交互边界。
    3. 约定切换 subjectId 时是否允许覆盖 active seed。
  - **验收标准**: 面板状态语义清晰，不再与运行态人格来源混淆。
  - **参考文件**: `app/src/magi/entry/persona-seed-panel/PersonaSeedPanel.draft.ts`、`app/src/magi/entry/persona-seed-panel/PersonaSeedPanel.ctx.ts`

- [ ] **Phase 5: 跨端回归与审计计划冻结 (P1)**
  - **背景**: 该问题本质是“跨端同源 + 启动一致性”，必须有专项测试矩阵。
  - **行动**:
    1. 制定三端回归矩阵（Desktop/Web/Mobile × 完备/不完备/缺失种子）。
    2. 增加加载决策日志字段（指针路径、校验结论、注入是否成功、是否触发降级）。
    3. 约定验收数据集与最小自动化覆盖。
  - **验收标准**: 可重复验证“同工作空间同人格种子同加载结果”。
  - **参考文件**: `app/src/magi/composables/useMagi.export.ts`、`docs/调研/MAGI问卷系统现状调研.md`

## 🟡 中期计划

- [ ] **Phase 6: 人格种子版本治理与回滚 (P2)**
  - **背景**: 单一 active 指针需要版本化，避免损坏版本污染全部端。
  - **行动**:
    1. 增加 seed 版本链与最近稳定版本回滚策略。
    2. 提供“强制切换 active profile”运维入口。
  - **验收标准**: 误写或损坏场景下可快速恢复，不影响三端一致性。

- [ ] **Phase 7: 启动性能与缓存优化 (P2)**
  - **背景**: 启动时新增 profile 解析与提示词构建，可能增加首屏时延。
  - **行动**:
    1. 评估 prompt injection 缓存键（按 profile hash）。
    2. 评估并行读取与惰性构建边界。
  - **验收标准**: 在不破坏一致性的前提下降低冷启动延迟。

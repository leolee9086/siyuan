# S-Forge 原生 Agent Forge 模式执行跟踪 (TikTocTak)

> **目标**: 在 `forge` 模式下为继承自上游的原生 AI Agent 提供受边界保护的源码仓库浏览、创建、删除、修改、搜索和 Git 原子提交能力；普通模式不暴露源码工具，且不改变 `nerv/magi` 的三贤人治理链路。
>
> **流程**: 这是一个滚动更新的执行路线图。
> 1. 从“近期计划”中认领一个任务。
> 2. 完成开发、测试和验证。
> 3. 将其移动到“已归档/已完成”区域。
> 4. 将“中期计划”中的条目提升到“近期计划”。

---

## 核心原则

1. 只有 `forge` 模式可以暴露开发源码仓库工具；生产、开发和普通工作区不获得该工具集。
2. 源码路径必须解析到 S-Forge 仓库根目录内，禁止访问 `.git` 元数据目录和根目录外路径。
3. 原生 agent 的写操作使用用户确认；MAGI 继续使用主导者选举与三贤人治理，二者不得混用。
4. Git 提交必须显式指定本次逻辑变更涉及的文件，禁止宽泛暂存和隐式提交其他改动。
5. 工具结果应包含稳定的相对路径和明确状态，便于 agent 继续推理和恢复任务。

## 近期计划

- [x] **Phase 1: 原生 Agent forge 工具接入 (P0)** [已完成 2026-07-16]
  - **背景**: `nerv/magi` 已具备开发仓库工具，但上游原生 agent 仅能看到工作区/MCP 工具，无法直接操作源码仓库。
  - **行动**: 增加 forge 工具注册、forge 模式工具过滤、源码根目录提示、文件 CRUD、批量替换和安全命令入口。
  - **验收标准**: forge 模式工具可见且可执行，普通模式不可见，路径边界测试通过。

- [x] **Phase 2: 原生 Agent 与 MAGI 边界回归 (P1)** [已完成 2026-07-16]
  - **背景**: 两套 agent 的确认与治理语义不同，接入后必须防止权限模型串线。
  - **行动**: 覆盖原生 agent 用户确认、MAGI 三贤人治理、工具来源标记和工具列表过滤。
  - **验收标准**: 原生 agent 不触发 MAGI 治理，MAGI 不退化为普通 agent 的确认流程。

- [x] **Phase 3: Git 原子提交约束 (P0)** [已完成 2026-07-16]
  - **背景**: forge agent 可以修改源码，提交时必须避免把无关改动混入同一条记录。
  - **行动**: 增加显式路径提交工具，拒绝 `git add .`、`git commit -a` 和无路径 `git commit`。
  - **验收标准**: 合法提交只包含指定路径，非原子命令返回可执行的替代提示。

## 如何维护此文档

1. **完成归档**：任务满足验收标准后，剪切到“已归档/已完成”，标记 `[x]` 并添加完成日期。
2. **补充弹药**：近期计划少于 3 个任务时，从中期计划提升可执行任务。
3. **因地制宜**：发现计划不合理时记录原因并调整，不保留无法验收的模糊任务。
4. **数据驱动**：同步记录测试结果、受影响文件和原子化提交信息。

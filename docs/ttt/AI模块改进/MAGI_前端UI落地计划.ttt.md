## 📋 核心原则

### 问题定义

### 问题定义

原有的前端验证代码段 (`toread/MAGI/*.vue`) 使用了 Vue 3，由于当前 Siyuan 分支的 UI 层面已经引入并使用了 Vue，这意味着我们可以很大程度上复用现有的代码结构。因此，这不仅是**视觉资产提取**，更是一次**Vue 组件库的集成与架构融合**。我们需要完整保留其独特的**EVA美学（高对比霓虹色、非对称网格、SVG裁切面板、扫描线动画）**，同时将其优雅地装载入 Siyuan 的面板/对话框体系中。

### 架构决策

**已确定方案：复用 Vue 3 组件生态，彻底分离 UI 展现与底层 SSE 逻辑**

**决策理由**:
1. **直接集成**: 既然当前分支已经启用了 Vue，我们可以直接迁移原有的 `.vue` 单文件组件（`SeelPanel.vue`, `MagiMainPanel.vue` 等），这将极大地节省重构 DOM 结构和 SVG 动画的时间，并确保 100% 的视觉渲染一致性。
2. **状态驱动 (Store/State)**: 抛弃原来在页面组件中堆砌网络请求和超时控制的做法。在 `app/src/util` 或专门的 `app/src/magi` 专属目录下封装专门的 `MagiClient`，负责处理与后端 WebSocket/SSE 接口的通信，并将状态同步至全局 Store。UI 纯粹作为状态的观察者 (Observer)。
3. **视觉保真**: 原版中大量的 CSS 魔法（`linear-gradient`, `stroke-dasharray`, `@keyframes scanline`, 自定义字体 `EVA-Matisse`）必须原封不动地迁移到 Siyuan 的主题/全局样式表中。

### 验收检查清单

- [ ] 视觉与原 `toread/MAGI` 严格对齐，支持明暗主题动态适配（或者强制固定暗调以保持 EVA 风格）。
- [ ] 左侧三贤人面板（Melchior, Balthazar, Casper）和中央的 Trinity 统合面板布局正确。
- [ ] 完美支持后端传来的 Stream（流式）打字机效果输出。
- [ ] 动画性能不出现严重衰退（特别是全局扫描线和 SVG 指示灯）。

# MAGI 通用 Diff 模块选型与落地执行跟踪 (TikTocTak)

> **目标**: 实现一个可复用、可配置、可在 MAGI 与其它前端场景复用的通用 Diff 模块（文本/代码优先），支持在“建议查看”场景展示差异，并保留后续扩展能力（只读编辑器、行内高亮、分栏对比、最小化渲染）。
>
> **范围边界 (2026-03-02)**:
> 1. 本任务仅实现前端通用 Diff 能力与接线，不改 MAGI 回答链路。
> 2. 可以引入新依赖（`CodeMirror`/`Monaco`/其它），但必须先走选型评审门禁。
> 3. 第一阶段优先支持 PersonaSeed 建议对比（当前文本 vs 建议文本），再抽象为通用组件。
> 4. 选型已确认：首阶段仅允许算法层依赖，渲染层自行实现并保留适配器扩展能力。
>

## 核心原则

1. **先抽象接口，再选依赖**: 避免先绑定具体编辑器导致后续迁移成本过高。
2. **依赖引入必须有证据**: 体积、性能、交互能力、维护成本必须量化。
3. **默认可降级**: 即使编辑器能力不可用，也要有纯文本 diff 兜底展示。
4. **可复用优先于一次性实现**: 模块必须可被 PersonaSeed 之外场景复用。
5. **移动端可用**: `magi-mobile` 必须可运行，不能只在 desktop 成立。

---

## 依赖决策门禁（强制）

1. **任何新依赖在安装前必须先提交“选型说明”并与你详细讨论**。
2. 选型说明至少包含：
   1. 候选项清单（例如 `CodeMirror`、`Monaco`、`diff-match-patch`、其它）。
   2. 能力对比（分栏/行内、语法高亮、编辑/只读、主题适配、API 复杂度）。
   3. 工程影响（包体积、懒加载策略、构建兼容性、移动端性能）。
   4. 许可证与维护状态（license、活跃度、版本稳定性）。
   5. 与当前项目技术栈适配风险（Vue 3 + webpack + magi-mobile）。
3. **未得到你明确确认，不执行依赖安装或代码接入**。
4. 每次依赖决策结果需记录到本 ttt 的“执行记录”与“依赖决策日志”。

## 🟢 近期计划

- [x] **Phase 0: 需求冻结与接口草案 (P0, 已完成)**
  - **背景**: 若直接开始写组件，容易和特定编辑器 API 绑定。
  - **行动**:
    1. 冻结首版场景：PersonaSeed 建议 diff 展示。
    2. 定义 `DiffModel`（old/new/chunks/metadata）与渲染模式接口。
    3. 明确最小能力：行级高亮、字段级标题、只读展示、滚动容器适配。
  - **验收标准**: 接口草案评审通过，可独立于具体依赖实现。

- [x] **Phase 1: 依赖选型评审 (P0, 门禁阶段, 已完成)**
  - **背景**: 允许引入依赖，但必须先给理由并与你详细讨论。
  - **行动**:
    1. 输出候选对比表（CodeMirror/Monaco/其它）。
    2. 提供推荐方案与拒绝方案理由。
    3. 等待你确认最终方案（或要求无新依赖）。
  - **验收标准**: 你明确批准后才进入实现阶段。

- [x] **Phase 2: 通用 Diff 内核与适配层 (P0, 已完成)**
  - **背景**: 需要把“差异生成”与“UI 渲染”解耦。
  - **行动**:
    1. 实现通用差异模型转换层（支持纯文本兜底）。
    2. 设计 `adapter` 接口（可挂编辑器实现，也可挂轻量实现）。
    3. 输出统一渲染数据给组件层。
  - **验收标准**: 不依赖 UI 也可得到稳定 diff 数据结构。

- [x] **Phase 3: 通用 Diff 组件落地 (P0, 已完成)**
  - **背景**: 需要可复用组件，不只服务 PersonaSeed。
  - **行动**:
    1. 新建 `DiffViewer` 组件（建议单独目录）。
    2. 支持至少两种视图：`inline` 与 `split`（可先实现其中一个并预留接口）。
    3. 支持主题与状态样式（新增/删除/修改/未变）。
  - **验收标准**: 组件可在独立 demo 或现有面板中可视化运行。

- [ ] **Phase 4: PersonaSeed 场景接线 (P0, 进行中)**
  - **背景**: 当前“查看建议”只有摘要文本，缺少差异可视化。
  - **行动**:
    1. 在建议列表“查看”流程增加 diff 展示区域（已完成：描述建议）。
    2. 问卷分值建议展示“当前分值 vs 建议分值”差异卡片（待完成）。
    3. 描述建议展示“原文 vs 原文+建议追加段”差异视图（已完成）。
  - **验收标准**: 用户可直观看到变更内容，再决定接受/拒绝。

- [x] **Phase 5: 测试与回归 (P0, 已完成)**
  - **背景**: diff 显示属于高频交互，回归风险高。
  - **行动**:
    1. 单测：差异模型生成、边界输入、空文本/超长文本。
    2. 组件测试：状态渲染、切换模式、降级显示。
    3. 构建验证：`magi-mobile` 与目标入口构建通过。
  - **验收标准**: 测试通过，核心路径可复现可回归。

## 🟡 中期计划

- [ ] **Phase 6: 性能优化与虚拟化 (P1)**
  - **背景**: 大文本 diff 可能导致渲染抖动与内存压力。
  - **行动**:
    1. 增加按需渲染/虚拟列表策略。
    2. 为超长文本提供折叠与懒展开。
  - **验收标准**: 大文本场景滚动与交互可接受。

- [ ] **Phase 7: 跨模块复用落地 (P1)**
  - **背景**: 通用模块需要在 MAGI 外场景验证复用价值。
  - **行动**:
    1. 在至少一个非 PersonaSeed 场景复用。
    2. 补充模块 README 与接入示例。
  - **验收标准**: 复用方接入成本可控，接口稳定。

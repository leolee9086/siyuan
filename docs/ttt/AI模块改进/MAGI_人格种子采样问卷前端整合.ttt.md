# MAGI 人格种子采样问卷前端整合 (TTT)

> **目标**: 将 IPIP-NEO-120 大五人格问卷（以及配套的自然语言自述功能）整合为 s-forge 前端的一个独立面板组件，输出标准 JSON 格式的采样数据，作为 MAGI 人格种子（Persona Seed）的 $P_{ref}$ 基线输入。
>
> **参考原型**: `toread/MAGI/core/nerv.js`（NERV人格容器）、`toread/MAGI/core/wise/index.js`（三贤人实现）
>
> **数据格式定义**: `test_data/private/zhi_ipip120_sample_2.json`（已定型）
>
> **设计文档**: `docs/设计/大五人格标测问卷(IPIP-NEO-120).design.md`、`docs/设计/MAGI_人格种子生成机制.design.md`

---

## 1. 背景与设计意图

原版 MAGI（`toread/MAGI`）中，问卷题库以三贤人专属切面的形式存在（`questionnaire-sections/melchior.js` 等），配套了复杂的投票选拔机制。新版砍掉投票制，同步将问卷的使用场景从"辅助决策"转向**人格基线采样**，有两个用途：

1. **$P_{ref}$ 基线生成**（裸模型/AI主体自评）：作为 ATF 系统的外部参考矩阵，供同步率 $\rho$ 的外部一致性 $C_{ext}$ 计算使用
2. **初始种子赋值**（用户手动为AI角色配置特质）：人工为新角色跑一遍问卷，替代冷启动时的随机初始化

**补偿设计**：自然语言自述文本（见 `test_data/private/zhi_as_Engineer.md` 等）与结构化问卷数据互相矫正，两者共同构成更可靠的侧写起点。面板需要同时支持两种输入。

## 2. 前端组件设计

### 2.1 组件定位

参考 `SeelPanel.vue` 的面板风格，新建 **`PersonaSeedPanel.vue`**（或接入现有面板路由），作为独立的"人格采样"入口。

### 2.2 问卷交互模式

提供两种填写模式，用户可切换：

**模式 A：逐题流模式（推荐）**
- 每屏显示一道题 + 5 级评分滑块/按钮（1~5）
- 题目下方显示对应的维度标签（如"N · 焦虑"）和题序（如"12/120"）
- 支持手势左/右滑动跳题，或左下角"上一题"按钮
- 防止顺序偏差：可选"乱序模式"（打乱 120 道题的展示顺序，但 q 字段记录原始题号，计算不受影响）

**模式 B：维度分组模式**
- 按五大维度（N/E/O/A/C）分 5 个 Tab，每 Tab 24 道题一页滚动
- 适合想要集中处理某个维度的场景

### 2.3 进度持久化

- 答题数据每题完成后**立即写入 localStorage**（key: `magi_questionnaire_draft_<subjectId>`）
- 关闭面板后重新打开，自动恢复进度，跳转到上次作答位置
- 完成率显示在顶部进度条（120 道题中已答 N 道）

### 2.4 自述文本输入

在问卷完成页面（或单独的 Tab）提供三个文本域，对应三个侧面自述文件：

| 标签 | 对应文件 | 引导文字 |
|------|----------|----------|
| 工程师侧面 | `zhi_as_Engineer.md` | "描述你在完成技术任务时的思考和行为习惯..." |
| 陪伴侧面 | `zhi_as_Sister.md` | "描述你在关系和情感层面的特质..." |
| 自我核心 | `zhi_as_Zhi.md` | "描述最接近你自己的那个样子..." |

文本域字数建议 200~600 字，显示当前字数。

### 2.5 双向收敛迭代与基线锁定

问卷和自述文本不是两个独立的一次性输入，而是**互相约束、可以反复迭代**的双向过程。在基线锁定之前，用户可以自由在两者之间来回修改。

**迭代流程**：

```
[问卷答案] ──LLM生成──→ [侧面自述文本]
     ↑                         │
     └────LLM推断建议答案────────┘
           (用户确认/修改)
```

- **问卷 → 描述**：完成问卷（或部分完成）后，点击"生成描述"，LLM 根据当前问卷分数的维度分布，生成三个侧面自述草稿，用户可直接编辑
- **描述 → 问卷**：写完自然语言描述后，点击"推断问卷"，LLM 分析文字风格与内容倾向，对 120 道题给出**建议分数**，以叠加高亮形式显示在问卷 UI 上，用户逐题确认或覆盖
- 两个方向可**交替多次**，没有顺序限制，直到数字与文字互相对齐

**基线锁定机制**（Phase 3 实现，当前先做 UI 预留）：

- 当 MAGI 后端反馈同步率 $\rho$ 换算置信度 > 60%，前端将问卷和自述切换为**只读模式**，显示"基线已锁定"提示
- 如需修改，监护人在设置中手动触发"解锁基线"，解锁后可编辑，保存后重新触发置信度计算
- Phase 1/2 阶段后端未就绪时，前端始终保持可编辑，仅预留锁定状态的 UI 显示区域

## 3. 数据格式与输出

### 3.1 JSON 输出格式

严格遵循已定型的 schema，不加入任何计算字段（traits/facets 由后端程序计算）：

```json
{
  "schema_version": "IPIP-NEO-120-v1",
  "subject": {
    "id": "<subject_id>",
    "name": "<展示名>",
    "type": "human | ai_agent"
  },
  "date": "YYYY-MM-DD",
  "answers": [
    { "q": 1,   "text": "杞人忧天", "score": 4 },
    { "q": 2,   "text": "平易近人", "score": 4 },
    ...
    { "q": 120, "text": "做事果断干脆", "score": 4 }
  ]
}
```

### 3.2 文件存储

- **存储位置**: `/data/private/` 目录，通过 Siyuan 内核 API 写文件
- **命名规则**: `<subject_id>_ipip120_sample_<N>.json`，N 为递增序号（支持多次采样对比）
- **自述文件**: `<subject_id>_as_<侧面>.md`，同目录

> ⚠️ `/data/private/` 目录中的内容跟/data/public中的相反,只能鉴权后查看

### 3.3 题目数据源与场景化扩展

题目元数据（q/text/domain/facet/keyed）硬编码在前端 JS 模块中，不依赖网络请求：

```js
export const 题目列表 = [
  { q: 1,   text: "杞人忧天", domain: "N", facet: 1, keyed: "plus" },
  { q: 2,   text: "平易近人", domain: "E", facet: 1, keyed: "plus" },
  // ...
]
```

**关键设计：`text` 是语义关键词，不是固定题干。**

`text` 字段存储的是题目的语义核心（如"杞人忧天"），在前端直接展示时可以作为题目文字使用，但它的更大价值在于提供给 LLM 作为生成场景化题干的依据：

- **前端问卷**：直接使用 `text` 字段展示，简洁直接
- **Seraph 四盲测试**：Seraph 调用 LLM，以 `text` + `domain` + `facet` 为输入，实时生成不同的情境化提问。例如 `text: "杞人忧天"` → "开始一个新项目时，你是否会在脑子里反复演练可能的最坏情况？"

这样每次 Seraph 给三贤人和 Trinity 发放的测验题都是**现生成的新场景**，而不是固定文字——被评估方无法靠记住上次答案来应答，测量更接近真实人格而非记忆。

场景化题干的生成由 Seraph 在 `monitor/observer.go` 中实现（参见后端 TTT），前端只需保证题目元数据完整输出到 JSON 文件中，后端读取后自行处理。

## 4. 落地实施路线图

### Phase 1：题库模块与基础 UI

**目标**: 完成题目数据和最简可用的问卷界面。

- **1.1** 将 120 道题目（text/domain/facet/keyed）整理成独立 JS 数据模块（`questionnaire-ipip120.js`），放在前端数据目录，不依赖外部接口
- **1.2** 实现 `PersonaSeedPanel.vue`，接入逐题流模式（模式 A）：题目展示、5 级评分按钮、前进/后退导航
- **1.3** 实现 localStorage 进度持久化，覆盖刷新/关闭场景
- **验证**: 手动从第 1 题做到第 10 题，关闭面板重新打开，确认恢复到第 11 题；确认乱序模式下 `q` 字段记录原始题号

### Phase 2：完成与导出

**目标**: 120 道题全部作答后能生成并存储标准 JSON。

- **2.1** 实现完成检测（120 道全有答案），显示"完成"按钮
- **2.2** 点击完成后弹出 subject 信息填写弹窗（id、name、type），填完后组装 JSON 并通过 Siyuan 内核 `/api/file/putFile` 接口写到 `test_data/private/`
- **2.3** 在完成页增加自述文本输入区域（三个文本域，可跳过），填写后同样通过文件 API 保存 `.md` 文件
- **2.4** 实现历史采样列表：列出 `test_data/private/` 下所有 `*_ipip120_sample_*.json`，支持点击查看
- **验证**: 完整走一遍问卷，确认 JSON 文件格式合规（符合 schema）；填写自述文本后确认 `.md` 文件创建成功

### Phase 3：维度分组模式与多样性增强

**目标**: 完善可用性，支持更灵活的采样场景。

- **3.1** 实现维度分组模式（模式 B），5 个 Tab 按 domain 分类展示
- **3.2** 实现乱序模式开关（可在设置里控制）
- **3.3** 在历史采样列表中加入简易的维度雷达图预览（纯前端计算，不依赖 MAGI 后端），让用户能直观看出不同采样的大五分布
- **3.4** 支持"对比视图"：选择两份采样 JSON，并排展示各维度得分差异（对应同步率分析的前驱可视化）

## 5. 与 MAGI 后端的对接预留

本 TTT 的范围是前端 UI 和数据存储，不实现 P 矩阵计算。后续 MAGI 后端（参见 `MAGI_后端核心引擎落地.ttt.md`）需要：

- 读取 `test_data/private/*_ipip120_sample_*.json`，按照 `大五人格标测问卷(IPIP-NEO-120).design.md` 中的计分标准计算各 facet 均值，映射到 $[-1, 1]$ 区间，初始化 $P_{ref}$ 矩阵
- 读取对应的 `.md` 自述文件，在生成三贤人侧写 Prompt 时作为自然语言基底输入（补偿问卷的认知盲区）

前端写文件路径和文件名格式是后端读取的约定，**双方格式必须对齐，不得单方面修改 schema**。

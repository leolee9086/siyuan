# MAGI 详细记录导出执行跟踪 (TikTocTak)

> **目标**: 为 MAGI 增加可审计的“详细记录导出”能力，支持导出完整会话轨迹（输入、三贤人响应、Trinity 综合、审慎决策、投票细节、降级与错误路径、人格注入信息、时间线与耗时）。量化指标：单次会话导出耗时 < 300ms（本地），导出结构具备稳定 schema，可用于复盘、调试与外部归档。

## 核心原则

1. **审计优先**: 导出内容必须覆盖“为何这样决策”的链路证据，而不只是最终回复文本。
2. **结构稳定**: 导出采用版本化 schema（`schemaVersion`），确保后续工具可兼容解析。
3. **最小侵入**: 优先复用 `consensusMessages/meta` 与现有共识流程，不重写主链路。
4. **可脱敏**: 导出前支持敏感字段剔除（如内部配置、潜在凭据、高风险原始上下文）。
5. **可复现**: 导出包应包含时间线与关键状态，支持“离线复盘一次决策轮次”。

**验证检查清单**:
- [x] 可导出单次会话完整记录（JSON）
- [x] 记录包含三贤人响应、Trinity 输出、投票细节与通过/否决结果
- [x] 记录包含关键决策路径（是否进入审慎模式、提案内容、降级原因）
- [x] 记录包含人格注入上下文（profile 路径、注入摘要/指纹，不强制全文）
- [x] 记录包含阶段时间戳与耗时统计
- [x] 导出支持“脱敏模式”
- [ ] 导出文件可在 UI 重新加载并查看（至少基础文本视图）
- [ ] 最小回归通过（单测 + 手工联调）

## 现状评估 (2026-03-03)

1. **已有记录基础**: 当前 `consensusMessages` 已含用户消息、共识消息、投票状态 `meta`、错误消息，可作为导出主数据源。
2. **核心缺口**: 缺少统一“会话导出模型”，无法稳定表达“轮次/决策因果/耗时”。
3. **关键缺口**: 缺少显式导出入口（UI 按钮或命令）及导出落盘策略。
4. **复盘缺口**: 当前日志更偏显示，不是严格审计结构，外部工具二次消费成本高。

## 🟢 近期计划

- [ ] **Phase 5: 查看与复盘最小闭环 (P1)**
  - **背景**: 仅导出不查看会降低可用性。
  - **行动**:

    3. 增加导出文件版本不兼容提示。
  - **验收标准**: 用户可在 UI 内查看导出内容并定位到关键决策轮次。

## 🟡 中期计划

- [ ] **Phase 6: 导出格式扩展 (P2)**
  - **背景**: JSON 适合机器消费，但人工阅读成本较高。
  - **行动**:
    1. 增加 Markdown 导出模板（按轮次生成复盘报告）。
    2. 评估 JSONL 增量导出（长会话场景）。
  - **验收标准**: 至少支持 JSON + Markdown 两种导出格式。

- [ ] **Phase 7: 远程诊断对接 (P2)**
  - **背景**: 后续可能需与后端诊断 API 联动。
  - **行动**:
    1. 对接 `API_内置日志暴露_诊断链路优化` 产物，支持导出包附带内核日志片段引用。
    2. 保持“引用优先”，避免导出包过大。
  - **验收标准**: 可在导出中定位到关联内核日志窗口。

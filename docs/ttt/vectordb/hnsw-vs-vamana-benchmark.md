## 关键发现

### Phase 6 基线发现 (保留)

1. **Vamana 逐条插入快于 HNSW ~1.47x** — HNSW 200/s vs Vamana 294/s
2. **HNSW 和 Vamana 衰减趋势一致** — 末/首比均约 0.60（衰减~40%）
3. **DiskVamana 逐条插入显著慢** — 89/s，约为内存 Vamana 的 30%
4. **DiskVamana 衰减极低** — 末/首比 0.89（仅衰减 11%）
5. **多线程批量构建性能接近** — Vamana Build-MT 3,209/s ≈ DiskVamana Build 3,155/s

### Phase 7 松弛因子优化发现

1. **HNSW Insert 吞吐量提升 59%** — 200/s → 318/s，松弛因子 1.3 显著减少了双向连接维护中的不必要裁剪操作
2. **HNSW 首阶段吞吐量提升 91%** — 297/s → 568/s，小图阶段提升最为显著
3. **HNSW 已反超 Vamana Insert** — Phase 6 中 HNSW 落后 Vamana 47%，Phase 7 中 HNSW 318/s 反超 Vamana 259/s（快 23%）
4. **Vamana 各指标略有下降 (~10%)** — 属于正常测试波动范围，Vamana 代码未变更
5. **HNSW 衰减加剧** — 末/首比从 0.59 降至 0.45（衰减 55%），因首阶段提升幅度远大于末阶段
6. **松弛因子优化仅影响 HNSW** — 其他索引类型数据变化在正常波动范围内

### Phase 8 距离计算8路展开优化发现

1. **HNSW Insert 总体吞吐量小幅提升 5%** — 318/s → 333/s，距离计算优化对全流程的边际收益有限
2. **HNSW 首阶段吞吐量提升 3%** — 568/s → 586/s，首阶段提升幅度较小
3. **HNSW 末阶段吞吐量提升 6%** — 254/s → 270/s，末阶段提升略高于首阶段
4. **全索引类型均有小幅提升** — Vamana Insert 259→273/s (+5%)，Vamana Build-1T 446→482/s (+8%)，多线程 Build-MT 3,027→3,351/s (+11%)，DiskVamana Build 2,917→3,384/s (+16%)
5. **距离计算优化是全局性的** — 所有使用欧氏距离的索引均受益，说明8路展开确实加速了距离计算
6. **HNSW 衰减基本不变** — 末/首比 0.46 vs Phase 7 的 0.45，距离计算优化不影响衰减特征
7. **累计优化效果：Phase 6→Phase 8 HNSW Insert +67%** — 200/s → 333/s

## 结论

### Phase 8 最新状态 (距离计算8路展开 + GraphSlackFactor=1.3)

| 维度 | HNSW | Vamana (内存) | DiskVamana |
|------|------|--------------|------------|
| 逐条插入吞吐量 | ✅ **最快 (333/s)** | 较快 (273/s) | ⚠️ 最慢 (85/s) |
| vs Phase 6 | **+67%** (200→333) | -7% (294→273) | -4% (89→85) |
| vs Phase 7 | **+5%** (318→333) | +5% (259→273) | +1% (84→85) |
| 吞吐量衰减 | ⚠️ 明显 (0.46) | ⚠️ 明显 (0.62) | ✅ 极低 (0.93) |
| 单线程批量构建 | N/A | ✅ 482/s | N/A |
| 多线程批量构建 | N/A | ✅ 3,351/s | ✅ 3,384/s |

### Phase 8 优化总结

距离计算8路循环展开使所有索引类型均获得小幅提升。HNSW Insert 总体吞吐量从 **318 items/s 提升至 333 items/s (+5%)**，累计从 Phase 6 的 200 items/s 提升 **+67%**。多线程场景提升更明显：Vamana Build-MT +11% (3,027→3,351/s)，DiskVamana Build +16% (2,917→3,384/s)。距离计算优化是全局性的底层优化，对所有使用欧氏距离的索引均有效。

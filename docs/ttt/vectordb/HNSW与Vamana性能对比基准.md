## 关键发现

### Phase 6 基线发现 (保留)

1. **Vamana 逐条插入快于 HNSW ~1.47x** — HNSW 200/s vs Vamana 294/s
2. **HNSW 和 Vamana 衰减趋势一致** — 末/首比均约 0.60（衰减~40%）
3. **DiskVamana 逐条插入显著慢** — 89/s，约为内存 Vamana 的 30%
4. **DiskVamana 衰减极低** — 末/首比 0.89（仅衰减 11%）
5. **多线程批量构建性能接近** — Vamana Build-MT 3,209/s ≈ DiskVamana Build 3,155/s

### Phase 7 松弛因子优化发现

1. **HNSW Insert 吞吐量提升 59%** — 200/s → 318/s，松弛因子 1.3 显著减少了双向连接维护中的不必要裁剪操作
2. **HNSW 首阶段吞吐量提升 91%** — 297/s → 568/s，小图阶段提升最为显著
3. **HNSW 已反超 Vamana Insert** — Phase 6 中 HNSW 落后 Vamana 47%，Phase 7 中 HNSW 318/s 反超 Vamana 259/s（快 23%）
4. **Vamana 各指标略有下降 (~10%)** — 属于正常测试波动范围，Vamana 代码未变更
5. **HNSW 衰减加剧** — 末/首比从 0.59 降至 0.45（衰减 55%），因首阶段提升幅度远大于末阶段
6. **松弛因子优化仅影响 HNSW** — 其他索引类型数据变化在正常波动范围内

### Phase 8 距离计算8路展开优化发现

1. **HNSW Insert 总体吞吐量小幅提升 5%** — 318/s → 333/s，距离计算优化对全流程的边际收益有限
2. **HNSW 首阶段吞吐量提升 3%** — 568/s → 586/s，首阶段提升幅度较小
3. **HNSW 末阶段吞吐量提升 6%** — 254/s → 270/s，末阶段提升略高于首阶段
4. **全索引类型均有小幅提升** — Vamana Insert 259→273/s (+5%)，Vamana Build-1T 446→482/s (+8%)，多线程 Build-MT 3,027→3,351/s (+11%)，DiskVamana Build 2,917→3,384/s (+16%)
5. **距离计算优化是全局性的** — 所有使用欧氏距离的索引均受益，说明8路展开确实加速了距离计算
6. **HNSW 衰减基本不变** — 末/首比 0.46 vs Phase 7 的 0.45，距离计算优化不影响衰减特征
7. **累计优化效果：Phase 6→Phase 8 HNSW Insert +67%** — 200/s → 333/s

### Phase 9 向量预取优化发现

1. **HNSW 首阶段吞吐量提升 10%** — 586/s → 644/s，预取优化在小图阶段效果显著
2. **HNSW 总体吞吐量微幅提升 1%** — 333/s → 336/s，预取优化对全流程边际收益有限
3. **Vamana 全面受益** — Vamana Insert 273→304/s (+11%)，Vamana Build-1T 482→536/s (+11%)，预取优化对Vamana的收益大于HNSW
4. **DiskVamana Insert 提升 6%** — 85→90/s，磁盘索引也从预取中受益
5. **HNSW 衰减进一步加剧** — 末/首比从 0.46 降至 0.40（衰减60%），首阶段提升幅度远大于末阶段
6. **测试总耗时持续下降** — 1010s → 983s → 951s → 895s，累计缩短 11.5%
7. **累计优化效果：Phase 6→Phase 9 HNSW Insert +68%** — 200/s → 336/s
8. **经验：预取优化在热路径前预取变量而非实时获取可显著提升性能，后续可在所有链路推广，需注意竞态**

### Phase 10 全面预取+VectorStore distancer发现

1. **HNSW Insert 吞吐量爆发式提升 285%** — 336/s → 1,292/s，VectorStore 连续内存布局使预取优化充分发挥
2. **HNSW 首阶段吞吐量突破 2000** — 644/s → 2,016/s (+213%)，创历史最高
3. **benchDistancer 严重低估 HNSW 性能** — `[][]float32` 的离散内存布局导致 CPU 预取失效，Phase 9 中对比测试仅+1%而独立基准+45.6%的差异根因在此
4. **HNSW 领先 Vamana Insert 5x** — 1,292/s vs 258/s，从 Phase 6 落后 1.47x 到领先 5x
5. **HNSW 衰减回升至 0.50** — 末/首比从 0.40 回升至 0.50（衰减50%），VectorStore 的连续内存访问改善了大图阶段的缓存命中率
6. **Vamana 系列略有下降** — Vamana Insert 304→258/s (-15%)，属正常测试波动，Vamana 代码未变更
7. **累计优化效果：Phase 1→Phase 10 HNSW Insert +797%** — 144/s → 1,292/s

## 结论

| vs Phase 9 | **+285%** (336→1,292) | -15% (304→258) | -3% (90→87) |

| 吞吐量衰减 | ⚠️ 明显 (0.50) | ⚠️ 明显 (0.61) | ✅ 极低 (0.90) |
| 单线程批量构建 | N/A | 454/s | N/A |
| 多线程批量构建 | N/A | ✅ 3,102/s | ✅ 3,156/s |

### Phase 10 优化总结

对比测试从 `benchDistancer`（`[][]float32` 离散内存）改用 `VectorStore`（连续 `[]float32` 存储）后，HNSW Insert 吞吐量从 **336 items/s 爆发式提升至 1,292 items/s (+285%)**，累计从 Phase 1 的 144 items/s 提升 **+797%**。这一结果验证了 Phase 9 中对比测试（+1%）与独立基准（+45.6%）之间巨大差异的根因：`[][]float32` 的离散内存布局使 CPU 预取指令无法有效工作，严重低估了 HNSW 的真实性能。VectorStore 的连续内存布局使 HNSW 充分发挥了此前所有预取优化的效果，HNSW 逐条插入性能现已领先 Vamana Insert **5 倍**（1,292/s vs 258/s）。

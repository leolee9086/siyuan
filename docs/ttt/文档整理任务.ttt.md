# 文档整理任务执行跟踪 (TikTocTak)

> **目标**: 系统性地整理 [`docs`](../docs) 目录的文档结构，建立清晰的分类体系，将当前混乱的根目录文档（30+个）整理到合理的目录结构中，实现文档查找时间从"不确定位置"降低到"明确分类路径"。
>
> **流程**: 这是一个滚动更新的执行路线图。
> 1. 从"近期计划"中认领一个任务。
> 2. 完成整理和验证。
> 3. 将其移动到"已归档/已完成"区域。
> 4. 将"中期计划"中的条目提升到"近期计划"。

## ⚠️ 核心原则：保留历史优先

**文档整理的铁律**：
1. **保留历史 > 整洁**：任何文档移动都必须使用 `git mv` 保留历史记录
2. **备份优先**：重要文档移动前必须确认可回滚
3. **引用完整**：移动后必须更新所有文档引用
4. **验证充分**：整理后必须验证链接有效性

**验证检查清单**（每次整理后必须执行）：
- [ ] 使用 `git mv` 移动文档（保留历史）
- [ ] 搜索并更新所有文档引用
- [ ] 验证文档链接有效性
- [ ] 检查目录结构合理性
- [ ] 更新文档索引
- [ ] 提交变更并编写清晰的提交信息

**如果发现问题**：
1. 立即停止整理工作
2. 回滚到上一个稳定状态
3. 分析问题原因
4. 修复问题后重新验证
5. 记录问题和解决方案

## ℹ️ 如何维护此文档

1. **验证优先**：
   - 每次移动文档后，立即验证链接
   - 移动前后必须确认文档内容完整
   - 必须更新所有引用该文档的位置
   - 记录所有整理步骤和结果
2. **完成归档**：任务完成后，**必须**把对应的任务剪切粘贴到最底下的【已归档】列表里，并打上 `[x]` 和日期。
3. **补充弹药**：当【近期计划】空了，就从【中期计划】里挑几个看着顺眼的挪上去。
4. **因地制宜**：如果你发现原来的计划不合理，随时修改或删除，不要死板遵守。
5. **结构驱动**：用清晰的目录结构说话，不凭感觉。

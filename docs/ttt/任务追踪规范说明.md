# TTT (TikTocTak) 任务追踪规范

这是一个用于敏捷开发和任务管理的文档格式规范，特别是为了适应 AI 协作环境。

## 核心理念 (Core Philosophy)
- **滚动更新 (Rolling Update)**: 文档是活的，随着进度不断变化。
- **分级聚焦 (Tiered Focus)**: 区分“现在要做什么”和“将来想做什么”。
- **归档历史 (Archive History)**: 记录已完成的工作，留下足迹。

## 文档结构 (Structure)

### 1. 头部元数据 (Header)
- 标题: `X Project (TikTocTak)`
- 引用块: 简述**目标 (Goal)** 和 **流程 (Process)**。

### 2. 维护指南 (Maintenance Guide)
- 简短说明如何使用此文档，方便新人（或新来的 AI）上手。

### 3. 🟢 近期计划 (Recent Plans)
- **定义**: 立即要做的、具体的、风险低的任务。
- **行动**: 撸起袖子干。
- **格式**:
  ```markdown
  - [ ] **任务名称**
    - **背景**: 为什么要做？
    - **行动**: 具体步骤。
    - **收益**: 预期结果。
  ```

### 4. 🟡 中期计划 (Mid-term Plans)
- **定义**: 需要架构演进、协调多模块的任务。
- **行动**: 步步为营。

### 5. 🔴 远期计划 (Long-term Plans)
- **定义**: 愿景、北极星目标。
- **行动**: 星辰大海。

### 6. 🏁 已归档/已完成 (Archived/Completed)
- **定义**: 完成的任务移动到这里。
- **格式**: `- [x] **任务名称** (日期)`

## 子文档规范 (Sub-TTT)
- 当某个任务过于复杂，需要独立追踪时，创建子文档。
- 命名: `[任务名].shorterm.ttt.md` (如果是短期攻坚)
- 关联: 在父文档的任务项中添加连接 `[详细追踪](./path/to/sub.ttt.md)`。

## 父子文档关联 (Parent-Child Linking)
- **子指向父**: 子文档头部由 `> **归属**: [父文档链接]` 指明。
- **父指向子**: 父文档在对应任务条目中添加 `[详细追踪](./sub.ttt.md)` 链接。

## 生命周期 (Lifecycle)
### 标准 TTT 文档 (`.ttt.md`)
- **长期存活**: 伴随功能模块的整个生命周期。
- **归档机制**: 定期将已完成内容移动到底部归档区，保持文档轻量。

### 短期 TTT 文档 (`.shorterm.ttt.md`)
- **阅后即焚**: 仅用于特定攻坚任务的临时追踪。
- **合并与删除**: 
  1. 任务完成后，将关键结论或成果摘要回写到 **父文档** 的归档条目中。
  2. 确认无误后，**直接删除** 该 `.shorterm.ttt.md` 文件。
  3. 保持仓库整洁，不要留下一堆死去的临时文件。

## 操作规则 (Rules)
1. **认领**: 在任务后签到（如果多 AI/人 协作）。
2. **移动**: 完成后剪切到归档区。
3. **补充**: 近期计划空了，从中/远期计划中提升。

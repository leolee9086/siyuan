## 📋 项目背景

### 现状分析

[kernel](../../kernel) 后端核心向量数据库当前实现：
- **索引结构**: HNSW分层图索引 + BBQ二值量化
- **存储架构**: 纯内存架构，所有向量常驻内存
- **内存占用**: 10万条1024维向量约400-600MB

### 已知问题

1. **内存瓶颈**: 百万级数据内存占用不可接受（预估4-6GB）
2. **纯内存架构**: 无磁盘分层机制，无法扩展
3. **重建成本高**: 删除操作后需重建整个图
4. **并发瓶颈**: Collection级别锁限制高并发

### 核心需求

1. 支持索引的热更新（增量更新，无需全量重建）
2. 保持现有BBQ量化算法（精度优势）
3. 查询/更新时无需加载全部向量到内存
4. 保持前端接口兼容性

### 参考资料

- [Microsoft DiskANN](https://github.com/microsoft/DiskANN) - 官方实现
- [IP-DiskANN](https://github.com/leixy2004/IP-DiskANN) - 内积距离优化版本
- [论文 arXiv:2502.13826](https://arxiv.org/abs/2502.13826) - 最新研究

> 可将参考代码/资料拉取到 `toread/` 目录以供长期参考

## 🎯 核心原则

### 设计原则

1. **磁盘优先**: 原始向量存储在磁盘，仅量化码驻留内存
2. **BBQ继承**: 保持现有BBQ量化算法的精度优势
3. **接口兼容**: 核心内部可变更，上层接口保持稳定
4. **渐进迁移**: 支持从现有HNSW平滑迁移

### 验证检查清单

- [ ] 百万级向量数据集测试通过
- [ ] 内存占用降低90%以上（相比纯内存方案）
- [ ] 召回率≥95%（与现有实现对比）
- [ ] 查询延迟P99 < 10ms
- [ ] 热更新支持（增量插入/删除）
- [ ] 前端接口100%兼容

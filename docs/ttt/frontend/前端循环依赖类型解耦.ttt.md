> **最终目标**：在保留所有 `imports.ts` 网关、业务逻辑和公开行为的前提下，通过细粒度类型契约、参数注入和单向模块职责消除 `app/src` 的全部循环依赖。
>
> **当前目标**：按严格限定为 `app/src` 的 Madge 依赖图，解除 `blockAttr -> transaction` 当前首条返回路径；当前生产图为 `2295` 节点、`299` 条代表环、唯一 SCC `579`，数量只用于定位，不作为单调门禁。
>
> **下一步任务**：枚举 `blockAttr.ts` 的通用事务 action，核对本地属性表 DOM/数据应用与广播刷新语义，复用正确的完整 AV 领域命令。

> **进行中专项**：[AV 定位状态与渲染生命周期拆分](./AV定位状态与渲染生命周期拆分.ttt.md)：消除 `locate.ts` 动态反向加载 AV 根渲染器的最短环，并将七类跨调用状态统一归入 SForge 注册表。
>
> **进行中专项**：[Protyle 上传编排与资源写入职责拆分](./Protyle上传编排与资源写入职责拆分.ttt.md)：分离文件校验/传输、默认 Editor/AV 结果处理和本地路径导入，同时保持显式 callback 与文件夹默认后处理的既有分派语义。
>
> **进行中专项**：[AV 单元格值更新与批量编辑职责拆分](./AV单元格值更新与批量编辑职责拆分.ttt.md)：将目标收集、值变换、列选项同步、操作规划、DOM 呈现和提交从 `updateCellsValue` 上帝函数拆为完整单向命令阶段。

## 不变量

- 不删除、绕开或从 Madge 扫描中排除任何 `imports.ts`。
- 不通过动态导入、字符串模块路径或 lint/构建忽略规则隐藏依赖边。
- 不改变运行逻辑、公开导入语义、事件顺序、错误类型身份或状态生命周期。
- 类型依赖本身不作为问题；契约依赖实现 class 才是抽象层级错误。
- 优先从领域根提取稳定契约，不为单个调用点制造细碎类型；不以 `unknown` 能力槽牺牲静态类型。
- 相同功能保持唯一实现；确有宿主差异时不通过上下文参数强行合并。
- 每消除一个 SCC 后运行相关测试和全图 SCC 检查，确认没有把环迁移到其他组件。
- `pnpm lint:cycles` 的代表环枚举数允许在节点拆分时阶段性反升；撤回只依据目标环仍存在、新增 SCC 或行为/类型回归，不要求枚举总数单调下降。
- `pnpm lint:cycles` 的图严格限定为 `app/src` 诱导子图；工作区包、构建产物、声明包和 `node_modules` 不进入前端源码循环计数。
- 新增测试与测试专用夹具统一位于 `app/test`；`app/src` 只保留生产运行时实现和生产依赖网关。
- 跨调用生命周期状态由统一注册表拥有，不以工厂闭包制造不可枚举的状态实例。

# 前端巨型领域对象类型门禁与抽象拆分（TTT）

> **最终目标**：在保留 `imports.ts` 网关和现有运行时行为的前提下，清理巨型领域对象的重复实现与具体类依赖；依赖方使用完整领域抽象，具体类仅位于初始化、组合和契约校验边界。
>
> **当前目标**：以 `vue-tsc` 同时检查 TypeScript 与 73 个 Vue SFC，在保持 `ISiyuan` 与 Model 真实生命周期可选性的前提下按根因清理全部诊断；Tree、CustomLists、EmbeddingDock 与 Vue 挂载事件契约当前诊断已归零。
>
> **下一步任务**：继续从全量类型检查的最高影响根因逐域修正；在所有 TypeScript 错误归零前不处理 lint。逐项追踪声明、实现和完整调用链，不以断言、虚假必有状态或缩小检查范围降错。

## 不变量

- 保留所有既有业务逻辑、事件顺序、生命周期和错误语义。
- `imports.ts` 继续作为既有网关；解耦通过完整领域类型、参数传递和组合根完成。
- 类抽象覆盖完整公共实例表面，使用 `PublicInstanceLooksLike` 或 `InstanceLooksLike` 双向校验。
- 不创建 `I*Host` 等只覆盖单个调用点的碎片接口；同一领域只维护一个聚合根抽象。
- 异步回调、观察器、DOM 生命周期和销毁路径均需显式可测，不以断言或宽泛类型掩盖状态缺失。
- `ISiyuan` 描述跨启动阶段和多宿主共享的可变全局对象，不具有“应用已经完成初始化”的隐含语义；阶段必有状态必须由可验证的访问器、守卫或已构造领域对象表达。
- 模块间交互默认采用异步语义；同步行为是必须带 `@同步豁免` 并给出可验证必要性的特殊例外。类型诊断只能定位契约两端不一致，不能把项目已经确定的异步方向重新解释成同步与异步之间的中立选择。
- “同步状态被错误声明为异步”不作为本项目的有效类型错误类别；现有同步调用方与 `Promise` 冲突，默认说明调用链尚未完成异步迁移。不得为了局部消除类型错误，把已经形成的异步边界压回同步语义。
- 如果发现“同步调用被错误写为异步”的问题，正确处理方式是：除非完整迁移确实难以完成并已记录阻塞证据，否则将整个调用栈迁移为异步语义，同时修正调用方、事件边界、返回类型、错误传播、取消/销毁时序和测试；不得通过移除 `Promise`、忽略返回值或同步包装来快速消除诊断。
- 只有当前用户手势、同一 DOM 快照、构造/装配原子性或既有外部同步协议等可验证约束，才可支持保留同步并添加 `@同步豁免`；“现有调用方是同步的”“修改范围较大”或“类型错误较少”均不构成同步必要性。
- 每个阶段完成后运行目标类型检查、运行测试、循环检查、构建和启动回归，并原子提交。
- 当前收敛顺序固定为 TypeScript 诊断归零优先；lint 问题只记录，不在类型错误归零前驱动代码修改。

## 类型错误判定规程

1. 先记录原始诊断、声明位置、实现位置和完整调用链；不得从错误文案直接推断应修改声明端还是实现端。
2. 依据运行时行为、生命周期、跨模块交互边界、错误/取消语义、现有测试和 lint 规则确定异步迁移范围；`require-async-export` 明确给出的异步方向是架构约束，而非可忽略的格式提示。错误数量变化仅用于定位，不作为方案正确性的证据。
3. 对同步调用与异步目标的冲突，默认向上迁移完整调用栈，并补充可等待完成、异常传播、取消和时序测试；只有第 2 步取得同步具有不可替代语义的正面证据时才保留同步并显式豁免。
4. 无法在当前阶段完成全栈迁移时，保留诊断或登记明确阻塞与后续边界，不制造局部伪异步、`void Promise`、断言、宽泛类型或静默失败来掩盖冲突。

## 风险与验收标准

- 旧副本清理必须有当前源码搜索和构建入口证据，不能依据文件名推断。
- 任何类契约变化必须通过 `LooksLike.types.ts` 校验，并覆盖完整公共表面。

- 失败必须保留完整错误上下文；禁止静默回退、缩小检查范围或删除测试来取得绿灯。

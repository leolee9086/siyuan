# 前端巨型领域对象类型门禁与抽象拆分（TTT）

> **最终目标**：在保留 `imports.ts` 网关和现有运行时行为的前提下，清理巨型领域对象的重复实现与具体类依赖；依赖方使用完整领域抽象，具体类仅位于初始化、组合和契约校验边界。
>
> **当前目标**：完成 BlockPanel 旧副本清理与活动类公共表面校验，建立后续 `keydown`、Protyle、History、Dock 和 AgentChat 的拆分基线。
>
> **下一步任务**：按全量类型诊断聚类推进下一个完整领域根；每阶段记录错误数量、实现文件、契约文件和回归证据。

## 不变量

- 保留所有既有业务逻辑、事件顺序、生命周期和错误语义。
- `imports.ts` 继续作为既有网关；解耦通过完整领域类型、参数传递和组合根完成。
- 类抽象覆盖完整公共实例表面，使用 `PublicInstanceLooksLike` 或 `InstanceLooksLike` 双向校验。
- 不创建 `I*Host` 等只覆盖单个调用点的碎片接口；同一领域只维护一个聚合根抽象。
- 异步回调、观察器、DOM 生命周期和销毁路径均需显式可测，不以断言或宽泛类型掩盖状态缺失。
- 每个阶段完成后运行目标类型检查、运行测试、循环检查、构建和启动回归，并原子提交。

## 风险与验收标准

- 旧副本清理必须有当前源码搜索和构建入口证据，不能依据文件名推断。
- 任何类契约变化必须通过 `LooksLike.types.ts` 校验，并覆盖完整公共表面。
- 循环数量为 0 仅是结构门禁；最终验收还要求全量 TypeScript 检查、开发构建、生产构建、目标测试和启动路径通过。
- 失败必须保留完整错误上下文；禁止静默回退、缩小检查范围或删除测试来取得绿灯。

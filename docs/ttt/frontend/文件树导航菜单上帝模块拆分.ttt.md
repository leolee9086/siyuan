# 文件树导航菜单上帝模块拆分（TikTocTak）

> **最终目标**：在保持桌面、移动、键盘和插件菜单行为不变的前提下，将 `menus/navigation.ts` 拆分为笔记本菜单、文件菜单、导入菜单及扩展菜单的单向领域子图；调用方直达真实所有者，旧上帝模块归零后删除。
>
> **当前目标**：导航菜单当前首条返回链已推进为 `menus/navigation -> search/spread -> genSearch -> handleListItemClick -> util/file/newFile -> editor/utils.openFileById`；先消除 Search 新建文档的具体实现返回边，再继续迁移 Cronjob 扩展段和笔记本/文件菜单组合根。
>
> **下一步任务**：核对 `handleListItemClick` 的新建文档分支与完整 `AppFacade.createDocument()` 行为等价性，以行为测试固定参数、返回和错误传播后切断 `newFile/openFileById` 返回边；重新计算导航首环后继续菜单领域拆分。

## 不变量

- 文件树菜单项顺序、ID、分隔符、权限、快捷键、点击时序和插件插入位置保持不变。
- 桌面与移动菜单差异按宿主保持独立，不通过全局断点或条件参数强行统一。
- 所有调用方依赖完整菜单能力，不创建只含单个回调的 Host/Port 碎片接口。
- 保留 `imports.ts` 机制；子域网关直达真实声明或唯一实现，禁止 imports 多跳。
- App 导航统一通过完整 AppFacade；具体 App、Tab、Files、Dialog class 只在组合或 factory 边界出现。
- 禁止动态导入隐藏环、模块工厂闭包状态、事件绕行、宽泛 `unknown` 和兼容 barrel。

## 现状基线

- **2026-07-27**：阶段前 `menus/navigation.ts` 为 776 行上帝模块，仅有 `confirmEncryptedExport/initNavigationMenu/initFileMenu/genImportMenu` 四个顶层职责入口，却加载约 35 个跨域实现。
- `initFileMenu` 内部动态导入笔记内插件、Cronjob API、Dialog 与 Dock 查询，运行时依赖对静态图不可见。
- 桌面 Files、移动 Files、全局 keydown、fileTreeKeydown 与 Menus 根共同调用笔记本/文件菜单。
- 权威循环基线为 `2328` 个生产节点、`149` 条代表环；首环经过 `Files/eventHandlers.element.click.helpers -> menus/navigation`。

## 目标架构

```text
menus/fileTree/
  notebookMenu/
  documentMenu/
  importMenu/
  extensionMenu/
  shared/

调用方 -> 对应完整菜单组合根
菜单组合根 -> 明确扩展动作 + AppFacade + 叶子菜单能力
```

## 风险与验收

- 异步扩展菜单当前可能晚于 popup 构建完成，拆分前必须用行为证据固定现状，不凭直觉调整。
- 加密笔记本禁止部分导出与卡片动作，权限判断顺序必须保持。
- 验收以全部调用方直达新所有者、旧上帝模块删除、行为测试与循环性质为准。

# 事务提交与本地同步职责拆分（TikTocTak）

## 最终目标

将 Protyle 事务的命令提交、撤销登记、本地 DOM 同步、内核请求和 transaction 辅助操作拆为单向职责；保留全部公开函数、事务顺序、undo 数据、编辑器局部同步和回调时序，使只需提交事务的交互模块不加载 turns、fold、onTransaction 或完整 Protyle 渲染运行时。

## 当前目标

- [x] 登记 `transaction.ts` 综合出口和 `transaction.promise.ts` 双向依赖基线。
- [x] 提取 `transaction/removeTopElement` 唯一命令实现，删除无消费者的综合根入口。
- [x] 将所有生产调用点直达真实事务职责所有者。
- [x] 消除 submit/promise 与 promise/removeTopElement 的直接模块互递。
- [x] 为已同步应用的 AV 视图切换建立不加载通用本地同步器的严格提交命令。

## 下一步任务

1. 拆分 `transaction.promise.ts` 的本地 DOM 同步阶段与内核请求阶段。
2. 消除 `submit -> imports -> promise -> submit` 真实互递，使提交入口退出 SCC。
3. 扩展请求队列、回调与嵌入块延迟刷新行为测试。

## 不变量

- `transaction` 的同步返回、空操作短路、无 Protyle 请求、undo 登记、lite 分支和 observer 断开顺序保持不变。
- 不以工厂闭包、动态导入、事件总线或调用点回调隐藏递归依赖。
- 模块级事务队列和跨调用状态继续由现有统一注册表/队列所有者管理。
- 不创建按调用点裁剪的事务 Port；函数职责使用完整请求与结果类型。
- `imports.ts` 继续存在并直接指向事务真实所有者，不经过其它网关。

## 现状基线

- `transaction.ts` 公开 `transaction/removeTopElement/updateTransaction/updateBatchTransaction`，并聚合 turns、fold、onTransaction 出口。
- 全仓约 125 个模块从综合 transaction 路径导入；只需 `transaction` 的调用也会静态加载所有 re-export。
- `transaction.promise.ts` 负责大规模本地 DOM 同步和内核提交，并反向导入根模块的 `transaction/removeTopElement`，形成直接模块循环。
- 当前唯一 SCC `679`，枚举环 `539`；dragFill 最短路径经 `transaction.turns -> block/imports -> Protyle -> mousedown` 返回。

# 前端上帝对象领域拆分（TikTocTak）

> **最终目标**：将阻碍前端单向依赖的上帝模块按稳定领域职责拆分，使具体 class、全局查询、宿主装配和纯算法不再通过中央聚合对象互相反向依赖，并为“前端循环依赖类型解耦”提供可持续的领域边界。
>
> **当前目标**：沿 Editor/Layout/Card/AI/Protyle AV 主环继续清除稳定子域对具体组合入口的依赖。
>
> **下一步任务**：分析 Editor 网关与 Layout 新页签组合、AV Asset 与 Editor rename 的双端职责，识别需要独立 TTT 的下一个组合根或上帝模块。

---

## 关联任务

- 主任务：[前端循环依赖类型解耦](./前端循环依赖类型解耦.ttt.md)
- 本文只追踪必须通过领域拆分才能解除的上帝模块；普通局部反向依赖仍由主任务追踪。
- 每个拆分阶段必须同时更新两份 TTT 的 SCC、简单环、测试和暂存证据。

## 不变量

- 保留并扫描所有 `imports.ts`；通过重新划定领域网关暴露真实依赖，不删除或绕开网关。
- 不以移动文件、动态导入、字符串模块路径、lint 忽略或类型降级掩盖循环。
- 类型可以依赖稳定领域类型；稳定类型不得反向依赖具体实现 class。
- 优先提取领域根与完整能力契约，不按单个调用点堆积细碎接口。
- 不用 `unknown` 代替可参数化的应用、页签、编辑器或模型身份；`unknown` 仅用于真实外部输入校验。
- 相同运行逻辑保持唯一实现；宿主差异确实不相同时允许分开实现。
- 工厂只负责装配，不持有跨调用生命周期状态；此类状态由统一注册表集中管理并提供显式重置。
- 迁移前后保持事件顺序、错误传播、DOM 生命周期、会话状态和公开行为一致。
- 一个拆分阶段只有在相关测试通过且 Tarjan SCC 净下降时才归档；仅改变环路径名称不算完成。

## 识别标准

满足下列多项且在 SCC 中形成大量扇入/扇出的模块，登记为上帝对象或上帝模块：

- 同时承担领域状态、实例创建、全局环境访问、遍历、分类和 UI 副作用。
- 一个 `imports.ts` 聚合多个子域，并被该域的核心 class 反向消费。
- 具体 class 被用于本应由稳定身份、判别字段或参数能力表达的判断。
- 单个模块变化会显著改变 Madge 枚举路径，却不能缩小 Tarjan SCC。
- 调用方为获取一个能力必须依赖完整 `App`、`Protyle`、`Tab`、`Wnd` 或中央注册表。

## 目标架构

### Editor 模型域

- 具体 Editor class 位于独立模型子域，只依赖 Protyle 创建、配置读取、字数统计、最近文档写入和宿主回调。
- Editor 公共入口只公开模型身份，不聚合 Editor 全域工具。
- Editor 创建工厂绑定宿主能力；窗口 hash 同步作为必需参数，不使用可选 hook 或空实现。
- `instanceof Editor` 仅保留在确实需要具体实现身份的分类边界，普通消费者使用稳定能力契约。

### Layout 查询域

- 纯布局遍历只依赖 `Branch/Window/Tab` 结构泛型，保留真实身份且不导入具体 class。
- 模型分类单独拥有具体模型映射，不与窗口/页签遍历实现混合。
- 全局环境查询负责取得当前布局、移动端和对话框集合，再调用纯遍历或分类函数。
- `getAll.ts` 最终缩减为兼容入口或被明确领域入口替代，不继续拥有全部实现。

- 每完成一个领域，重新读取 `pnpm lint:cycles` 最短环和 Tarjan SCC，决定下一个拆分对象。

## 风险

- **行为漂移**：遍历顺序、未初始化页签、Electron 窗口判断和模型动态值必须保持原语义。
- **形式解耦**：把依赖移动到 factory 或新网关但 SCC 不下降时，不得归档为完成。
- **类型退化**：递归布局和宿主身份若用 `unknown` 或断言拼接，会隐藏真实契约错误。
- **并行修改**：工作树存在大量已暂存变更；只增量暂存本任务文件，不重置其他改动。

## 验收标准

- 对应上帝模块不再同时拥有多个独立领域的运行实现。
- 新领域根拥有直接测试，专项 lint 和 `git diff --check` 通过。
- 每个归档阶段的 Tarjan SCC 相比阶段基线净下降，且没有新增独立 SCC。
- `pnpm lint:cycles` 最终为零；全部 `imports.ts` 保留并参与扫描。
- Node、Vitest、浏览器契约测试及最终 TypeScript 检查全部通过。

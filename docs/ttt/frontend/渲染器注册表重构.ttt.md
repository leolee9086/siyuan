# 渲染器注册表重构执行跟踪 (TikTocTak)

> **目标**: 将 `processRender` 硬编码 switch-case 分发器改为注册表模式（ContentRendererRegistry），9 个子渲染器自注册，20 处消费方统一依赖注册表接口。量化指标：消除 `processRender` 函数，所有 20 处调用迁移至 `contentRendererRegistry.render()`，TypeScript 编译和 lint 通过。
>
> **流程**: 这是一个滚动更新的执行路线图。
> 1. 从"近期计划"中认领一个任务。
> 2. 完成开发和测试。
> 3. 将其移动到"已归档/已完成"区域。
> 4. 将"中期计划"中的条目提升到"近期计划"。

---

## 🎯 核心原则

### 架构决策
- **注册表模式**: 参考 [`TabRegistry`](../../../app/src/registry/TabRegistry.ts) 的 Map + SForge 全局状态模式
- **注册表统一存放**: 新建 `ContentRendererRegistry` 位于 `app/src/registry/` 目录
- **渲染器签名统一**: `(element: Element, cdn?: string) => void | Promise<void>`，htmlRender 无 cdn 参数但兼容此签名
- **自注册模式**: 各渲染器文件自行调用 `register()`，不由中心文件统一导入

- [x] ContentRendererRegistry 能正确注册和查找渲染器
- [x] 9 个子渲染器全部通过自注册方式注册

- [x] `processRender` 函数从 `processCode.ts` 中移除
- [x] `processPasteCode` 保留在 protyle 内部不受影响
- [x] TypeScript 编译通过（1 个已有 TS2688 错误与本次重构无关）
- [x] lint 通过（仅 task-checker/require-task 规则报错，非代码质量问题）

    6. [x] 更新 `registry/index.ts` 导出

    4. ✅ `render()` 方法从 element 的 `data-subtype` 属性读取类型并分发
    5. ✅ 在 `app/src/registry/index.ts` 中导出
  - **验收标准**:

    - 基于 Map + SForge 全局状态模式（参考 TabRegistry）

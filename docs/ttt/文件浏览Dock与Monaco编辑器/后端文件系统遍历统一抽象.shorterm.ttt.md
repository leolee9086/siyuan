# 后端文件系统遍历统一抽象 (TikTocTak)

> **归属**: [文件浏览 Dock 与 Monaco 编辑器](../文件浏览Dock与Monaco编辑器.ttt.md)
> **目标**: 审计后端所有递归文件系统遍历，将目录枚举、受控读取/写入和平台边界收敛到一个深模块；领域层只声明授权入口、目录剪枝、文件选择、匹配/转换回调和业务事务，不接触绝对路径、文件句柄或具体文件 I/O。

## 统一原则

- 统一的是目录枚举、并发调度、取消、深度/条目上限、链接边界、受限读取、原子写入和错误统计；权限根选择、审批、索引事务和内容转换仍由各领域声明。
- 调用方必须先解析并固定授权根；底层 walker 只接受已验证的绝对根和根相对路径，不接受模型或前端传入的任意绝对路径。
- visitor 只在协调 goroutine 中调用；目录读取可并发，停止条件、错误计数和输出上限必须确定且可测试。
- Windows 使用同一 `GetFileInformationByHandleEx(FileIdBothDirectoryInfo)` 枚举器和 reparse 防护；其他平台保留等价接口。
- `fswalk` 是深模块：领域层只声明目录剪枝、文件选择、行匹配、纯文本变换、对象编解码或入口消费回调；绝对路径、枚举、`Stat`、限量读取、图片解码、备份、原子写入、删除、取消和错误聚合均留在模块内部。
- 深模块按工作流提供聚焦入口：`Walk/ReadDirectory`、`SearchText`、`PlanTextTransform`/`Apply`、`CopyTree`；不以一个带大量可选参数的万能函数混合读取、写入和领域事务。
- 授权根解析仍由拥有权限语义的调用方完成，但进入 `fswalk.New` 后公共 API 只接收根相对路径，入口事件不暴露绝对路径或 `os.File`。

| `kernel/mcp/tools/file.go`、`kernel/cli/cmd/file.go` grep | 工作空间根内的 `resolvePath`/`absPath` | gulu 对入口链接和嵌套链接有不同处理；调用方另有授权检查 | 正则、include、顺序、上下文、上限、静默 I/O 错误和输出均为兼容契约 | 迁移门禁未通过；见 [`gulu.File.Grep行为守恒.shorterm.ttt.md`](gulu.File.Grep行为守恒.shorterm.ttt.md) |

| `kernel/search/find.go` | 调用方提供的内部根 | 不跟随链接 | 文件读取错误降级为无匹配；跨块匹配且每文件目标去重 | 已迁移到独立字节搜索工作流，领域只映射匹配结果 |
| `kernel/assetmeta/service.go` | 内部 `data/assets` | 不跟随链接 | 遍历错误终止；单文件图片探测错误降级并保留物理元数据 | 迁移到批量图片探测入口，领域只声明未索引文件选择与元数据组装 |
| `kernel/assetmeta/model.go` | 内部元数据命名空间 | 不跟随链接 | 单个 JSON 读取/解析错误记录后继续；写入必须原子 | 迁移到绑定根 JSON 存储；移除领域层路径拼接、存在性检查和直接读写 |
| `kernel/model/export.go`、`import_obsidian.go` | 已验证的导出/导入临时根 | 遇到链接立即失败 | 遍历、建目录、复制任一错误终止 | 复用枚举内核前需提供 fail-fast 模式；副作用 visitor 独立 |
| `kernel/cronjob/folder_watcher.go` | cron 配置目录 | 不跟随链接 | 遍历错误终止，单个 watcher.Add 错误记录后继续 | 后续迁移；保留 watcher 生命周期语义 |
| `kernel/cronjob/watermark.go` | 导出目录 | 不跟随链接 | 遍历或水印处理错误终止 | 后续迁移；水印副作用独立 |
| `kernel/util.WalkWithSymlinks` | 调用方根 | 明确跟随链接并带 visited 集合 | `filelock.Walk` 回调语义 | 明确保留为专用实现，不并入默认不跟随链接的 walker |
| 其余 `filelock.Walk` 调用 | 数据目录、笔记本、导入包等内部根 | 由 filelock 和各调用方控制 | 包含 `.sy` 文件锁、索引、迁移、复制和写入副作用 | 不作为通用只读遍历重复实现；逐领域评估，不机械替换 |

单层 `os.ReadDir` 用于列表、配置加载或递归算法内部，不自动视为重复递归实现；只有承担树遍历调度职责的调用点进入迁移范围。

## 验收

- `kernel` 只读通用递归枚举只有一个平台实现；Agent、MCP、MAGI 和文件浏览不再各自调用 `filepath.WalkDir` 完成同类任务。
- 每个迁移调用方的原有过滤、上限、错误输出和授权边界都有真实目录测试，且 junction 替换不会越过根。
- 小规模清单、race 和性能结果通过；完整 `D:\` 证据在统一实现之后生成，避免验收未被实际调用方复用的孤立实现。

## 2026-08-06 边界纠偏记录

- 已确认“只把 `filepath.Walk` 换成 `Walker.Walk`，随后仍由领域循环执行 `os.ReadFile`、图片打开或原子写入”不构成深模块迁移。
- 领域层可以声明文件/目录入口回调、过滤、纯内容转换和索引事务；不可获得绝对路径、`os.File`、`io.Reader` 或自行实现文件读取/写入步骤。

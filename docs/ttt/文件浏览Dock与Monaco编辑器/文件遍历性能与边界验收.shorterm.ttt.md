# 文件遍历性能与边界验收 (TikTocTak)

> **归属**: [文件浏览 Dock 与 Monaco 编辑器](../文件浏览Dock与Monaco编辑器.ttt.md)
> **目标**: 用小规模真实目录推进正确性，用完整 `D:\` 扫描形成性能验收证据；性能基线不再使用 S-Forge 自身旧实现。

## 推进门禁

- 小规模真实落盘目录用于每次实现调整：先运行集合摘要、计数、错误语义和边界校验，再运行不计算摘要的计时轮。
- 完整 `D:\` 只用于最终验收；小规模结果不得表述为整盘性能结论，整盘耗时也不得替代集合与错误正确性证据。
- 任何实现只要少扫、越过根目录、吞掉错误、取消不生效或条目/目录计数不一致，即使耗时更短也不进入性能排名。
- 性能优化必须保留相应回归测试；计时路径省略 `Entry` 构造或摘要计算时，由独立验证轮证明它与完整路径的结果一致。

## 正确性边界

- [x] 空目录和精确条目上限。
- [x] Windows 64 KiB 原生枚举多批次。
- [x] 超过 260 字符的 Unicode/emoji/组合字符路径。
- [x] 遍历回调中取消请求。
- [x] 枚举父目录后删除待扫描子目录，保留部分结果并返回归一化错误。
- [x] 最大深度边界和截断状态。
- [x] 根内/根外 junction 不递归且越界节点受限。
- [x] 遍历期间把已发现目录替换为 junction，确认不发生根外跟随；批量枚举的空结果/不支持分支及 `FindFirstFileW` 回退均拒绝 reparse point。
- [x] 4097 个真实目录读取错误时，总错误数和有效条目计数完整，仅保留前 4096 条错误明细。
- [x] 长路径、Unicode、多批次和目录变化测试随整个 `filebrowser` 包通过 `go test -race ./filebrowser -count=1`。

**当前执行**：四种小规模真实形状的首轮集合校验均成立；大量空目录轮发现原生枚举为每个空目录预分配 128 个条目槽，4096 个空目录产生约 24.6 MiB Go 分配并落后 `fastwalk-tuned`。正在移除该分配并重跑全部形状，首轮耗时不作为调优后结论。

## 性能基线

- S-Forge：生产 `filebrowser.ScanContext`，Windows 使用 `GetFileInformationByHandleEx(FileIdBothDirectoryInfo)`。
- Node：SACAssetsManager `94c8534a` 的真实 `fdirModified`、stock `fdir 6.2.0`、`fast-glob 3.3.2` Promise/stream。
- Go：`filepath.WalkDir`、`filepath.Walk`、`godirwalk 1.17.0` 默认/unsorted、`fastwalk 1.0.14` 默认/同 worker 调优、`saracen/walker 0.1.4` 默认/同 worker 调优、`doublestar 4.10.0 GlobWalk`。
- `godirwalk 1.17.0` 的 Windows unsorted scanner 在当前 Go 1.26 下把正常目录结尾的 `io.EOF` 返回为失败并中断整棵树；工具保留该失败和不完整计数，另跑默认排序路径，不通过吞掉 `EOF` 伪造性能数字。
- 验证轮比较文件数、目录数、条目数和顺序无关路径摘要；计时轮不计算摘要，但仍执行与其他 walker 等价的路径流式回调。错误不可观测的实现明确标为 `errorsKnown=false`，不把跳过错误后的较少工作量当作性能优势。
- `worker-sweep-6432.json` 的 S-Forge 计时使用了无 visitor 的纯计数快路径，只保留为内部 worker 调优线索，不再作为横向性能证据；正式结果必须使用路径流式回调并标记每个计时样本是否与验证轮计数一致。

## 分层验收

- [ ] 小规模真实目录：所有实现返回集合一致；重复三次并记录中位数和分配。
- [ ] 中等宽目录、深目录、空目录和大量小文件分别测量，避免单一形状偏置。
- [ ] 完整 `D:\`：先完成验证轮，再对每个实现至少一次热身和一次计时；记录扫描期间文件变化、可访问错误、条目摘要、耗时和内存。
- [ ] 原生实现的完整结果集合成立且性能高于列出的 Node 与 Go 基线后，才勾选 M1.4 性能验收。

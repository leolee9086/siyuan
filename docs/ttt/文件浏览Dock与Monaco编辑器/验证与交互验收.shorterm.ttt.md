# 验证与交互验收 (TikTocTak)

> **归属**: [文件浏览Dock与Monaco编辑器.ttt.md](../文件浏览Dock与Monaco编辑器.ttt.md)
> **目标**: 为每个可用里程碑建立与需求范围相匹配的后端、前端、浏览器和性能证据。

## 验收层级

1. Go：根聚合、路径边界、capability、文件操作、索引、标签和颜色查询。
2. Vitest/Node：契约、仓储、状态机、菜单、筛选、编辑器保存和错误映射。
3. 浏览器交互：Dock 恢复、根切换、树/画廊、拖放、标签颜色搜索、预览、编辑、保存和外部修改。
4. 性能：大目录分页/取消、虚拟化、缩略图并发、索引重建和颜色查询响应时间。

## 证据规则

- 聚焦测试只证明其覆盖的契约，不能替代全范围声称；每个里程碑记录命令、结果、时间和未覆盖项。
- A 级证据：真实运行 Kernel 与前端中的浏览器交互、布局恢复、网络请求和截图；可用于里程碑用户流程验收。
- B 级证据：真实临时文件系统、真实 Gin handler、真实 Vue/TabRegistry/Custom 组合链；可用于对应边界验收，但不替代 A 级。
- C 级证据：仓储、状态机、应用外观和菜单替身单元测试；只证明局部分支与请求形状。
- D 级证据：模块可导入、SFC/SCSS 可编译、类型存在；只作为构建回归保护，不计入业务功能完成度。
- 测试记录必须标注等级；禁止用 C/D 级测试声称树、瀑布流、预览页签或真实文件打开已完成。
- 前端不处理本次范围外的 P1 以上既有 lint 债务；本次新增 P0 逻辑/类型错误必须清零。
- 交互失败、权限拒绝、取消、冲突和部分成功必须可见并可复现。

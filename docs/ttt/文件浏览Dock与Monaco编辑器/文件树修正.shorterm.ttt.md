# 文件树修正 (TikTocTak)

> **归属**: [文件浏览Dock与Monaco编辑器.ttt.md](../文件浏览Dock与Monaco编辑器.ttt.md)
> **目的**: 对照 SACAssetsManager/Monaco 的真实树原型，修正文件 Dock 的递归树组合、可访问性、状态恢复和拖拽交互。

## 验收边界

- 文件根、目录和文件必须是同一棵递归树中的节点；根不能被渲染为下拉选项或平铺结果卡片。
- 每个目录节点只在展开时显示自己的 `role=group` 子树；子节点必须嵌套在对应父节点的列表中。
- 节点必须暴露 `aria-level`、`aria-posinset`、`aria-setsize`、`aria-expanded` 和稳定身份；键盘导航按当前可见树顺序工作。
- 刷新根集合时保留仍存在节点的展开、焦点和选择；失效根仍显示但不发起目录读取。
- 对照参考原型接入树节点拖拽、目录延迟展开、放置目标反馈、刷新和菜单动作；领域状态仍由文件树控制器持有。
- 交互测试必须挂载 Vue SFC，断言真实嵌套 DOM 和事件结果；纯数组测试不能单独作为树验收证据。

## 参考语义记录

- SACAssetsManager 的 `tagItem.vue` 使用递归子项、深度缩进、拖放反馈和点击打开；其标签结果打开行为不能替代文件树节点模型。
- Monaco 的 ExplorerDock/filetree 使用目录优先排序、递归子树、懒加载、展开恢复、拖拽移动和拖拽延迟展开；文件 Dock 只复用这些交互语义，不伪造思源块节点字段。

# 文件根目录与后端能力 (TikTocTak)

> **归属**: [文件浏览Dock与Monaco编辑器.ttt.md](../文件浏览Dock与Monaco编辑器.ttt.md)
> **目标**: 在不绕过既有 Agent capability 的前提下，提供工作空间根和全部已绑定任务目录的统一浏览、查询、元数据和文件操作后端。

## 现有可复用设施

- `kernel/util.WorkspaceDir`、`DataDir`、路径规范化、`filelock` 和现有文件 API。
- `kernel/agent/session.go` 的 `TaskDirectoryBinding`、权限枚举、workspace-owned store、会话锁和路径验证。
- `kernel/assetmeta` 的 JSON 文件主数据、SQLite `asset_meta/asset_tags/asset_palettes` 表、尺寸扫描和调色板提取。
- `kernel/api/router.go` 的鉴权/响应包络与 `kernel/api/asset_meta.go` 的素材 API 约定。

## 冻结契约

| 契约 | 必须包含 |
| --- | --- |
| `FileRoot` | `id`、`kind`、`label`、`path`、`permission`、`sessionIDs`、`exists` |
| `FileEntry` | `rootID`、相对路径、名称、类型、大小、mtime、扩展名、缩略图/预览引用、metadata 摘要 |
| `FileQuery` | root/path、递归、关键词、扩展名、tags、颜色/HSL、star、排序、分页、取消 token |
| `FileOperation` | 新建、写入、复制、移动、重命名、删除、上传、打包下载；返回逐项结果和冲突原因 |
| `EditorDocument` | root/path、语言、编码、原始 revision、可写能力、保存策略、来源类型、diff 对端 |

### M1.2 只读内容契约

- [x] `POST /api/s-forge/file-browser/stat`：校验 root/path 和符号链接边界，返回 `FileStat`、预览类型、MIME、revision 与受控内容 URL。
- [x] `POST /api/s-forge/file-browser/preview`：只读取受限字节数的文本预览，返回编码和截断状态；目录、二进制与越界路径显式报错。
- [x] `GET /api/s-forge/file-browser/content/:rootID/*path`：以同一根解析器流式返回文件，保留 HTTP Range 和修改时间语义，仅向 Kernel 同设备管理员开放。
- 三个入口共享 `ValidateFilePath`，客户端没有提交绝对路径的字段；该读取契约将直接作为后续编辑器 document/revision 能力的基础。

当前证据为临时真实文件系统与 API handler 测试；实际运行 Kernel 的鉴权中间件、媒体标签请求和 PDF.js Range 行为仍待浏览器验证。

## 安全不变量

- 客户端只能提交 root ID 和相对路径，服务端从当前 workspace/capability store 解析绝对路径。
- 相对路径必须经过清理、符号链接边界检查和根目录内验证；跨根移动必须显式授权并可回滚。
- 远程请求沿用既有 owner/guardian/同设备边界；普通 Agent 会话响应继续脱敏，文件浏览 API 只在明确能力下返回真实位置。
- 写入使用临时文件、刷盘和原子替换；删除/覆盖前产生冲突状态，不静默丢失数据。

## M1.3 平台目录枚举与计数性能

- [x] Windows 枚举主路径使用 `GetFileInformationByHandleEx(FileIdBothDirectoryInfo)` 以 64 KiB 批次读取名称、类型、大小、mtime、隐藏属性和重解析点标志；不支持批量查询的文件系统回退 `FindFirstFileW/FindNextFileW`，长路径统一使用 `\\?\` 前缀。
- [x] 普通文件不再执行逐项 `Lstat`；只有重解析点继续解析真实目标并复用根内边界检查。其他平台通过同一快照接口并行读取目录项元数据。
- [x] `ListContext` 传播 HTTP 请求取消；直接子目录的文件数/目录数只对当前分页中的目录执行，并由 `2*GOMAXPROCS`、最少 4、最多 32 的有界 worker pool 并发统计。响应同时返回当前目录总 `fileCount/directoryCount` 和每个目录可选的 `childFileCount/childDirectoryCount/childCountKnown`。
- [x] `TestListReportsImmediateCountsForTreeNodes` 使用真实临时目录验证树计数，不使用仓储替身。
- [ ] 原生枚举的 `os.ReadDir + 每项 Lstat` 微基准只用于定位系统调用和分配开销，不再作为产品性能验收证据。正式基线必须直接运行 SACAssetsManager `94c8534a` 的 `fdirModified` 最终实现，并在同一棵目录树上校验返回集合后比较。

## M1.4 有界并发递归遍历

- [x] `WalkContext` 将平台目录快照接入正式递归遍历器；目录之间由 `2*GOMAXPROCS`、最少 4、最多 32 的 worker 池并发，结果按稳定任务序号提交，乱序预取窗口限制为 worker 数的两倍。
- [x] 遍历请求只接受 `rootID + 相对路径`；不跟随符号链接或 Windows junction 目录，支持请求取消、最大深度和条目上限，并分别返回 `depthLimitReached`、`entryLimitReached` 和汇总 `truncated`。
- [x] Windows 路径解析使用 `CreateFileW + GetFinalPathNameByHandleW` 获取 reparse point 的最终目标；越界 junction 节点标为 `restricted`，手动展开同样返回 `ErrPathTraversal`。目录枚举句柄使用 `FILE_FLAG_OPEN_REPARSE_POINT`，避免扫描时把被替换的目录跟随到根外。
- [x] 并发完成顺序不影响响应顺序或截断集合；子目录读取失败只记录根内相对路径和归一化错误码，起始目录读取失败直接返回请求错误。
- [x] `POST /api/s-forge/file-browser/walk` 已注册到正式 Kernel 路由，复用同设备管理员门禁、API 包络和 HTTP 请求上下文，供后续递归搜索、标签/颜色索引与监听初始扫描复用。
- [ ] 边界验收尚未完成。已有真实多层树、子路径、并发稳定截断和 junction 越界测试；仍需补齐空目录、64 KiB 多批次、长路径、Unicode、精确深度/条目上下限、遍历中取消、遍历中删除/替换目录和部分读取错误。
- [ ] 原 `filepath.Walk` 对比仅说明相对 S-Forge 旧路径的变化，已撤出性能验收。正式验收改为直接运行 SACAssetsManager `94c8534a` 的 `source/server/processors/fs/fdirModified`，并分别记录冷缓存/热缓存、目录宽度/深度、元数据差异和结果完整性。

当前边界：Windows 目录查询是同步系统调用，请求取消可在 worker 调度、条目处理和每个 64 KiB 批次之间生效，不能中断正在执行的单次系统调用。网络盘、机械盘、杀毒软件、HTTP JSON 和前端渲染必须单独测量，不由本机文件系统基准外推。

# 内核内置日志暴露诊断 API (TikTocTak)

> **目标**: 在思源核心 (Kernel) 添加一个诊断接口，允许外部客户端（如 MAGI 或其他诊断工具）实时获取或拉取核心服务当前的运行日志，从而解决外部排障困难（无法快捷访问物理机器上日志文件）的问题。指标为：支持获取内核最新 N 行日志，接口响应时间 < 200ms。
>
> **流程**: 这是一个滚动更新的执行路线图。
> 1. 从"近期计划"中认领一个任务。
> 2. 完成开发和测试。
> 3. 将其移动到"已归档/已完成"区域。
> 4. 将"中期计划"中的条目提升到"近期计划"。

---

## 🧭 核心原则与验证

- **安全优先**: 日志可能包含敏感信息，须确保接口仅在授权环境或本地可信环境下可用。
- **性能无损**: 读取日志的操作不能阻塞正常核心业务运作，文件读取必须高效。
- **验证检查清单**:
  - [ ] 接口正常响应，无 500 错误
  - [ ] 接口响应时延达标 (< 200ms)
  - [ ] 日志内容无截断、无中文乱码
  - [ ] MAGI 调用成功并能基于真实日志自我修正

## 🟢 近期计划 

- [-] **Phase 1: 核心日志获取与接口定义 (P0)**
  - **背景**: 外部调试工具（比如 Claude Code 或 MAGI Frontend）在对接思源内核时，无法查看到服务端的错误堆栈与 Debug 日志，导致排错效率低下。需要内核自身暴露读取日志的手段。
  - **行动**: 
    1. 探查当前 `logging` 模块，明确日志写入的具体文件路径和日志轮转机制。
    2. 设计核心接口 `POST /api/system/getLogs`，支持参数 `lines`。
    3. 编写 `kernel/api/system.go` 中的路由处理与核心读取逻辑。
  - **验收标准**: 能通过 curl 调用新接口成功获得日志原文；日志顺序正确，无乱码。
  - **参考文档**: `kernel/api/router.go`, `logging` 模块。

- [ ] **Phase 2: MAGI Agent 集成 (P1)**
  - **背景**: 为了更强地自我纠错与诊断，大语言模型代理在出错时如果能自主查阅服务端日志将极大提高鲁棒性。
  - **行动**:
    1. 以 Tool (Function Calling) 的形式暴露这个新 API 给内部的 Agent（例如 Trinity 或 Three Wise Men）。
    2. 添加对应的执行逻辑，让 MAGI 拥有 `read_server_logs` 的能力。
  - **验收标准**: 在 MAGI 提示词里请求其自主排查最近报错，MAGI 能够调用 Tool 读到后台日志并给出确切的排他分析。
  - **参考文档**: `kernel/api/magi.go`, `kernel/magi` 相关实现。

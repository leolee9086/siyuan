# 无外部使用的导出符号扫描脚本

> 状态：已完成
> 创建时间：2026-08-01
> 完成时间：2026-08-01

## 任务背景

在修复 [`AgentChat.errorCards.ts`](app/src/layout/dock/agent/chat/interaction/errors/AgentChat.errorCards.ts) 的 lint 错误时，发现了一个问题：该文件导出的 `canRetryLastUserTurn` 包装函数没有任何外部调用方，却带有 `export` 修饰。这类"无外部使用的导出"会让模块公开面膨胀、误导调用方，且难以通过人工 review 发现。

项目已有的 [`scanUnusedFrontend.js`](app/scripts/checker/scanUnusedFrontend.js)（基于 Knip）可以检测未使用导出，但它是全仓级重型扫描（报告 823 个未使用导出），无法按需快速检查单个文件，不适合作为日常反馈工具。

## 任务目标

创建一个轻量的、基于 TypeScript Language Service 的独立扫描脚本，检查**所有类型的导出符号**（函数、变量、常量、类型、接口、类、枚举等）是否存在外部使用。

- **判定标准**：导出符号的外部引用数（排除声明文件自身、排除定义位置自身）为 0，即视为"无外部使用的导出符号"。
- **支持模式**：单文件、目录、全仓（`src/` + `test/`）。
- **遵循规程**：[`前端自定义lint规则实现.procedure.md`](docs/规程/代码质量/前端自定义lint规则实现.procedure.md) 中的报错信息规范（❌ 标识、替代方案、豁免方式、修复提示）。
- **注册方式**：在 `app/package.json` 注册 `scan:unused:exports` 脚本，与现有 `scan:unused:frontend` 等脚本并列。

## 设计要点

- 复用 [`scanLowUsageTypes.js`](app/scripts/checker/scanLowUsageTypes.js) 的 TypeScript Language Service 模式（`findReferences` 统计外部引用）。
- 收集导出符号的类型：`FunctionDeclaration`、`VariableStatement`（含 `const/let/var`）、`TypeAliasDeclaration`、`InterfaceDeclaration`、`ClassDeclaration`、`EnumDeclaration` 等所有带 `export` 修饰的声明。
- 外部引用判定：排除 `reference.isDefinition`；**只统计跨文件引用**（`reference.fileName !== declaration.fileName`），同文件引用不属于外部使用。
- 豁免机制：在导出声明前的注释中添加 `@内部导出` 标记即可跳过检查（使用 `node.getFullStart()` 定位前置注释）。

## 验证结果

- **反例（不误报）**：`appendError`（被 `session/imports.ts`、`stream/protocol/imports.ts` 外部引用）未被报告。
- **正例（正确检出）**：构造测试文件中的函数、类型、接口、变量、常量导出均被检出；`orphanConst`（仅同文件内部引用）也被正确检出。
- **豁免**：带 `@内部导出` 注释的 `publicApiFunction` 被跳过，未豁免的 `orphanFunction` 被检出。
- **全仓扫描**：扫描 5531 个导出声明，检出 898 个无外部使用的导出（与 knip 报告 823 个数量级一致）。
- **实际应用**：检出 [`AgentChat.errorCards.ts`](app/src/layout/dock/agent/chat/interaction/errors/AgentChat.errorCards.ts:30) 的 `appendErrorActions`、confirm 目录的 `postConfirm` 等无外部使用的导出，可作为后续清理依据。

## 实现中修复的问题

1. **单文件模式**：`--file` 指定文件被当作目录递归扫描，改为区分文件与目录。
2. **变量声明漏扫**：`VariableStatement` 无 `.name` 属性，需遍历 `declarationList.declarations` 收集声明符。
3. **跨文件引用判定**：`findReferences` 返回路径与声明路径分隔符不一致，需 `path.normalize` 规范化后比较。
4. **豁免注释定位**：`node.getStart()` 不含前置注释，需改用 `node.getFullStart()`。

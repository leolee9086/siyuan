> **目标**: 系统性地优化 [`kernel/av/filter.go`](../../kernel/av/filter.go) 的性能瓶颈，将响应时间从当前的 500ms-1s（1000条数据+5个过滤条件）降低到 150ms 以内。

> 1. 从"近期计划"中认领一个任务。
> 2. 完成开发和测试。

> 4. 将"中期计划"中的条目提升到"近期计划"。

## ⚠️ 核心原则：正确性优先

**性能优化的铁律**：
1. **正确性 > 性能**：任何性能优化都不能以牺牲正确性为代价
2. **反复验证**：每次修改后必须运行完整的测试套件
3. **对比测试**：优化前后的输出必须完全一致
4. **回归检测**：任何性能提升都必须伴随零回归验证

**验证检查清单**（每次优化后必须执行）：
- [ ] 运行所有单元测试：`go test -v ./av/`
- [ ] 运行功能等价性测试：`go test -run=TestFilterEquivalence -v`
- [ ] 运行性能回归测试：`go test -run=TestFilterPerformanceRegression -v`
- [ ] 运行基准测试对比：`go test -bench=BenchmarkFilter -benchmem`
- [ ] 检查测试覆盖率：`go test -cover ./av/`
- [ ] 人工抽查关键场景的输出结果

**如果任何测试失败**：
1. 立即停止优化工作
2. 回滚到上一个稳定版本
3. 分析失败原因
4. 修复问题后重新验证
5. 记录问题和解决方案

## 🟢 近期计划 (立即聚焦，撸起袖子干)
*任务范围清晰，风险低，能立竿见影提升性能的任务。*

- [ ] **Phase 3: 优化关联字段过滤 (P1优化)**
  - **背景**: 关联字段过滤需要遍历所有关联值，响应时间增加 2-3 倍。
  - **行动**:
    1. 为关联值建立索引（使用 Set 或 Map）
    2. 实现快速匹配算法（避免嵌套循环）
    3. 考虑缓存关联关系
  - **预期收益**: 关联字段过滤性能提升 50-60%

## 🟡 中期计划 (架构演进，步步为营)
*需要更多测试和验证，或者涉及较大重构的任务。*

- [ ] **Phase 4: 优化资源字段过滤 (P1优化)**
  - **背景**: 资源字段过滤需要遍历所有资源项，响应时间增加 1.5-2 倍。
  - **行动**:
    1. 为资源项建立索引
    2. 实现快速匹配算法
    3. 考虑预加载常用资源信息
  - **预期收益**: 资源字段过滤性能提升 40-50%

- [ ] **Phase 5: 优化文本过滤算法 (P1优化)**
  - **背景**: 当前使用简单的 `strings.Contains`，对长文本性能较差。
  - **行动**:
    1. 评估 Boyer-Moore 或 KMP 算法的适用性
    2. 对长文本（>1000字符）使用优化算法
    3. 考虑使用正则表达式引擎的优化版本
  - **预期收益**: 长文本过滤性能提升 30-40%

- [ ] **Phase 6: 实现过滤条件预编译 (P1优化)**
  - **背景**: 每次过滤都重新解析过滤条件，存在重复计算。
  - **行动**:
    1. 设计过滤条件的编译表示
    2. 实现过滤条件编译器
    3. 缓存编译后的过滤条件
  - **预期收益**: 减少 10-15% 的过滤时间

## 🔴 远期计划 (北极星目标，星辰大海)
*需要大规模重构或引入新技术的任务。*

- [ ] **Phase 7: 引入并行过滤 (P2优化)**
  - **愿景**: 利用多核 CPU 并行处理过滤操作。
  - **细节**:
    - 将数据分片，每个 goroutine 处理一个分片
    - 使用 worker pool 模式避免 goroutine 创建开销
    - 实现结果合并逻辑
  - **预期收益**: 大数据集（5000+条）性能提升 2-3 倍

- [ ] **Phase 8: 实现过滤索引 (P2优化)**
  - **愿景**: 为常用过滤条件建立索引，实现 O(1) 查找。
  - **细节**:
    - 分析用户常用的过滤条件
    - 为高频过滤字段建立倒排索引
    - 实现索引的增量更新机制
  - **预期收益**: 索引命中场景性能提升 10 倍以上

- [ ] **Phase 9: 实现查询计划优化器 (P2优化)**
  - **愿景**: 根据过滤条件的选择性自动调整执行顺序。
  - **细节**:
    - 收集字段的统计信息（基数、分布等）
    - 实现代价模型
    - 自动生成最优执行计划
  - **预期收益**: 复杂过滤场景性能提升 2-5 倍

## 💡 优化经验总结

### 🔍 验证经验积累

#### 验证流程最佳实践
1. **三层验证体系**：
   - **第一层：单元测试**（功能正确性）
     - 测试所有核心函数的输入输出
     - 覆盖正常场景和边界条件
     - 确保基本功能无误
   - **第二层：等价性测试**（优化前后一致性）
     - 对比优化前后的输出结果
     - 使用随机测试用例（建议 ≥ 100 个）
     - 验证边界条件和异常情况
   - **第三层：性能测试**（性能提升验证）
     - 运行基准测试 ≥ 10 次
     - 计算平均值、标准差、置信区间
     - 确保性能提升达到预期目标

2. **自动化验证脚本**：

#### 常见验证陷阱
- ❌ **只运行部分测试就认为优化成功**
  - ✅ 正确做法：运行完整的测试套件，包括单元测试、等价性测试、性能测试
- ❌ **忽略边界条件和异常情况**
  - ✅ 正确做法：专门编写边界条件测试，如空数据、单条数据、大量数据
- ❌ **性能提升但功能有细微差异**
  - ✅ 正确做法：使用等价性测试验证输出完全一致
- ❌ **测试通过但实际使用中有问题**
  - ✅ 正确做法：人工抽查典型场景，确保实际使用正常
- ❌ **没有对比优化前后的实际输出**
  - ✅ 正确做法：保存优化前的输出，逐项对比验证

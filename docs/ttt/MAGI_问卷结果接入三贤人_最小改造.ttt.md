## 核心原则

1. **最小改造**: 优先复用 `summaryPrompts/personaPromptBuilder/initMagi(options.prompts)`，只补接线，不重写三贤人核心流程。
2. **提示词最小扰动**: 保留现有贤者基础提示词，新增人格信息以“附加层/注入层”方式接入，避免替换整套模板。
3. **消息结构不破坏**: 维持现有 `MagiMessage` 与共识链路数据结构，不引入新消息协议。
4. **失败可回退**: 人格加载或提示词生成失败时，自动回退默认提示词，不影响 `sendUserMessageWithConsensus`。
5. **先三贤人后扩展**: 以 Melchior/Balthazar/Casper 为必选接线目标；Trinity 作为兼容扩展位，保持与现有逻辑可并存。

**验证检查清单**:

- [ ] 重建后下一轮回复可见三贤人风格差异
- [x] 失败时自动回退默认提示词，且会话不中断

- [x] 最小回归测试通过（接线单测 + 构建验证）

## 🟢 近期计划

- [ ] **Phase 1: 运行时接线契约冻结 (P0)**
  - **背景**: 当前问卷保存回调只传 `samplePath`，无法稳定驱动运行时消费 `profile`。
  - **行动**:
    1. 明确 `saved` 事件最小契约（建议包含 `samplePath + profilePath`）。
    2. 明确 `MagiRoot` 消费策略：保存成功后读取或传递 `profile`，触发重建。
    3. 明确兼容策略：旧契约仅有 `samplePath` 时仍能工作（降级为只提示，不重载）。
  - **验收标准**: 文档化接线契约并锁定影响文件列表，得到可编码的接口定义。
  - **参考文件**: `app/src/magi/entry/persona-seed-panel/PersonaSeedPanel.vue`、`app/src/magi/entry/MagiRoot.ctx.ts`

- [ ] **Phase 2: 最小提示词注入方案冻结 (P0)**
  - **背景**: 直接替换系统提示词会破坏现有贤者模板风格，不符合“最小调整”。
  - **行动**:
    1. 定义“基础提示词 + 人格注入层”拼装策略，避免整段替换。
    2. 复用 `personaPromptBuilder`，约定 `currentInput/telemetry` 的占位输入规范。
    3. 明确三贤人与 Trinity 的注入边界：先保证三贤人可用，Trinity 保持兼容扩展。
  - **验收标准**: 输出可执行的提示词拼装规则与字段映射表（Melchior/Balthazar/Casper）。
  - **参考文件**: `app/src/magi/prompts/personaPromptBuilder.ts`、`app/src/magi/core/wise/mockWise.subclass.ts`

- [ ] **Phase 3: 重载与回退策略冻结 (P1)**
  - **背景**: 人格注入属于运行时配置变更，必须有可观测性和失败回退。
  - **行动**:
    1. 约定 `initializeMAGI` 的最小扩展参数形态（可选 `prompts`）。
    2. 约定重建成功/失败时的系统消息策略（沿用现有消息结构）。
    3. 约定回退顺序：人格注入失败 -> 默认提示词重建 -> 仅系统提示告警。
  - **验收标准**: 重载流程与降级路径有清晰时序图或步骤文档。
  - **参考文件**: `app/src/magi/composables/useMagi.ts`、`app/src/magi/composables/useMagi.types.ts`

- [ ] **Phase 4: 回归测试计划冻结 (P1)**
  - **背景**: 接线跨 `Panel -> Root -> useMagi -> wise`，需要先定义回归范围，防止改动外溢。
  - **行动**:
    1. 定义单测最小集合：提示词映射、契约兼容、失败回退。
    2. 定义手工联调清单：保存问卷、触发重载、观察三贤人差异、异常降级。
    3. 定义“不可回归项”：共识消息结构、输入发送链路、面板打开关闭行为。
  - **验收标准**: 形成可直接执行的测试清单与通过标准。
  - **参考文件**: `app/src/magi/prompts/personaPromptBuilder.test.ts`、`app/src/magi/entry/MagiRoot.vue`

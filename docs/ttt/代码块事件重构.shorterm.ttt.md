## 🎯 目标

将散落在 `keydown.ts` 及其他中间件中的代码块（`NodeCodeBlock`）相关按键处理逻辑（Enter, Tab, Esc 等），聚合到统一的 `keydown.codeBlock` 模块中，并使用 `CalibURRouter` 模式重构。

## 🔍 背景与现状

目前 `keydown.codeBlock.ts` 仅仅处理了**代码块的创建**（即 ` ``` ` 快捷键）。
然而，代码块**内部**的交互逻辑非常复杂且分散：
- **Enter**: 换行、缩进继承（可能在 `enterKeyMiddleware` 或 `softEnterMiddleware` 中）
- **Tab/Shift+Tab**: 缩进/反缩进（在 `tabKeyMiddleware` 中）
- **Esc**: 退出编辑模式（在 `escapeKeyMiddleware` 中）
- **Arrow Keys**: 光标移动（可能涉及边界跳转）
- **Backspace/Delete**: 删除处理

这种分散导致修改代码块行为时需要在多个文件中跳跃，且难以维护状态的一致性。

## 🗓️ 执行计划

### Phase 1: 侦察与分析 (Reconnaissance)
- [ ] **全库扫描**: 搜索 `NodeCodeBlock` 或 `data-type="NodeCodeBlock"`，找出所有涉及代码块的键盘事件处理逻辑。
  - 重点关注: `keydown.ts`, `keydown.enter.ts`, `keydown.tab.ts`, `keydown.delete.ts`, `keydown.arrow.ts`.
- [ ] **行为清单**: 列出所有需要在新路由器中支持的行为（Use Case List）。

### Phase 2: 设计与骨架 (Design & Skeleton)
- [ ] **定义 Schema**: 创建 `CodeBlockStateSchema`，定义代码块操作所需的上下文（如：是否在代码块内、光标位置、语言类型等）。
- [ ] **设计 Router**: 规划 `codeBlockMasterRouter` 的路由表。
- [ ] **创建文件结构**:
  - `app/src/protyle/wysiwyg/keydown.codeBlock/unified/index.ts`
  - `app/src/protyle/wysiwyg/keydown.codeBlock/unified/router.ts`
  - `app/src/protyle/wysiwyg/keydown.codeBlock/unified/state.ts`
  - `app/src/protyle/wysiwyg/keydown.codeBlock/unified/middleware.ts`

### Phase 3: 迁移与实现 (Migration)
- [ ] **迁移 Tab/Shift+Tab**: 将缩进逻辑移入 Router。
- [ ] **迁移 Enter**: 将换行逻辑移入 Router。
- [ ] **迁移 Esc**: 将退出逻辑移入 Router。
- [ ] **迁移 Creation**: 将原有的 `handleCodeBlockCreation` 逻辑整合进 Router (作为 Entry 逻辑或独立逻辑？需要权衡)。
  - *注*: Creation 属于“进入”代码块前的动作，可能更适合保留在外部或作为一种特殊的 Trigger。但如果能统一更好。

### Phase 4: 清理与验证 (Cleanup)
- [ ] **替换入口**: 在 `keydown.ts` 中引入 `codeBlockUnifiedMiddleware`，并移除旧的零散调用（或者在旧中间件中增加 `if (inCodeBlock) return` 的卫语句）。
- [ ] **验证**: 测试所有列出的行为清单。
- [ ] **清理**: 删除旧代码。

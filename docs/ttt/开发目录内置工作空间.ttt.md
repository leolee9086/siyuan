# 开发目录内置工作空间（工坊模式）执行跟踪 (TikTocTak)

> **目标**: 在开发目录中内置一个可用的工作空间（工坊模式 / Workshop Mode），使开发者可以直接在源码目录中调试，同时 git clone 用户也能直接运行，且不与正式安装的思源实例冲突。
>
> **流程**: 这是一个滚动更新的执行路线图。
> 1. 从"近期计划"中认领一个任务。
> 2. 完成开发和测试。
> 3. 将其移动到"已归档/已完成"区域。
> 4. 将"中期计划"中的条目提升到"近期计划"。

## 核心需求

1. **不被 git 跟踪** — 工作空间数据目录必须在 `.gitignore` 中排除
2. **完整笔记功能** — 不是纯测试空间，应可正常使用编辑、搜索等全部功能
3. **多开发目录可同时启动** — 本地存在多个 clone 时，各自使用独立端口和锁，不相互干扰
4. **Electron 测试启动不受影响** — 现有 `pnpm run dev` + Electron 的启动方式完全兼容

### 关键约束分析

1. **`setWorkspaceDir` 安装目录限制已按模式分流**：`prod/dev` 仍禁止安装目录内工作空间；`forge` 已放宽，支持项目根下内置工作空间。
2. **`.` 开头工作空间名已按模式分流**：`prod/dev` 仍禁止；`forge` 已放宽，支持 `.dev-workspace`。
3. **`workspace.json` 是全局共享的**：位于 `~/.config/siyuan/`，多个开发目录的 kernel 都会写入同一个文件，末尾为"当前工作空间"。内置工作空间不应污染此文件。
4. **端口冲突**：dev 模式默认用固定端口 `6806`。多个开发目录同时运行时必然冲突，需要随机端口或可配置端口。
5. **工作空间锁**：`flock` 保证一个工作空间只被一个 kernel 使用，这点天然满足互不干扰的需求，无需额外改动。

## 核心原则

- 工坊模式使用独立的 `--mode forge` 标识，不复用 `dev` 模式
- 工坊模式工作空间路径约定为 `<项目根>/.dev-workspace`
- 对上游影响最小化：只修改我们自己的 fork 逻辑，不改变 API 语义
- 优先通过命令行参数解决问题，减少硬编码
- forge 模式下放宽安装目录限制，prod/dev 模式行为不变

# 三贤人历史管理改进执行跟踪 (TikTocTak)

> **目标**: 为三贤人实现差异化的历史管理策略：Melchior按对话会话（sessionId）隔离历史，Balthazar和Caspar保持所有对话的单一连续历史。
>
> **核心语义**: sessionId是对话级别的标识符，每次对话创建一个新session。Melchior应该知晓对话对象是哪一个用户但是专注于当前对话上下文，因此需要按sessionId隔离历史；Balthazar和Caspar则需要跨对话的连续记忆。
>

## 📋 核心原则

### 设计原则

1. **差异化管理**：三贤人根据其角色特性采用不同的历史管理策略
2. **向后兼容**：改动不应破坏现有的MAGI协调流程
3. **最小侵入**：优先在contextManager层面实现，避免大规模重构
4. **性能优先**：多会话历史管理不应显著影响响应性能

## 📊 技术调研摘要

### 当前实现分析

**文件**: `kernel/nerv/magi/sages/sage.go`

1. **Sage结构**:
   - 每个Sage实例包含一个`contextManager ContextManager`
   - contextManager负责管理对话历史

2. **ContextManager接口**:
   ```go
   type ContextManager interface {
       AddMessage(msg types.ContextMessage)
       GetMessages() []types.ContextMessage
       Clear()
       ApplyStrategy(strategy *config.ContextStrategy)
   }
   ```

3. **当前实现（contextManagerImpl）**:
   - 维护单一的`messages []types.ContextMessage`数组
   - 不区分会话，所有消息混在一起
   - 支持message_count策略（保留最近N条消息）

4. **sessionId传递链路**:
   - `Coordinator.CoordinateDecision(sessionId, ...)`
   - → `collector.CollectResponses(sessionId, ...)`
   - → `sage.SendMessage(sessionId, ...)`
   - 但在sage内部，sessionId未用于历史管理

5. **Session结构** (`kernel/nerv/magi/session/manager.go`):
   ```go
   type Session struct {
       ID           string                     // 会话ID (magi-{timestamp}-{random})
       CreatedAt    time.Time
       LastActiveAt time.Time
       UserID       string                     // 用户标识
       Metadata     map[string]interface{}
   }
   ```
   - Session包含UserID字段，可用于标识对话用户
   - 需要设计机制将UserID信息传递给Melchior

### 关键发现

1. **Melchior需求**:
   - 需要实现`map[string][]types.ContextMessage`结构
   - key为sessionId，value为该会话的历史
   - 需要会话级别的锁保护

2. **Balthazar/Caspar需求**:
   - 保持当前的单一历史实现
   - 可以复用现有的contextManagerImpl

3. **兼容性考虑**:
   - ContextManager接口可能需要扩展以支持sessionId参数
   - 或者在Sage层面处理会话路由，保持接口不变

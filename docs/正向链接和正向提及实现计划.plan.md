# 正向链接和正向提及 Dock 实现计划

## 需求概述

1. **正向链接 (Forwardlinks)**: 显示当前笔记中存在块引用的块列表，即"我引用了谁"
2. **正向提及 (Forward Mentions)**: 显示当前笔记中存在文本提及的块列表（与锚文本匹配的文档/块）
3. 外观与反向链接 Dock 保持一致

## 概念对比

| 概念 | 反向链接 (Backlink) | 正向链接 (Forwardlink) |
|------|---------------------|------------------------|
| 问题 | "谁引用了我？" | "我引用了谁？" |
| refs表查询条件 | `def_block_id = 当前块ID` | `root_id = 当前文档RootID` |
| 返回内容 | 引用来源块列表 | 引用目标块列表 |

### refs 表结构 (来自 Go 代码分析)

```go
// scanRefRows 中的字段顺序
ID              // 引用记录ID
DefBlockID      // 被引用块ID (定义块)
DefBlockParentID // 被引用块父ID
DefBlockRootID  // 被引用块所属文档ID
DefBlockPath    // 被引用块路径
BlockID         // 引用块ID (包含引用的块)
RootID          // 引用块所属文档ID
Box             // 笔记本ID
Path            // 路径
Content         // 锚文本内容
Markdown        // Markdown 内容
Type            // 引用类型
```

### 数据获取策略

**方案选择：使用 SQL API 前端实现**

由于目前后端没有现成的正向链接 API，我们可以：

1. **短期方案**：在前端使用 `/api/query/sql` 直接查询 refs 表
2. **长期方案**：后续可添加后端 API `/api/ref/getForwardlink` 以提升性能

**正向链接 SQL 查询**：
```sql
-- 获取当前文档引用的所有目标块（按文档分组）
SELECT DISTINCT 
    r.def_block_root_id,
    b.content,
    b.hPath,
    b.box
FROM refs AS r
INNER JOIN blocks AS b ON b.id = r.def_block_root_id
WHERE r.root_id = ?  -- 当前文档 rootID
ORDER BY b.hPath
```

**正向提及策略**：
- 获取当前文档的标题、命名、别名
- 搜索其他文档中包含这些关键词的块

```typescript
/**
 * 获取正向链接数据
 * @param rootId 当前文档 rootID
 */
export async function getForwardlinks(rootId: string): Promise<IForwardlinkData> {
    // 使用 SQL API 查询
    const sql = `
        SELECT DISTINCT 
            r.def_block_root_id,
            b.content,
            b.hPath,
            b.box,
            b.type
        FROM refs AS r
        INNER JOIN blocks AS b ON b.id = r.def_block_root_id
        WHERE r.root_id = '${rootId}'
        ORDER BY b.hPath
    `;
    
    const response = await fetchPost("/api/query/sql", { stmt: sql });
    return transformToTreeData(response.data);
}
```

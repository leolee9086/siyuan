## 1. 适用范围

### 1.1 适用场景

本规程适用于以下Go后端模块实现场景：

- **新模块开发**: 在kernel目录下创建新的Go模块
- **功能扩展**: 为现有模块添加新功能
- **跨平台实现**: 需要支持多平台的功能模块

### 1.2 不适用场景

以下场景不适用本规程：

- **Bug修复**: 应使用专门的bug修复规程
- **性能优化**: 应使用性能优化规程
- **代码重构**: 大规模重构应使用重构规程

### 1.3 核心目标

1. **功能正确**: 实现符合设计文档的功能需求
2. **跨平台兼容**: 支持Windows/Linux/macOS/iOS/Android
3. **高性能**: 在功能正确的前提下追求最优性能
4. **可维护性**: 代码结构清晰，便于后续维护

## 2. 文件组织结构

### 2.1 模块目录结构

#### 2.1.1 标准目录布局

```
kernel/模块名/
├── types.go              # 类型定义（接口、结构体、常量）
├── config.go             # 配置相关定义
├── 核心功能.go           # 主要功能实现
├── 核心功能_平台.go      # 平台特定实现（如需要）
└── 模块名_test.go        # 测试文件
```

#### 2.1.2 文件职责划分

- **types.go**: **应该**包含所有公共接口、结构体和常量定义
- **config.go**: **应该**包含配置结构体和默认值
- **功能文件**: **应该**按功能模块拆分，每个文件职责单一
- **测试文件**: **应该**与被测文件同目录，使用`_test.go`后缀

### 2.2 文件组织约束

#### 2.2.1 文件大小控制

- 单个文件**不宜**超过500行
- 单个函数**不宜**超过80行
- 超过限制时**应该**进行合理拆分

#### 2.2.2 依赖关系

- **不得**产生循环依赖
- **应该**保持依赖方向单一（从高层到低层）
- **不宜**在模块内部产生过多的跨文件依赖

## 3. 跨平台构建标签

### 3.1 构建标签使用规范

#### 3.1.1 平台特定文件命名

| 平台 | 文件后缀 | 构建标签 |
|------|----------|----------|
| Unix通用 | `_unix.go` | `//go:build darwin \|\| linux` |
| Windows | `_windows.go` | `//go:build windows` |
| 移动端 | `_mobile.go` | `//go:build ios \|\| android` |
| 通用回退 | `_fallback.go` | `//go:build !darwin && !linux && !windows` |

#### 3.1.2 构建标签格式

- **必须**使用`//go:build`语法（Go 1.17+）
- **不应**使用旧式`// +build`语法
- **应该**将构建标签放在文件首行，package声明之前

```go
//go:build darwin || linux

package 模块名
```

### 3.2 平台抽象设计

#### 3.2.1 接口抽象要求

- **应该**在`types.go`中定义平台无关的接口
- **应该**在平台特定文件中提供具体实现
- **不得**在通用代码中直接使用平台特定API

#### 3.2.2 平台实现示例结构

```
模块名/
├── io.go                    # 接口定义
├── io_mmap_unix.go          # //go:build darwin || linux
├── io_mmap_windows.go       # //go:build windows  
├── io_buffered_mobile.go    # //go:build ios || android
└── io_fallback.go           # 纯Go实现的通用回退
```

### 3.3 平台兼容性约束

- **必须**确保所有目标平台都有对应实现
- **应该**提供纯Go的回退实现
- **不得**遗漏任何目标平台的支持

## 4. 接口设计原则

### 4.1 接口定义规范

#### 4.1.1 接口粒度

- **应该**保持接口小而专注（单一职责）
- **不宜**定义超过5个方法的接口
- **应该**优先组合小接口而非定义大接口

#### 4.1.2 接口命名

- **应该**使用动词或动词短语命名接口（如`Reader`、`Writer`）
- **不应**使用`I`前缀（如`IReader`）
- **应该**接口名反映其行为而非实现

### 4.2 接口设计约束

#### 4.2.1 依赖倒置

- **应该**依赖接口而非具体实现
- **应该**在使用方定义接口（消费者定义）
- **不宜**导出仅内部使用的接口

#### 4.2.2 接口兼容性

- **不得**修改已发布接口的方法签名
- **应该**通过新增接口扩展功能
- **不应**在接口中添加可选方法

## 5. 错误处理规范

### 5.1 错误定义

#### 5.1.1 错误类型

- **应该**使用`errors.New`定义简单错误
- **应该**使用自定义错误类型携带上下文信息
- **不宜**使用字符串拼接构造错误消息

```go
// 推荐：定义错误变量
var ErrNotFound = errors.New("记录未找到")

// 推荐：自定义错误类型
type ValidationError struct {
    Field   string
    Message string
}

func (e *ValidationError) Error() string {
    return fmt.Sprintf("验证失败: %s - %s", e.Field, e.Message)
}
```

#### 5.1.2 错误命名

- **应该**使用`Err`前缀命名错误变量
- **应该**使用`Error`后缀命名错误类型
- **不应**使用模糊的错误名称

### 5.2 错误处理

#### 5.2.1 错误传播

- **应该**使用`fmt.Errorf`包装错误并添加上下文
- **应该**使用`%w`动词保留原始错误链
- **不得**丢弃错误而不处理

```go
// 推荐：包装错误
if err != nil {
    return fmt.Errorf("加载配置失败: %w", err)
}
```

#### 5.2.2 错误检查

- **应该**使用`errors.Is`检查特定错误
- **应该**使用`errors.As`提取错误类型
- **不应**使用字符串比较检查错误

### 5.3 错误处理约束

- **不得**使用panic处理可恢复的错误
- **不应**忽略函数返回的错误
- **应该**在API边界处记录错误日志

## 6. 测试覆盖要求

### 6.1 测试文件组织

#### 6.1.1 测试文件命名

- **必须**使用`_test.go`后缀
- **应该**与被测文件同目录
- **应该**测试文件名与被测文件对应

#### 6.1.2 测试函数命名

- **必须**使用`Test`前缀
- **应该**函数名描述测试场景
- **应该**使用表驱动测试组织多个用例

```go
func TestCalculateDistance_Euclidean(t *testing.T) { }
func TestCalculateDistance_Cosine(t *testing.T) { }
```

### 6.2 测试覆盖标准

#### 6.2.1 覆盖率要求

- 核心功能**应该**达到80%以上覆盖率
- 公共API**必须**有对应测试
- 错误处理路径**应该**有测试覆盖

#### 6.2.2 测试类型要求

- **必须**编写单元测试验证核心逻辑
- **应该**编写基准测试验证性能
- **不宜**在单元测试中依赖外部资源

### 6.3 测试约束

#### 6.3.1 测试独立性

- **必须**确保测试可独立运行
- **不得**测试之间存在执行顺序依赖
- **应该**使用`t.Parallel()`支持并行测试

#### 6.3.2 测试数据

- **应该**使用`testdata`目录存放测试数据
- **不应**在测试中硬编码大量数据
- **应该**测试边界条件和异常情况

## 7. 文档注释要求

### 7.1 包注释

#### 7.1.1 包文档要求

- **必须**在包的主文件中添加包注释
- **应该**说明包的用途和主要功能
- **应该**提供简单的使用示例

```go
// Package vamana 实现了Vamana图索引算法。
//
// Vamana是一种高效的近似最近邻搜索算法，支持动态插入和删除。
// 本包提供了索引构建、搜索和持久化功能。
//
// 基本用法:
//
//     index := vamana.New(config)
//     index.Build(vectors)
//     results := index.Search(query, k)
package vamana
```

### 7.2 导出符号注释

#### 7.2.1 函数注释

- **必须**为所有导出函数添加注释
- **应该**说明函数的作用、参数和返回值
- **应该**说明可能返回的错误

```go
// Search 在索引中搜索与查询向量最相似的k个向量。
//
// 参数:
//   - query: 查询向量，维度必须与索引维度一致
//   - k: 返回结果数量
//
// 返回最相似的k个向量ID及其距离。如果索引为空，返回空切片。
// 当查询向量维度不匹配时，返回ErrDimensionMismatch错误。
func (idx *Index) Search(query []float32, k int) ([]Result, error) {
```

#### 7.2.2 类型注释

- **必须**为所有导出类型添加注释
- **应该**说明类型的用途和使用场景
- **应该**说明重要字段的含义

```go
// Config 定义Vamana索引的配置参数。
type Config struct {
    // Dimension 向量维度，必须大于0
    Dimension int
    
    // MaxDegree 图中每个节点的最大出度
    MaxDegree int
    
    // SearchListSize 搜索时的候选列表大小
    SearchListSize int
}
```

### 7.3 注释约束

- **不得**为导出符号省略注释
- **不应**添加与代码重复的无意义注释
- **应该**保持注释与代码同步更新

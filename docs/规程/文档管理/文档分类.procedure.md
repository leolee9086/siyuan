# 文档分类规程
此规程已经封固,未经允许禁止修改
## 适用场景

本规程适用于以下文档分类场景：

1. 新增文档需要确定存放位置
2. 文档数量增长需要建立分类体系
3. 评估现有文档是否放置在正确位置
4. 设计或调整项目文档目录结构

## 文档分类体系

### 一级分类

项目文档应按以下一级分类组织：

#### 1. ttt/ - 任务跟踪文档

- **用途**：记录任务的执行过程、进度和结果，包括所有具体行动规划
- **文件格式**：`*.ttt.md`
- **说明**：根据元规程要求，所有具体行动规划（包括实现计划、优化计划、迁移计划等）都应以ttt文档形式存在

#### 2. 规程/ - 规程文档

- **用途**：定义工作流程、规范和标准
- **文件格式**：`*.procedure.md`
- **说明**：规程应简短专注，单个规程不超过300行

#### 3. 设计/ - 设计文档

- **用途**：功能设计、架构设计、方案设计（设计说明，非行动计划）
- **子分类**：功能设计、架构设计、方案设计
- **说明**：描述"是什么"和"为什么"，关注方案设计和架构说明

#### 4. 技术文档/ - 技术文档

- **用途**：技术说明、API文档、流程文档
- **子分类**：架构、流程、API
- **说明**：面向开发者的技术参考资料

#### 5. 分析/ - 分析文档

- **用途**：性能分析、代码分析、问题分析
- **子分类**：性能分析、代码分析、问题分析
- **说明**：分析结果和结论性文档

#### 6. 归档/ - 已完成或过时的文档

- **用途**：保存历史文档，避免删除重要信息
- **说明**：不确定是否有用的文档应归档而非删除

### 二级分类

根据文档内容进一步细分：

#### 设计类二级分类

- **设计/功能设计/** - 新功能的设计文档（设计说明，非实现计划）
- **设计/架构设计/** - 系统架构、模块架构设计
- **设计/方案设计/** - 特定问题的解决方案

#### 技术文档类二级分类

- **技术文档/架构/** - 架构说明文档
- **技术文档/流程/** - 业务流程、技术流程说明
- **技术文档/API/** - API接口文档

#### 分析类二级分类

- **分析/性能分析/** - 性能瓶颈、优化效果分析
- **分析/代码分析/** - 代码结构、质量分析
- **分析/问题分析/** - 问题排查、根因分析

### 分类层级规范

1. **不应超过3层**
   - 目录层级不应超过3层
   - 过深的层级不利于查找
   - 保持结构简洁明了

2. **不宜过度细分**
   - 分类应适度，不宜过细
   - 过细的分类反而增加查找难度
   - 考虑未来扩展性

## 分类判断标准

### 设计文档 vs 行动计划

这是最容易混淆的分类，判断标准如下：

#### 设计文档（归入 [`设计/`](../../设计/) 目录）

- 描述"是什么"和"为什么"
- 关注方案设计和架构说明
- 不包含具体执行步骤和进度跟踪
- 示例：功能设计说明、架构设计文档、方案对比分析

#### 行动计划（归入 [`ttt/`](../../ttt/) 目录）

- 描述"怎么做"和"做到哪"
- 关注具体执行和进度跟踪
- 包含任务目标、执行步骤、进度状态
- 示例：实现计划、优化计划、迁移计划

**重要**：所有实现计划、优化计划、迁移计划等具体行动规划文档，都应归入 [`ttt/`](../../ttt/) 目录，以 `.ttt.md` 格式存在。

### 技术文档 vs 设计文档

#### 技术文档（归入 [`技术文档/`](../../技术文档/) 目录）

- 面向开发者的技术参考
- 说明现有系统的技术实现
- 包含API文档、流程说明
- 示例：模块技术文档、API接口文档、业务流程说明

#### 设计文档（归入 [`设计/`](../../设计/) 目录）

- 面向设计阶段的方案说明
- 说明为什么这样设计
- 包含设计决策和方案对比
- 示例：新功能设计、架构设计、方案设计

### 分析文档 vs 设计文档

#### 分析文档（归入 [`分析/`](../../分析/) 目录）

- 对现状的分析和评估
- 发现问题和瓶颈
- 提供数据和结论
- 示例：性能瓶颈分析、代码质量分析、问题根因分析

#### 设计文档（归入 [`设计/`](../../设计/) 目录）

- 基于分析结果的解决方案
- 设计新的功能或架构
- 提供设计方案和决策
- 示例：基于分析的优化方案设计

## 特殊情况处理

### 计划文档迁移

根据元规程要求："任何具体行动规划而非设计的说明文档,能且仅能以ttt文档的形式进行追踪"

所有计划类文档应按以下规则迁移：

| 原分类 | 原格式 | 目标分类 | 目标格式 | 说明 |
|--------|--------|----------|----------|------|
| `计划/实现计划/` | `.plan.md` | `ttt/` | `.ttt.md` | 功能实现的具体行动计划 |
| `计划/优化计划/` | `.plan.md` | `ttt/` | `.ttt.md` | 性能优化的具体行动计划 |
| `计划/迁移计划/` | `.plan.md` | `ttt/` | `.ttt.md` | 技术迁移的具体行动计划 |
| 任何 `.plan.md` | `.plan.md` | `ttt/` | `.ttt.md` | 所有计划文档统一迁移 |

**注意**：不再创建 `docs/计划/` 目录，所有计划类文档应归入 [`docs/ttt/`](../../ttt/) 目录。

### 不确定类型的文档

如果无法确定文档类型：

1. **阅读文档内容**
   - 查看文档的主要内容和目的
   - 判断文档的受众和用途

2. **参考文档标题**
   - 标题通常能反映文档类型
   - 注意关键词：设计、计划、分析、说明

3. **咨询文档作者**
   - 与文档作者确认文档用途
   - 了解文档的预期读者

4. **临时归档**
   - 实在无法确定时，先移至归档目录
   - 标记为待分类，后续再处理

### 跨类别文档

如果文档包含多种类型内容：

1. **拆分文档**
   - 将不同类型内容拆分为独立文档
   - 每个文档归入对应分类

2. **选择主要类型**
   - 根据文档的主要内容确定分类
   - 在文档中添加说明，指向相关文档

3. **使用链接关联**
   - 在文档间建立链接关系
   - 便于读者查找相关内容

## 分类验证清单

完成文档分类后，使用以下清单验证：

- [ ] 文档放置在正确的一级分类目录
- [ ] 如有二级分类，选择了正确的子目录
- [ ] 目录层级不超过3层
- [ ] 设计文档和行动计划已正确区分
- [ ] 所有 `.plan.md` 文档已归入 [`ttt/`](../../ttt/) 目录
- [ ] 文档类型与目录分类一致
- [ ] 不确定的文档已标记或归档

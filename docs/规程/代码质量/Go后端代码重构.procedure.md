## 1. 适用范围

### 1.1 适用场景

本规程适用于以下Go后端代码重构场景：

- **目录结构调整**: 将散落文件迁移到子目录，优化项目结构
- **常量归集**: 将分散的常量统一到专门文件
- **接口统一**: 统一不一致的API签名，消除重复定义
- **Package名变更**: 修改package名称并更新所有引用
- **代码整理**: 提取公共逻辑，消除重复代码

### 1.2 不适用场景

以下场景不适用本规程：

- **功能重构**: 涉及业务逻辑变更的重构应使用专门的规程
- **性能优化**: 以性能为目的的代码调整应使用性能优化规程
- **新模块开发**: 新功能开发有独立的开发规程

### 1.3 核心目标

1. **功能不变**: 重构过程中不得改变代码原有行为和外部接口
2. **编译通过**: 重构后的代码必须能够正常编译
3. **测试通过**: 所有现有测试必须继续通过
4. **依赖正确**: 确保import路径和包引用正确更新

## 2. 目录结构调整

### 2.1 迁移时机

#### 2.1.1 触发条件

- 目录下文件超过10个时**应该**评估是否需要子目录
- 存在明显职责分组的文件时**应该**按职责分组存放
- 跨模块引用混乱时**不宜**立即迁移，应先理清依赖关系

#### 2.1.2 迁移优先级

- **应该**优先迁移独立性高的功能模块
- **应该**优先整理工具类和辅助函数
- **不宜**在发布前进行大规模目录调整

### 2.2 迁移策略

#### 2.2.1 按职责分组

- **应该**将同一功能的文件放在同一子目录
- **应该**保持单一职责原则
- **不得**将紧密耦合的文件拆分到不同目录

```
// 推荐：按职责分组
kernel/vectordb/
├── vamana/              # Vamana索引实现
│   ├── index.go
│   ├── search.go
│   └── vamana_test.go
└── hnsw/                # HNSW索引实现
    ├── index.go
    ├── build.go
    └── hnsw_test.go
```

#### 2.2.2 保留兼容性

- **应该**在迁移后保留旧路径的兼容性导入（过渡期）
- **应该**使用类型别名或重导出保持API兼容
- **不得**在没有过渡期的情况下直接删除旧路径

```go
// 旧文件保持兼容性导出（过渡期）
// kernel/vectordb/old_path.go

// @deprecated 请使用 'kernel/vectordb/vamana' 包
package oldpath

import "kernel/vectordb/vamana"

type Index = vamana.Index
type Config = vamana.Config
```

### 2.3 迁移约束

#### 2.3.1 依赖处理

- **必须**同步更新所有import路径
- **不得**产生循环依赖
- **应该**保持依赖方向单一

#### 2.3.2 构建标签保留

- **必须**保留原文件的构建标签（`//go:build`）
- **应该**在迁移后验证各平台构建
- **不得**丢失平台特定的实现文件

## 3. 常量归集

### 3.1 归集时机

#### 3.1.1 触发条件

- 同一常量在多个文件中重复定义时**应该**归集
- 魔法数值散落在多处时**应该**提取为常量
- 配置相关的常量超过5个时**应该**集中管理

#### 3.1.2 归集优先级

- **应该**优先归集错误码和状态码
- **应该**优先归集配置默认值
- **不宜**归集仅单个文件使用的局部常量

### 3.2 归集策略

#### 3.2.1 按类别分组

- **应该**将相关常量组织在const块中
- **应该**使用iota定义枚举类型的常量
- **不得**将所有常量无差别地堆放在一个文件中

```go
// 推荐：按类别分组
package constants

// 错误码
const (
    ErrCodeNotFound     = 404
    ErrCodeInvalidParam = 400
    ErrCodeInternal     = 500
)

// 默认配置值
const (
    DefaultMaxDegree      = 32
    DefaultSearchListSize = 100
    DefaultDimension      = 128
)

// 限制值
const (
    MaxVectorDimension = 65535
    MaxIndexSize       = 1 << 30
)
```

#### 3.2.2 命名规范

- **应该**使用有意义的常量名，避免缩写
- **应该**使用驼峰命名法（Exported）或全大写下划线（内部）
- **不得**使用与标准库冲突的名称

### 3.3 归集约束

#### 3.3.1 可见性控制

- **应该**根据使用范围决定导出与否
- **不宜**将所有常量都导出为公共API
- **不得**为了归集而改变常量的可见性导致破坏封装

#### 3.3.2 类型安全

- **应该**为相关常量定义自定义类型
- **应该**使用类型化的常量而非裸类型
- **不宜**在需要类型区分的地方使用无类型常量

```go
// 推荐：类型化常量
type ErrorCode int

const (
    ErrNotFound     ErrorCode = 404
    ErrInvalidParam ErrorCode = 400
    ErrInternal     ErrorCode = 500
)
```

## 4. 接口统一

### 4.1 统一时机

#### 4.1.1 触发条件

- 相似功能使用不同方法签名时**应该**统一
- 接口定义分散在多处时**应该**集中定义
- 实现相同接口但方法名不一致时**应该**统一

#### 4.1.2 统一优先级

- **应该**优先统一公共API接口
- **应该**优先统一核心数据结构的接口
- **不宜**统一仅内部使用的私有接口

### 4.2 统一策略

#### 4.2.1 提取公共接口

- **应该**在types.go或interfaces.go中定义公共接口
- **应该**保持接口小而专注
- **不得**创建大而全的万能接口

```go
// 推荐：提取公共接口
package vectordb

// Index 定义向量索引的通用接口
type Index interface {
    // Insert 插入向量，返回向量ID
    Insert(vector []float32) (uint64, error)
    
    // Search 搜索最近邻，返回k个结果
    Search(query []float32, k int) ([]SearchResult, error)
    
    // Delete 删除指定ID的向量
    Delete(id uint64) error
    
    // Close 关闭索引，释放资源
    Close() error
}
```

#### 4.2.2 适配器模式

- **应该**使用适配器模式统一不兼容的接口
- **应该**保持适配器的轻量级
- **不得**让适配器引入额外的复杂性

```go
// 适配器示例
type VamanaAdapter struct {
    inner *vamana.Index
}

func (a *VamanaAdapter) Insert(vector []float32) (uint64, error) {
    return a.inner.Insert(vector)
}

func (a *VamanaAdapter) Search(query []float32, k int) ([]SearchResult, error) {
    return a.inner.Search(query, k)
}
```

### 4.3 统一约束

#### 4.3.1 向后兼容

- **不得**修改已发布接口的方法签名
- **应该**通过新增接口扩展功能
- **应该**提供迁移路径给调用方

#### 4.3.2 文档同步

- **必须**更新接口注释说明其用途
- **应该**在接口变更处添加@deprecated标记
- **不得**遗漏接口方法的文档注释

## 5. Package名变更

### 5.1 变更时机

#### 5.1.1 触发条件

- package名与实际功能不符时**应该**变更
- package名与标准库或其他包冲突时**应该**变更
- 合并或拆分模块时需要**应该**相应调整package名

#### 5.1.2 变更约束

- **不宜**频繁变更package名
- **不得**在没有过渡期的情况下直接变更
- **应该**评估对下游使用者的影响

### 5.2 变更策略

#### 5.2.1 渐进式迁移

- **应该**先创建新package并复制代码
- **应该**保留旧package作为兼容性包装
- **应该**在文档中明确标注废弃信息

```go
// 旧package（过渡期）
// kernel/oldname/oldname.go

// @deprecated 此包已废弃，请使用 kernel/newname
package oldname

import "kernel/newname"

// 重导出所有公共符号
type Client = newname.Client
var NewClient = newname.NewClient
```

#### 5.2.2 引用更新

- **必须**更新所有import语句
- **必须**更新所有限定符引用（如oldname.Func）
- **应该**使用IDE或工具批量更新

### 5.3 变更约束

#### 5.3.1 构建验证

- **必须**确保变更后代码能够编译
- **必须**运行所有测试验证功能正常
- **不得**提交有编译错误的代码

#### 5.3.2 版本管理

- **应该**在CHANGELOG中记录package名变更
- **应该**遵循语义化版本规范
- **不宜**在patch版本中变更package名

## 6. 验证要求

### 6.1 编译验证

#### 6.1.1 本地编译

- **必须**执行 `go build ./...` 验证所有包可编译
- **必须**验证所有目标平台的构建（如有构建标签）
- **不得**忽略编译警告

#### 6.1.2 交叉编译

- **应该**验证Windows/Linux/macOS构建
- **应该**验证移动端构建（如适用）
- **不得**遗漏任何目标平台

```bash
# 验证各平台构建
GOOS=windows go build ./...
GOOS=linux go build ./...
GOOS=darwin go build ./...
```

### 6.2 测试验证

#### 6.2.1 单元测试

- **必须**执行 `go test ./...` 确保所有测试通过
- **必须**检查是否有测试因重构而失效
- **不得**跳过失败的测试

#### 6.2.2 回归测试

- **应该**运行集成测试验证整体功能
- **应该**验证关键路径的性能没有退化
- **不宜**仅依赖单元测试

```bash
# 运行测试并生成覆盖率报告
go test -race -coverprofile=coverage.out ./...
go tool cover -html=coverage.out -o coverage.html
```

### 6.3 静态检查

#### 6.3.1 Lint检查

- **必须**运行 `go vet ./...` 检查潜在问题
- **应该**运行golangci-lint等工具进行全面检查
- **不得**引入新的lint错误

#### 6.3.2 格式化检查

- **必须**确保代码经过 `gofmt` 格式化
- **应该**使用 `goimports` 整理import
- **不得**提交未格式化的代码

```bash
# 格式化检查
gofmt -l .
goimports -l .

# 自动修复
gofmt -w .
goimports -w .
```

### 6.4 验证清单

重构完成后，**必须**确认以下事项：

- [ ] 所有包可以正常编译（`go build ./...`）
- [ ] 所有测试通过（`go test ./...`）
- [ ] 无竞态条件（`go test -race ./...`）
- [ ] 静态检查通过（`go vet ./...`）
- [ ] 代码已格式化（`gofmt`）
- [ ] import已整理（`goimports`）
- [ ] 文档已更新（如有必要）

# 前端组件迁移规程

> **版本**: 1.0.0
> **最后更新**: 2026-02-28
> **适用范围**: 将原型/验证目录中的前端实现迁移到正式源码目录

## 1. 适用范围

### 1.1 适用场景

- 将 `toread/` 或其他验证目录中的前端代码迁移到 `app/src/` 正式目录
- 迁移过程中需要同时完成 JS → TS 转换、架构整理、问题修复
- 原型代码与正式代码存在功能重叠需要合并

### 1.2 与其他规程的关系

- [前端模块功能剥离规程](./前端模块功能剥离.procedure.md) — 从已有模块剥离子功能
- [代码拆分与模块化规程](./代码拆分与模块化.procedure.md) — 文件级拆分
- 本规程关注跨目录迁移与架构升级，与上述规程冲突时以本规程为准

### 1.3 不适用场景

- 正式目录内部的重构（使用代码拆分规程）
- 纯粹的文件移动（无架构变更）

---

## 2. 迁移前分析要求

### 2.1 源码清单

- **应该**列出原型目录中所有文件及其职责
- **应该**识别原型代码与正式代码之间的功能重叠
- **不得**未经分析直接开始迁移

### 2.2 问题识别

- **应该**在迁移前完成现状调查，记录已知问题及优先级
- **应该**区分"迁移时修复"和"迁移后修复"的问题
- **不宜**在迁移过程中引入与迁移无关的功能变更

### 2.3 目标目录规划

- **应该**在迁移前确定目标目录结构
- **不得**将所有文件平铺到单一目录
- **应该**按职责分层：类型定义、服务层、UI 组件、工具函数

---

## 3. 迁移成果特征要求

### 3.1 语言与类型安全

- **不得**迁移后的文件保留 `.js` 扩展名（应转为 `.ts` 或 `.vue`）
- **应该**所有公共接口具有明确的 TypeScript 类型标注
- **不得**使用 `any` 类型绕过类型检查（`unknown` + 类型守卫除外）
- **不得**存在 `@ts-ignore` 或 `@ts-expect-error` 注释

### 3.2 导入路径

- **不得**迁移后的代码引用 `toread/` 或其他原型目录
- **不得**使用相对路径穿越超过 3 层父目录（`../../../` 以上应使用路径别名）
- **应该**使用项目已有的路径别名和模块导入约定

### 3.3 架构一致性

- **不得**同一功能存在两套并行实现（迁移时必须选择一套并删除另一套）
- **不得**保留未使用的接口定义、类型、函数（死代码）
- **应该**状态管理方案与项目现有模式一致
- **不得**在组件中直接进行网络请求（应通过服务层）

### 3.4 代码清洁度

- **不得**保留 `console.log` 等调试代码
- **不得**存在硬编码的用户可见字符串（应接入 i18n）
- **不得**存在硬编码的配置值（应从配置传入）
- **不得**保留注释掉的代码块

### 3.5 性能

- **不得**使用 `MutationObserver` 监听 `document.body` 全子树
- **不宜**在高频回调中创建临时 DOM 元素
- **应该**模块级缓存具有清理机制

### 3.6 旧代码清理

- **不得**迁移完成后原型目录中仍存在已迁移的文件
- **不得**正式目录中保留被替代的旧版实现
- **应该**更新所有引用旧路径的代码

---

## 4. 备份要求

- **不得**在未备份的情况下开始修改正式目录中的已有文件
- **应该**使用 `.backup` 后缀备份将被修改的文件
- **应该**在迁移完成且构建验证通过后删除备份文件

---

## 5. 验收要求

- **应该**通过 `pnpm build` 无编译错误
- **应该**通过项目 lint 检查
- **不得**存在指向已删除文件的悬空引用
- **应该**迁移后的功能与迁移前行为一致（可通过手动测试验证）

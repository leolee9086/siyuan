# 参考源码拉取规程

## 适用场景

本规程适用于需要拉取外部仓库进行阅读、对比、选型或实现调研的场景，包括但不限于 CLI 客户端、编辑器组件、Diff 组件与相关工具链。

## 核心目标

1. 参考源码可复查、可复用、可追溯。
2. 拉取过程不污染主仓库版本状态。
3. 参考内容与业务源码严格隔离。

## 强制约束

### 1. 落盘位置

- **必须**将所有外部参考仓库拉取到 `toread/_refs/` 下。
- **不得**将参考仓库放在 `app/`、`docs/`、仓库根目录或其他未忽略目录。
- **不宜**继续使用 `tmp/` 作为长期存放目录；临时目录在任务结束前应清理。

### 2. Git 隔离

- **必须**确保主仓库 `.gitignore` 已忽略 `toread/`。
- **必须**在拉取前后检查主仓库状态：`git status --short`。
- **不得**通过 `git submodule add` 引入参考仓库。
- **不得**把参考仓库内容加入主仓库提交。

### 3. 安全边界

- **不得**在未知参考仓库中直接执行不受控脚本。
- **不应**在主项目环境中执行参考仓库的安装脚本（如 `postinstall`）而不做隔离。

## 标准流程

1. 准备目录  
   确认 `toread/_refs/` 存在，不存在则创建。

2. 目标命名  
   目录名应稳定且可识别，优先使用仓库名；若重名，使用 `组织名-仓库名`。

3. 拉取或更新  
   新仓库：`git clone <repo-url> toread/_refs/<repo-name>`  
   已存在仓库：`git -C toread/_refs/<repo-name> fetch --all --prune` 并按需 `pull --ff-only`。

4. 来源校验  
   记录并核对远程地址：`git -C toread/_refs/<repo-name> remote get-url origin`。

5. 主仓库复核  
   再次执行 `git status --short`，确认未新增参考仓库相关跟踪项。

6. 调研留痕  
   在对应调研文档或 ttt 中记录：仓库 URL、分支/Tag、提交哈希、拉取日期、用途。

## 验收清单

- [ ] 参考仓库全部位于 `toread/_refs/`
- [ ] 主仓库 `git status --short` 未出现参考源码目录污染
- [ ] 每个参考仓库都能查询到明确 `origin`
- [ ] 调研文档已记录来源与版本信息
- [ ] 未留存无用的临时目录（如 `tmp/`）

## 常见违规与修正

### 违规 1：拉到了 `tmp/` 或根目录

- 修正：移动到 `toread/_refs/`，并清理旧目录。

### 违规 2：主仓库出现 `?? tmp/` 或其他参考目录

- 修正：先迁移到忽略目录，再复核 `.gitignore` 与 `git status --short`。

### 违规 3：误用了 submodule

- 修正：移除 submodule 配置并改为普通忽略目录拉取。

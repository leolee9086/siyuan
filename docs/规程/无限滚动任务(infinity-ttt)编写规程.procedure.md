## 1. 适用场景

适用于永远不会"完成"的持续性任务，例如：
- 前端模块维护（如 ttt 目录维护）
- 内核性能持续优化
- 文档整理与规范化
- 代码质量持续改进

判断标准：如果一个任务没有明确的"全部完成"终态，而是持续产生新的子任务，则应使用本规程。

---

## 2. 与有限任务 ttt 的差异

### 2.1 文件后缀

- 有限任务：`.ttt.md`
- 无限滚动任务：`.infinity.ttt.md`

### 2.2 文档头部

头部必须明确标注任务类型：

```markdown
# [项目名称] 执行跟踪 (TikTocTak)

> **任务类型**: 🔄 无限滚动任务
> **目标**: [持续性目标描述]
```

### 2.3 生命周期

- 文档本身永不标记为"已完成"，永不归档
- 不参与"已完成文档清理"流程
- 文档内部的子任务仍然正常流转和归档

### 2.4 配合文档处理

当无限滚动任务产出配合文档时：
- **一次性产出物**（如调查报告、临时分析）：跟随对应的子任务归档或删除
- **持续参考价值的文档**（如规程、设计文档）：留在原位，不随子任务归档

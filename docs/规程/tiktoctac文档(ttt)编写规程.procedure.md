# TikTocTak 文档编写与维护规程

> **规程类型**: 执行跟踪文档编写  
> **适用场景**: 多阶段任务的滚动执行跟踪文档（TikTocTak）  
> **版本**: 1.0.0  
> **最后更新**: 2026-01-26

---

## 1. 规程定位

### 1.1 规程范围

本规程**仅**规范 TikTocTak 文档的编写和维护方式，包括：
- 文档必需章节和格式
- 任务状态标记规则
- 任务流转和归档流程
- 文档更新和维护规则

本规程**不包含**：
- 具体任务的执行方法（应参考对应的任务类型规程）
- 性能优化的验证方法（应参考性能优化规程）
- 代码编写规范（应参考代码规程）

### 1.2 适用场景

- 多阶段任务项目（≥3个阶段）
- 需要长期跟踪的任务（跨度 ≥1周）
- 涉及多个模块的复杂任务
- 需要团队协作的项目

## 2. 文档结构规范

### 2.1 必需章节

TikTocTak 文档**不得**缺少以下章节：

#### 2.1.1 文档头部

```markdown
# [项目名称]执行跟踪 (TikTocTak)

> **目标**: [清晰描述目标，包含量化指标]
>
> **流程**: 这是一个滚动更新的执行路线图。
> 1. 从"近期计划"中认领一个任务。
> 2. 完成开发和测试。
> 3. 将其移动到"已归档/已完成"区域。
> 4. 将"中期计划"中的条目提升到"近期计划"。
```

**规则**:
- **不得**省略目标描述
- **不得**缺少量化指标
- **不应**使用模糊表述

#### 2.1.2 核心原则章节

必须包含项目的核心原则和验证检查清单。

**规则**:
- **不得**删除核心原则
- **不得**省略验证检查清单

#### 2.1.3 维护说明章节

```markdown
## ℹ️ 如何维护此文档

1. **完成归档**：任务完成后，**必须**剪切粘贴到【已归档】列表，并打上 `[x]` 和日期。
2. **补充弹药**：当【近期计划】空了，从【中期计划】里挑选任务挪上去。
3. **因地制宜**：如果发现计划不合理，随时修改或删除。
4. **数据驱动**：用数据说话，不凭感觉。
```

**规则**:
- **不得**省略维护说明
- **不应**删除归档流程说明

### 2.2 任务分类章节

#### 2.2.1 近期计划（必需）

```markdown
## 🟢 近期计划 

- [ ] **Phase X: [任务名称] (优先级)**
  - **背景**: [为什么要做]
  - **行动**: [具体步骤]
  - **验收标准**: [完成标准]
  - **参考文档**: [相关链接]
```

**规则**:
- **不得**在近期计划中放置超过5个任务
- **不得**省略验收标准
- **不应**使用模糊的行动描述

#### 2.2.2 中期计划（推荐）

```markdown
## 🟡 中期计划 

- [ ] **Phase X: [任务名称] (优先级)**
  - **背景**: [优化背景]
  - **行动**: [主要步骤]
```

**规则**:
- **不应**在中期计划中放置超过10个任务

#### 2.2.3 远期计划（可选）

```markdown
## 🔴 远期计划 

- [ ] **Phase X: [任务名称] (优先级)**
  - **愿景**: [长期目标]
```

**规则**:
- **不应**将远期计划作为"垃圾桶"

### 2.3 归档章节（必需）

```markdown
## 🏁 已归档/已完成

- [x] **Phase X: [任务名称]** [已完成 YYYY-MM-DD]
  - **背景**: [优化背景]
  - **完成情况**: [完成内容]
  - **成果文件**: [文件列表]
  - **参考文档**: [相关链接]
```

**规则**:
- **不得**将未完成的任务标记为已完成
- **不应**省略成果文件列表
- **不宜**删除已归档的任务

## 3. 任务状态管理

### 3.1 状态标记

- `[ ]` - **待办**: 任务尚未开始
- `[-]` - **进行中**: 任务正在执行
- `[x]` - **已完成**: 任务已完成

**规则**:
- **不得**同时有多个任务标记为"进行中"
- **不得**跳过"进行中"状态直接标记为"已完成"

### 3.2 优先级标记

- **P0**: 关键任务，必须立即完成
- **P1**: 重要任务，应尽快完成
- **P2**: 一般任务，可以延后

**规则**:
- **不得**在近期计划中放置超过2个P0任务
- **不应**将P2任务放在近期计划中

---

## 4. 任务流转规则

### 4.1 任务认领

1. 从"近期计划"中选择一个任务
2. 将任务状态改为 `[-]`

**规则**:
- **不得**同时认领多个任务
- **不应**认领超出能力范围的任务

### 4.2 任务执行

按照任务的"行动"章节逐步实施。

**规则**:
- **不得**跳过关键步骤
- **不应**在未满足验收标准的情况下完成任务

### 4.3 任务归档

1. 确认满足验收标准
2. 剪切任务内容
3. 粘贴到"已归档/已完成"章节顶部
4. 更新状态为 `[x]`，添加完成日期
5. 补充完成情况和成果文件

**规则**:
- **不得**在未满足验收标准的情况下归档
- **不得**省略成果文件列表
- **不应**修改原始任务描述
- **不宜**延迟归档

---

## 5. 文档维护规则

### 5.1 滚动更新

#### 5.1.1 近期计划补充

当近期计划中的任务少于3个时：
1. 从中期计划中选择1-2个任务
2. 评估任务的可行性
3. 移动到近期计划

**规则**:
- **不得**让近期计划长期为空
- **不应**一次性移动超过3个任务

#### 5.1.2 计划调整

当发现计划不合理时：
1. 评估任务的实际价值
2. 删除不切实际的任务
3. 拆分过大的任务
4. 合并相似的任务

**规则**:
- **不得**死板遵守原计划
- **不应**频繁大幅调整（每周最多1次）

### 5.2 文档质量检查

每周应检查：
- [ ] 近期计划中的任务是否清晰可执行
- [ ] 验收标准是否完整
- [ ] 已归档任务是否包含完整记录
- [ ] 文档链接是否有效

---

## 6. 规程遵守

### 6.1 强制性规则（不得违反）

1. 未满足验收标准的任务不得标记为已完成
2. 不得省略成果文件列表
3. 不得同时有多个任务标记为"进行中"

### 6.2 建议性规则（不应违反）

1. 不应在近期计划中放置超过5个任务
2. 不应将P2任务放在近期计划中
3. 不应省略成果文件列表

### 6.3 原则性规则（不宜违反）

1. 不宜延迟归档
2. 不宜删除已归档的任务
3. 不宜频繁调整计划

### 6.4 规程异议

当规程与实际情况严重不符时：
1. 记录异议内容
2. 分析不适用的原因
3. 提出改进建议
4. 暂停执行，等待规程更新

**规则**:
- **不得**在未解决异议的情况下继续执行
- **不应**私自修改规程

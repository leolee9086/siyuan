# D5A 查看器持续演进执行跟踪 (TikTocTak)

> **目标**: 建成可移植的高性能本地 CLI 与内嵌 WebUI；以统一场景中间层查看、检查和互转 D5A、SKP 及常见 3D 模型格式，以独立的统一材质文档解析、预览和制作 D5M。可解析部分的代表性样例应正确显示几何、UV 和 PBR 纹理，150 万三角面模型保持可交互，并对模型转换与材质往返分别输出可审计的保真报告。
>
> **流程**: 这是一个滚动更新的执行路线图。
> 1. 从“近期计划”中认领且只认领一个任务。
> 2. 记录样例、推断、代码变更和可复现验证结果。
> 3. 满足验收标准后移入“已归档/已完成”。
> 4. 再从中期计划提升下一项任务。

## 核心原则与验证清单

- 以真实可解析 D5A 样例和文件内数据为依据，不用缩略图猜格式。
- 解析层保留格式语义，渲染层负责映射到 Three.js；未知字段保留证据和警告。
- D5M 是材质格式，使用材质文档与标准测试几何预览；个别包内的 `.d5mesh/.split` 只按辅助载荷研究，不据此把 D5M 纳入模型互转管线。
- 高面数路径优先避免几何复制、逐三角形对象和不受控纹理解码。
- 官方素材库的加密容器只检测和提示，不纳入当前解析范围。
- 执行、构建和验收只使用短命令或仓库内具名脚本；复杂 PowerShell 逻辑必须沉淀为职责单一、可审计、可复用的脚本，禁止在终端拼接超长命令。
- 每次阶段完成前检查：单元测试、TypeScript、生产构建、代表性样例截图、资源释放。
- 视觉验收至少覆盖：硬表面多材质模型、透明/裁切材质、森林高面数植物。

## 如何维护此文档

1. **唯一进行中**：全文同时只能有一个 `[-]` 条目。
2. **完成归档**：达到验收标准后，将任务剪切到【已归档/已完成】，标记 `[x]` 并注明日期、证据和成果文件。
3. **持续记录**：关键二进制结构、失败样例、性能数值和截图路径直接更新到对应任务。
4. **滚动排期**：近期任务少于 3 项时，从中期计划提升 1-2 项；优先级变化以用户最新要求为准。
5. **状态措辞**：阶段达到验收标准时只称“Phase N 已归档”或“阶段检查点完成”；只有所有计划项均验收归档后，才可称整个目标完成。
